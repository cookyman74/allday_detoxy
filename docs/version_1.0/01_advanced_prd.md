# Allday Detoxy 1차 고도화 PRD

## 1. 배경 및 목표
- **배경**: MVP(4.3)까지 기본 차단·타이머·리포트·보상 기능을 구현했지만, “집중 시간 확보”에 초점을 맞춘 현재 설계만으로는 스마트폰 과의존을 **진단·예방·회복**하려는 사용자 니즈를 충족하기 어렵다는 피드백이 확인되었다. 디지털 Detoxy 앱으로서 사용자의 중독 패턴을 파악하고, 회복 경로를 제안하는 인사이트가 필요하다.
- **목표**: (a) 사용자가 차단 강도를 상황·취향에 맞게 관리할 수 있는 디톡시 제어 화면 제공, (b) 차단·허용 데이터를 기반으로 중독 위험도를 진단하고 회복 행동을 제안하는 리포트 고도화.
- **성과 지표**:
  - 디톡시 제어 설정 화면 노출 대비 설정 완료율 60% 이상.
  - 일간 리포트 조회 사용자 중 70% 이상이 “디톡시 인사이트(위험 지수/회복 제안)” 섹션을 확인(스크롤/탭)한 로그.
  - 중도 포기 세션과 허용 앱 사용 시간까지 합산한 **Detoxy 총 회복 시간**의 통계 누락률 0%.
  - 디톡시 위험 지수(Risk Index) 고위험 → 중위험 전환율 15% 이상(4주 이동 평균).

## 2. 범위
- **포함**: Android 클라이언트(UI, ViewModel, DB) 및 서비스 연동(DND, Accessibility), 로컬 리포트 데이터 모델 확장, 통계 로직 개선.
- **제외**: 서버 연동, 신규 권한 체계, iOS 앱, 외부 리워드 시스템.

## 3. 주요 사용자 시나리오
1. 사용자는 설정 탭 또는 타이머 화면에서 디톡시 제어 설정을 열어 카테고리별 차단 강도를 조정한다.
2. 프리셋 또는 커스텀 세션을 시작하면 선택된 카테고리에 기반하여 차단 정책이 적용된다.
3. 세션 완료 또는 중도 포기 시, 리포트에 성공/실패뿐 아니라 진행된 시간, 허용 앱 사용 패턴, 위험 지수 변화가 반영된다.
4. 사용자는 일/주 리포트에서 회복률 추세, 위험 원인, 코치 추천을 확인하고 디톡시 루틴을 조정한다.

## 4. 기능 요구사항

### 4.1 디톡시 제어 설정 화면
- **엔트리 포인트**: 메인 타이머 화면 상단 설정 아이콘, 혹은 사이드 메뉴 → “디톡시 제어 설정”.
- **레이아웃**:
  - 섹션 1: 차단 강도 프리셋(전체 차단/집중/완화) 선택 후 커스터마이즈 가능.
  - 섹션 2: 카테고리별 토글 및 강도 슬라이더.
  - 섹션 3: DND 권한 상태 및 바로가기 버튼.
- **카테고리** *(최종 명칭 TBD)*:
  - SNS (Instagram, Facebook, Threads 등)
  - 메신저 & 커뮤니케이션 (KakaoTalk, WhatsApp, Telegram 등)
  - Web 서핑 (Chrome, Samsung Internet 등)
  - 영상 & 쇼츠 (YouTube, TikTok, Instagram Reels 등)
  - 기타 앱 일괄 차단.
- **향후 고려**: 업무/생산성 앱 화이트리스트 기능은 추가 스펙(검색/선택 UI, 우선순위 처리)이 필요하므로 2차 고도화 후보로 이관한다.
- **카테고리 구분 원칙**:
  - 접근성 서비스 차단은 패키지 단위로만 가능하므로 동일 앱 내 기능(예: YouTube vs Shorts, Instagram 피드 vs Reels)은 **동일 카테고리로 취급**한다.
  - 영상 & 쇼츠 카테고리는 장·단편 영상 플랫폼(YouTube, TikTok)과 SNS 내 쇼츠 기능(Instagram, Facebook Watch 등)을 모두 포함한다.
  - 메신저 카테고리는 긴급 연락 가능성을 고려해 기본값은 `허용`으로 두되, 사용자가 명시적으로 차단을 선택할 수 있도록 안내한다.
  - 추후 사용자 피드백 기반으로 서브 카테고리(예: 커뮤니티/커머스, 업무 화이트리스트)를 확장할 수 있도록 데이터 모델을 유연하게 설계한다.
- **동작 요구사항**:
  - 기본값은 “전체 차단” 프리셋으로 진입하되, SNS/웹/영상/기타는 즉시 차단 ON, 메신저는 “긴급 연락 유지” 배너를 통해 사용자가 차단 여부를 선택한 뒤 상태를 저장한다.
  - 카테고리별 설정은 Room에 저장하여 이후 세션에 자동 적용.
  - 설정 변경 즉시 프리뷰 문구 업데이트(예: “SNS와 영상 앱만 차단합니다”).
  - AccessibilityService는 선택된 카테고리에 따라 차단 패키지 목록을 동적으로 로드한다.
  - DndManager는 세션 시작/종료 시 현재 정책을 그대로 유지하되, 사용자에게 “알림 전체 차단” 상태를 안내한다(카테고리별 DND 필터는 제공되지 않음).
  - 중도 권한 해제 발생 시, 설정 화면에서 경고 표시 및 재요청 버튼 제공.

### 4.2 리포트 고도화
- **데이터 보강**:
  - `FocusSession` 모델에 `interruptedSeconds`, `primaryDistractionCategory`, `giveUpReason` 필드 추가.
  - 세션 중 차단 이벤트를 `FocusInterruption` 테이블(세션 ID, 발생 시각, 앱 패키지, 카테고리, 결과[blocked/allowed])로 기록, 리포트 집계 시 참조.
  - 디톡시 세션 중 감지된 모든 주의 분산 앱 진입(`TYPE_WINDOW_STATE_CHANGED`)을 `FocusDistraction` 로그(카테고리, 패키지, 진입 시각, 지속 추정치)로 기록하여 차단 여부와 관계없이 행동 데이터를 축적한다.
  - 중도 포기 시에도 타이머가 진행된 시간(`elapsedSeconds`)을 기록하여 총 집중 시간에 합산.
  - 선택적으로 `UsageStatsManager` 권한을 획득해 포그라운드 앱 체류 시간을 보완 데이터로 수집(사용자 opt-in).
  - 회복 루틴(예: 22시~07시 SNS 차단) 실행 여부를 나타내는 `DetoxyRoutineLog`를 생성해 루틴별 성공/실패를 기록한다.
- **지표 확장**:
  - **Detoxy 위험 지수(Risk Index)**: 차단/허용 이벤트, 사용 시간, 연속 실패 패턴을 가중치로 산출한 0~100 스코어(고위험/주의/안정 3단계).
  - **회복률 추세**: 최근 7일/30일 기준 성공 세션 + 허용 앱 체류 감소율을 기반으로 한 회복률 변화 그래프.
  - **집중률 성장세(보조 KPI)**: 최근 7일/30일 대비 세션 성공률 변화 그래프. 디톡시 위험 지수의 구성 요소로도 활용하며, 리포트에서 별도 카드로 제공.
  - **유혹 저항 시간**: 성공/실패 세션별 평균 지속 시간과 실패 시점(예: 세션 중 몇 %에서 포기했는지) 분석.
  - **방해요인 Top 3**: 차단·허용 이벤트를 통합한 카테고리·앱별 발생 횟수, 위험 지수와의 상관도.
  - **포인트/회복 루틴 진행도**: 주간 포인트 변동, 사용자 정의 루틴(예: 저녁 10시 이후 차단 유지) 달성률, 다음 보상까지 남은 포인트.
  - **분산 회피율**: 분산 앱 진입 대비 5초 이내 이탈 비율, 허용 앱 체류 시간 대비 타이머 성공률 추이.
  - **Detoxy 코치 추천**: 위험 지수 변화에 따라 “야간 차단 시간 늘리기”, “SNS 카테고리 일시 차단” 등 개인화 메시지 제공.
- **UI 요구사항**:
  - 일간 카드: 핵심 KPI + 위험 지수, 총 회복 시간(성공 + 허용 앱 감소 시간), 누적 포인트, 회복률 변화.
  - 주간 인사이트: 그래프 2개(회복률/총 회복 시간) + 방해요인 카드 + 분산 회피율 요약 + 코치 추천 섹션.
  - 도움말/Tooltips로 계산 기준 설명, UsageStats opt-in 여부에 따라 지표 출처 안내.
- **정확성 요구사항**:
  - 세션 종료 시점에 타이머 잔여 시간을 기반으로 elapsed 계산(중도 종료 처리).
  - Accessibility 이벤트 기반 로그가 과도하게 쌓이지 않도록 범주 필터·디바운싱(예: 동일 앱 연속 이벤트 3초 이내는 하나로 합산).
  - UsageStats opt-in 사용자의 경우 포그라운드 체류 시간이 Accessibility 로그와 일관되는지 검증 후 기록.

## 5. 데이터 및 트래킹
- **로컬 DB**:
  - `FocusSession` 추가 필드 저장 및 마이그레이션 스크립트 필요(Room Migration v2→v3).
  - `UserSettings` 또는 별도 `ReportSnapshot` 테이블에 집계 캐싱.
- **이벤트 로깅**:
  - `focus_settings_open`, `focus_settings_saved`, `focus_settings_category_toggle`.
  - `focus_distraction_logged`(category, package, duration, result[blocked/allowed]).
  - `report_view_daily`, `report_view_weekly`, `report_insight_expand`.
  - `session_interrupted`(reason/category 포함).
  - `usage_stats_opt_in` / `usage_stats_opt_out`.
  - `detoxy_risk_index_calculated`, `detoxy_coach_tip_shown`, `detoxy_routine_completed`.
- **분석 지표**: 카테고리 활용률, 회복률 변화, 리포트 조회 빈도, 위험 지수 분포, 실패 원인 Top, 분산 회피율, 허용 앱 체류 시간 대비 성공률, 루틴 준수율.

## 6. 비기능 요구사항
- 권한 변경 감지 시 UI 피드백 < 500ms.
- 리포트 화면 신규 카드 추가 후 첫 로딩 < 1.5s (캐싱/비동기 처리).
- 오프라인에서도 최신 리포트 데이터를 조회 가능(최근 캐시 사용).

## 7. 위험 요소 및 대응
- **카테고리 분류 정확도**: 패키지 매핑 누락 시 차단 실패 → 초기 버전에선 정적 매핑 + 사용자 커스텀 블랙리스트 제공 고려.
- **단일 패키지 내 복수 기능**: YouTube(Shorts), Instagram(Reels) 등은 동일 패키지 → 기능별 차단 불가 사실을 UI 도움말과 FAQ에 명시, 필요 시 “앱 전체 차단” 경고 노출.
- **데이터 마이그레이션**: Room 마이그레이션 실패 시 앱 크래시 위험 → 스테이징 디바이스에서 필수 검증 및 백업/복구 로직 마련.
- **지표 해석 난이도**: 사용자에게 지표가 과도하게 복잡해 보일 수 있음 → UI 카피 및 툴팁으로 단순화, 핵심 KPI는 상단 카드에 요약.
- **추가 권한 거부 가능성**: UsageStats 권한은 사용자가 민감하게 느낄 수 있음 → opt-in 플로우와 데이터 활용 목적/보관 기간을 명확히 안내하고, 미허용 시에도 핵심 지표가 동작하도록 설계.

## 8. 완료 기준(DoD)
- 디톡시 제어 설정 화면에서 카테고리 조정 후 세션을 시작해, 해당 카테고리 앱이 정상 차단되고 예외 앱은 허용되는 것을 QA 체크리스트로 검증.
- 중도 포기한 세션의 진행 시간과 방해요인, 허용 앱 체류 시간이 리포트 전체/일간 통계에 반영돼 수치가 일치함을 확인.
- 리포트 고도화 카드(Detoxy 위험 지수, 회복률 추세, 방해요인, 포인트/루틴 진행도)가 실제 데이터로 채워지며 빈 상태에서는 비어있음 안내가 노출.
- 신규 이벤트 로그가 QA 빌드에서 확인되며, 기존 리포트 기능엔 회귀 오류가 없는 상태로 `./gradlew assembleDebug` 및 `./gradlew test` 통과.
