# 12. 프리미엄 콘텐츠 결제 플로우 기획 (할 일 관리 기능 연계)

## 1. 개요
- **프리미엄 핵심 가치**: `docs/11_추가기능_할일관리기능.md`에서 정의한 스케줄 메모/할 일 관리 기능을 유료 혜택으로 묶어 집중 세션의 목적성과 성취감을 강화.
- **과금 전략**: 구독(월/연) 기반. 베타 트랙에서는 Remote Config로 무료 해제, 정식 배포 시 Google Play Free Trial만 사용.
- **지원 플랫폼**: Google Play Billing Library 6.x (구독 SKU + Free Trial + Intro Price) + Play Integrity API.

## 2. 사용자 여정
| 단계 | 시나리오 | UI/로직 |
| --- | --- | --- |
| 1 | 스케줄 생성/편집 진입 | Premium 미구매 → To-Do 섹션 잠금 + “30일 무료 체험” CTA, 구매자/체험자 → 즉시 사용 |
| 2 | CTA 클릭 | Benefit BottomSheet 노출: 기능 데모, 가격, Free Trial 안내 |
| 3 | 결제 진행 | BillingClient 호출 → Google Play 결제창에서 Trial/가격 자동 안내 |
| 4 | 결제 완료 | Billing 콜백 + (선택) 서버 검증 후 Feature Flag 업데이트, 잠금 해제 |
| 5 | 세션 실행/리포트 | Premium 사용자만 할 일 알림·완료율 리포트 노출 |
| 6 | 구독 만료 | Billing 상태 변경 → EXPIRED_GRACE 알림 → Grace 종료 시 잠금 복귀 (데이터는 읽기 전용)

## 3. Trial / 베타 정책
- **Play Free Trial**: SKU에 `freeTrialPeriod=P1M` 설정. Trial 종료/만료일은 Billing `SubscriptionPurchase`의 `expiryTimeMillis`를 사용해 계산한다.
- **베타 무료**: 클로즈드 테스트용 Remote Config `beta_todo_free=true`. 정식 출시 시 false로 고정해 Trial만 활성.
- **Trial 카운트다운 UI**: 만료 예정일은 Billing 데이터 기반으로 표시(D-7 배너 등). 별도 `trial_end_epoch` Config는 제거.

## 4. Billing 설계
### 4.1 상품 구성
| SKU ID | 유형 | 가격 정책 | 비고 |
| --- | --- | --- | --- |
| `premium_todo_monthly` | SUBS | 월 4.99 USD (현지화 필수) | Free Trial 30일 |
| `premium_todo_yearly` | SUBS | 연 39.99 USD | Intro Price 19.99 USD (첫 해) |

### 4.2 구독 복원 및 캐시
- 앱 재설치/기기 변경 → `BillingClient.queryPurchasesAsync()`로 구독 상태 복원.
- DataStore는 PremiumState 캐시(오프라인 UX)만 담당하며, 앱 삭제 시 데이터 손실을 가정하고 Play에서 재검증.

### 4.3 만료 이후 데이터 정책
- 만료/Grace 종료 후에는 **읽기 전용** 모드: 기존 스케줄/할 일 데이터는 확인 가능하지만 편집/신규 추가/체크가 잠금.
- UI 문구: “구독이 만료되어 할 일 관리가 잠겼어요. 데이터는 안전하게 보관 중입니다.”

## 5. 아키텍처 & 상태 흐름
```
[UI Layer]
  ScheduleScreen → PremiumGateBanner → BillingSheet
[ViewModel]
  PremiumViewModel : StateFlow<PremiumState>
[Domain]
  PremiumEligibilityUseCase (beta flag + purchase state + offline cache)
[Data]
  BillingRepository (BillingClient wrapper)
  RemoteConfigRepository
  DataStore (cached PremiumState)
```

```kotlin
data class PremiumState(
    val entitlement: Entitlement = Entitlement.FREE,
    val isBetaFree: Boolean = false,
    val trialEndsAt: Long? = null,
    val purchaseToken: String? = null,
    val lastVerifiedAt: Long = 0L,
    val error: String? = null
)

enum class Entitlement { FREE, TRIAL, ACTIVE, EXPIRED_GRACE, EXPIRED }
```

### Flow
1. 앱 시작 → Remote Config fetch → DataStore 반영.
2. BillingRepository.queryPurchasesAsync() 호출로 최신 구독 상태 획득.
3. PremiumEligibilityUseCase가 아래 우선순위로 Entitlement 계산:
   - `beta_todo_free` → `ACTIVE`.
   - Play 구독 ACTIVE → `ACTIVE`.
   - Trial 남음 → `TRIAL`.
   - 만료 + Grace 기간 → `EXPIRED_GRACE`.
   - 네트워크 실패 시 마지막 검증 시각 기준 7일 이내면 캐시 상태 유지, 초과 시 `EXPIRED` + 재연결 요청.
4. Schedule UI는 PremiumState에 따라 입력 필드/체크리스트 잠금 여부를 결정.

## 6. 오프라인·에러 시나리오
| 상황 | 처리 |
| --- | --- |
| Remote Config 실패 | DataStore 캐시 사용 + “네트워크 재시도” 안내 |
| BillingClient 연결 실패 | Cached PremiumState를 24시간 허용 후 재시도 배너 노출 |
| 완전 오프라인 7일 초과 | Premium 기능 잠금 + “인터넷 연결 필요” 모달 |
| Purchase Pending | 상태 배너 + 편집 잠금 유지 |

## 7. 클라이언트 구현 체크리스트
- Billing: 단일 BillingClient 인스턴스, lifecycle-aware. Play Integrity API / 서버 검증을 **권장**.
- UI: 잠금 컴포넌트(Blur + Lock Icon), Benefit Sheet 다국어 지원, “구독 관리” 버튼 → Play Store 링크.
- Analytics 이벤트: `todo_premium_viewed`, `todo_premium_trial_start`, `todo_premium_trial_conversion`, `todo_premium_purchase_success`, `todo_premium_purchase_cancel`, `todo_premium_subscription_expired`.

## 8. 서버/RTDN(Optional)
- 서버에서 RTDN/Play Integrity 수신 시 `entitlementStatus`, `expiryTime`, `purchaseToken`을 저장하고, 이상 징후 시 Remote Config로 긴급 잠금 가능.

## 9. QA 및 테스트 시나리오
| 케이스 | 설명 |
| --- | --- |
| Trial 시작/만료 | Trial 시작 → 30일 후 만료 이벤트 동작 확인 |
| 베타 플래그 on/off | Remote Config 토글 시 즉시 반영 |
| Pending/Purchase cancel | 가족 결제/취소 시 UI 안내 및 Analytics 로그 |
| Grace period | Play Console 설정 기반 만료 → Grace → 결제 재개 흐름 |
| Refund | RTDN 또는 수동 환불 시 Entitlement 제거 |
| 오프라인 7일 경과 | 캐시 만료 후 잠금 + 재연결 안내 |

## 11. 리스크 & 대응
- **플래그 미동기화**: Remote Config fetch 실패 시 캐시 사용 + 만료 전 push 알림.
- **보안**: 클라이언트만으로는 취약 → Play Integrity API + (추후) 서버 검증을 기본 정책으로 문서화.
- **데이터 일관성**: 만료 시에도 데이터는 삭제하지 않고 read-only. 사용자 불만 최소화.
- **현지화/가격**: Google Play Pricing Template을 사용해 KRW 등 주요 통화 정의, Benefit Sheet 텍스트 다국어 리소스화.
