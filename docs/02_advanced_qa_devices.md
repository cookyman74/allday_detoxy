## 1. 개요

### 1.1 목표
- 2차 고도화 기능 (자동 실행, 커스텀 타이머) QA 시나리오 정의
- 회귀 테스트 방지 (MVP + 1차 고도화 기능)
- OEM 호환성 테스트 (Samsung, Xiaomi, Huawei, OnePlus)

### 1.2 테스트 기기 목록

| 제조사 | 기기 | OS 버전 | UI | 테스트 우선순위 |
|--------|------|---------|-----|----------------|
| Samsung | Galaxy S23 | Android 14 | One UI 6.0 | 높음 (시장 점유율 1위) |
| Google | Pixel 8 | Android 14 | Stock Android | 높음 (표준 참조) |
| Xiaomi | Redmi Note 12 | Android 13 | MIUI 14 | 높음 (백그라운드 제약) |

**신규 기능 (2차 고도화)**:
- 시간 기반 자동 실행 (10개 시나리오)
- 위치 기반 자동 실행 (8개 시나리오)
- 커스텀 타이머 UI (5개 시나리오)

**회귀 테스트 (MVP + 1차 고도화)**:
- 타이머 기능, 앱 차단, 리포트 (5개 시나리오)

**권한 및 호환성**:
- 정확 알람 권한 (Android 12+)
- 백그라운드 위치 권한
- OEM 호환성 (4개 제조사)

## 2. 시간 기반 자동 실행 시나리오 (10개)

### 2.1 시나리오 T1: 시간대 추가 및 삭제

**목적**: 시간 기반 자동 실행 설정 CRUD 동작 확인

**사전 조건**:
- 앱 설치 및 초기 권한 설정 완료
- 정확 알람 권한 허용 (Android 12+)

**단계**:
1. 설정 → 시간 기반 자동 실행 진입
2. "+ 시간대 추가" 버튼 탭
3. 시간 선택: 09:00
4. 타이머 시간: 45분
5. 차단 프리셋: 표준 디톡시
6. 요일: 월~금 선택
7. 라벨: "오전 업무" 입력
8. "저장" 버튼 탭
9. 리스트에 추가된 항목 확인
10. 편집 버튼 탭 → 시간 변경 (09:30)
11. 삭제 버튼 탭 → 확인 다이얼로그 → 삭제

**예상 결과**:
- ✅ 추가: 리스트에 "🕐 오전 9:00, 45분 • 표준 디톡시, 월화수목금" 표시
- ✅ 편집: 시간이 09:30으로 변경됨
- ✅ 삭제: 리스트에서 제거됨
- ✅ Analytics: `auto_run_time_created`, `auto_run_time_edited`, `auto_run_time_deleted` 로깅 확인

**실패 시나리오**:
- ❌ 최대 10개 초과 시 경고 메시지 표시
- ❌ 중복 시간(hour, minute) 추가 시 경고 표시

---

### 2.2 시나리오 T2: 시간대 활성화/비활성화

**목적**: 토글 동작 및 AlarmManager 등록/해제 확인

**사전 조건**:
- 시나리오 T1 완료 (1개 시간대 추가됨)

**단계**:
1. 시간대 카드의 토글 OFF → ON
2. 시스템 설정 → 알람 → 등록된 알람 확인
3. 토글 ON → OFF
4. 시스템 설정 → 알람 → 등록 해제 확인

**예상 결과**:
- ✅ 토글 ON: AlarmManager에 알람 등록 확인
- ✅ 토글 OFF: AlarmManager에서 알람 제거 확인
- ✅ Analytics: `auto_run_time_toggled` 로깅 확인

---

### 2.3 시나리오 T3: 템플릿으로 빠르게 추가

**목적**: 템플릿 선택 기능 동작 확인

**사전 조건**:
- 설정 화면 진입 (Empty State)

**단계**:
1. "템플릿으로 시작하기" 버튼 탭
2. "💼 업무 집중" 템플릿 선택
3. 미리보기 확인 (오전 9시, 오후 2시 / 45분 / 표준 디톡시)
4. "적용하기" 버튼 탭
5. 리스트에 2개 시간대 추가 확인

**예상 결과**:
- ✅ 템플릿 미리보기 다이얼로그 표시
- ✅ 적용 후 2개 시간대 자동 추가
- ✅ Analytics: `auto_run_time_created` (is_from_template=true) 로깅 확인

---

### 2.4 시나리오 T4: 알람 트리거 정확도 (±2분)

**목적**: AlarmManager 정확 알람 동작 확인

**사전 조건**:
- 정확 알람 권한 허용
- 현재 시간 + 5분 후로 시간대 설정

**단계**:
1. 시간대 추가: 현재 시간 + 5분 (예: 현재 14:20 → 14:25 설정)
2. 토글 ON
3. 앱 백그라운드 전환 또는 화면 OFF
4. 14:25 ±2분 이내 알림 표시 확인
5. 알림 탭 → 타이머 시작 확인

**예상 결과**:
- ✅ 14:23~14:27 사이 알림 표시
- ✅ 알림 액션 (시작/스누즈/건너뛰기) 정상 동작
- ✅ Analytics: `auto_run_triggered`, `auto_run_notification_shown`, `auto_run_started` 로깅 확인

**실패 시나리오** (권한 없을 때):
- ⚠️ WorkManager fallback 사용 (±15분 오차)
- ⚠️ 경고 배너: "정확한 시간 실행을 위해 권한을 설정해주세요"

---

### 2.5 시나리오 T5: 사전 알림 표시

**목적**: 사전 알림 (5분 전) 동작 확인

**사전 조건**:
- 글로벌 옵션 → 사전 알림: 5분 전 설정
- 현재 시간 + 10분 후로 시간대 설정

**단계**:
1. 시간대 추가 및 활성화
2. 현재 시간 + 5분 대기
3. 사전 알림 표시 확인 ("5분 후 자동 실행됩니다")
4. 현재 시간 + 10분 대기
5. 본 알림 표시 확인

**예상 결과**:
- ✅ 사전 알림 (5분 전) 표시
- ✅ 본 알림 (정시) 표시
- ✅ Analytics: `auto_run_notification_shown` (is_pre_notification=true/false) 로깅 확인

---

### 2.6 시나리오 T6: 알림 액션 (시작/스누즈/건너뛰기)

**목적**: 알림 액션 버튼 동작 확인

**사전 조건**:
- 시나리오 T4 완료 (알림 표시 상태)

**단계**:
1. **시작 액션**: "시작하기" 버튼 탭 → 타이머 시작 확인
2. **스누즈 액션**: "10분 뒤" 버튼 탭 → 10분 후 재알림 확인
3. **건너뛰기 액션**: "건너뛰기" 버튼 탭 → 알림 제거 확인

**예상 결과**:
- ✅ 시작: 타이머 화면 진입, 세션 시작
- ✅ 스누즈: 10분 후 재알림 (AlarmManager 재등록)
- ✅ 건너뛰기: AutoRunLog에 SKIPPED 기록
- ✅ Analytics: `auto_run_notification_action` (action=START/SNOOZE/SKIP) 로깅 확인

---

### 2.7 시나리오 T7: 자동 시작 (5분 후)

**목적**: 알림 무응답 시 자동 시작 동작 확인

**사전 조건**:
- 글로벌 옵션 → 자동 시작: 알림 5분 후 설정

**단계**:
1. 시간대 추가 및 활성화
2. 알림 표시 확인
3. 알림 무시 (아무 액션도 안 함)
4. 5분 대기
5. 타이머 자동 시작 확인

**예상 결과**:
- ✅ 5분 후 타이머 자동 시작
- ✅ Analytics: `auto_run_started` (is_auto_start=true, delay_seconds=300) 로깅 확인

---

### 2.8 시나리오 T8: 주말 제외 옵션

**목적**: 글로벌 옵션 "주말 제외" 동작 확인

**사전 조건**:
- 시간대 추가 (요일: 매일 선택)
- 오늘이 토요일 또는 일요일

**단계**:
1. 글로벌 옵션 → "주말 제외" 토글 ON
2. 시간대 활성화 확인
3. 알림 트리거 시간 대기
4. 알림 표시 안 됨 확인
5. 월요일에 다시 테스트 → 알림 표시 확인

**예상 결과**:
- ✅ 주말: 알림 표시 안 됨
- ✅ 평일: 알림 정상 표시
- ✅ AutoRunLog에 주말 건너뜀 기록 (reason=WEEKEND_EXCLUDED)

---

### 2.9 시나리오 T9: 앱 재시작 후 알람 유지

**목적**: Boot Completed Receiver 동작 확인

**사전 조건**:
- 시간대 2개 추가 및 활성화
- 배터리 최적화 제외 설정

**단계**:
1. 앱 강제 종료 (최근 앱 목록에서 스와이프)
2. 기기 재부팅
3. 시스템 설정 → 알람 → 등록된 알람 확인
4. 다음 알람 시간 대기 → 알림 표시 확인

**예상 결과**:
- ✅ 재부팅 후 AlarmManager에 모든 시간대 재등록
- ✅ 알림 정상 트리거

**실패 시나리오**:
- ❌ 배터리 최적화 ON 시 재등록 실패 가능 → 경고 안내

---

### 2.10 시나리오 T10: 배터리 최적화 제외 안내

**목적**: 배터리 최적화 관련 안내 UI 동작 확인

**사전 조건**:
- 배터리 최적화 ON (기본 상태)

**단계**:
1. 시간대 추가 후 저장
2. "배터리 최적화 제외 권장" 다이얼로그 표시 확인
3. "설정으로 이동" 버튼 탭
4. 시스템 설정 → 배터리 최적화 → Detoxy 제외 설정
5. 앱 복귀 → 권한 상태 카드 "✅ 제외됨" 확인

**예상 결과**:
- ✅ 다이얼로그 표시 (1회만, 이후 DataStore에 기록)
- ✅ 설정 화면 이동
- ✅ 권한 상태 카드 업데이트

## 3. 위치 기반 자동 실행 시나리오 (8개)

### 3.1 시나리오 L1: 위치 추가 (검색, 반경 설정)

**목적**: 위치 검색 및 설정 플로우 확인

**사전 조건**:
- 위치 권한 허용 (ACCESS_FINE_LOCATION)
- Google Play Services 설치

**단계**:
1. 설정 → 위치 기반 자동 실행 진입
2. "+ 위치 추가" 버튼 탭
3. 주소 검색: "강남역" 입력
4. 검색 결과 리스트에서 "강남역" 선택
5. 지도 화면에서 핀 위치 확인 (선택 사항)
6. 라벨: "회사" 입력
7. 반경: 100m 선택
8. 타이머 시간: 45분
9. 차단 프리셋: 표준 디톡시
10. 트리거 타입: 도착 시 시작
11. 체류 시간: 1분 선택
12. "저장" 버튼 탭
13. 리스트에 "🏢 회사, 서울시 강남구..., 반경 100m • 45분" 표시 확인

**예상 결과**:
- ✅ Google Places API 검색 정상 동작
- ✅ 위치 정보 저장 (좌표, 주소)
- ✅ GeofencingClient에 Geofence 등록
- ✅ Analytics: `auto_run_location_created` (location_label_hash) 로깅 확인

**실패 시나리오**:
- ❌ 최대 5개 초과 시 경고 메시지
- ❌ Google Play Services 없을 때 오류 안내

---

### 3.2 시나리오 L2: 위치 편집 및 삭제

**목적**: 위치 CRUD 동작 확인

**사전 조건**:
- 시나리오 L1 완료 (1개 위치 추가됨)

**단계**:
1. 위치 카드 편집 버튼 탭
2. 반경 변경: 100m → 200m
3. 체류 시간 변경: 1분 → 3분
4. "저장" 버튼 탭
5. 카드에 "반경 200m" 표시 확인
6. 삭제 버튼 탭 → 확인 다이얼로그 → 삭제
7. 리스트에서 제거 확인

**예상 결과**:
- ✅ 편집: GeofencingClient에 Geofence 재등록 (새 반경)
- ✅ 삭제: GeofencingClient에서 Geofence 제거
- ✅ Analytics: `auto_run_location_edited`, `auto_run_location_deleted` 로깅 확인

---

### 3.3 시나리오 L3: 위치 권한 요청 플로우

**목적**: 정확한 위치 + 백그라운드 위치 권한 요청 2단계 플로우 확인

**사전 조건**:
- 앱 재설치 (권한 초기화)

**단계**:
1. 설정 → 위치 기반 자동 실행 진입
2. 권한 안내 카드 표시 확인
3. "권한 설정하기" 버튼 탭
4. 시스템 권한 다이얼로그: "정확한 위치" 허용
5. 백그라운드 위치 필요성 설명 다이얼로그 표시
6. "설정으로 이동" 버튼 탭
7. 시스템 설정 → 위치 권한 → "항상 허용" 선택
8. 앱 복귀 → "+ 위치 추가" 버튼 활성화 확인

**예상 결과**:
- ✅ 1단계: ACCESS_FINE_LOCATION 요청
- ✅ 2단계: ACCESS_BACKGROUND_LOCATION 안내 + 설정 이동
- ✅ Analytics: `permission_background_location_requested` (permission_level=ALWAYS) 로깅 확인

**실패 시나리오**:
- ❌ "앱 사용 중에만 허용" 선택 시 경고 안내
- ❌ 거부 시 위치 기반 기능 비활성화 안내

---

### 3.4 시나리오 L4: 백그라운드 위치 권한 설정

**목적**: Android 10+ 백그라운드 위치 권한 동작 확인

**사전 조건**:
- Android 10 이상 기기
- 시나리오 L3 완료

**단계**:
1. 위치 추가 및 활성화
2. 앱 백그라운드 전환 (홈 버튼)
3. 등록한 위치로 이동 (또는 GPS 모의 위치 사용)
4. Geofence 진입 트리거 확인
5. 알림 표시 확인

**예상 결과**:
- ✅ 백그라운드에서 Geofence 트리거 정상 동작
- ✅ 알림 표시: "회사에 도착했습니다. 타이머를 시작하시겠습니까?"
- ✅ Analytics: `auto_run_triggered` (trigger_type=LOCATION) 로깅 확인

---

### 3.5 시나리오 L5: Geofence 진입 트리거

**목적**: Geofence ENTER 이벤트 동작 확인

**사전 조건**:
- 시나리오 L1 완료 (위치 1개, 반경 100m)
- 체류 시간: 0분 (즉시 실행)

**단계**:
1. 등록한 위치 밖에서 시작 (반경 200m 밖)
2. 등록한 위치로 이동 (반경 100m 내 진입)
3. Geofence 진입 감지 확인 (5분 이내)
4. 알림 표시 확인
5. "시작하기" 버튼 탭
6. 타이머 시작 확인

**예상 결과**:
- ✅ 진입 후 5분 이내 알림 표시
- ✅ GPS 정확도: "높음" (AutoRunLog에 기록)
- ✅ Analytics: `auto_run_notification_shown`, `auto_run_started` 로깅 확인

**실패 시나리오**:
- ❌ 위치 서비스 OFF 시 AutoRunLog에 FAILED (reason=LOCATION_DISABLED) 기록
- ❌ GPS 정확도 낮음 시 반경 확대 권장 안내

### 3.6 시나리오 L6: 체류 시간 확인 (진입 조건 강화)

**목적**: 체류 시간 설정 동작 확인

**사전 조건**:

**단계**:
1. 등록한 위치로 이동 (반경 내 진입)

3. 다시 반경 내 진입
4. 3분 이상 체류 → 알림 표시 확인

**예상 결과**:
- ✅ 3분 미만 체류: 알림 없음 (오진 방지)
- ✅ 3분 이상 체류: 알림 표시
- ✅ AutoRunLog에 체류 시간 기록

### 3.7 시나리오 L7: 위치 이탈 시 안내

**예상 결과**:
- ✅ EXIT 이벤트 감지 및 다이얼로그 표시
- ✅ 사용자 선택에 따라 타이머 유지/종료
