# Allday Detoxy 2차 고도화 PRD

## 1. 배경 및 목표
- **배경**: 1차 고도화(v0.5)에서 디톡시 제어 설정과 리포트 고도화를 완료했으나, 사용자가 매번 수동으로 타이머를 시작해야 하는 불편함이 있다. 특히 직장인·학생 사용자는 "출근 후 자동으로 집중 모드 시작", "매일 오후 2시에 자동 실행" 등 **루틴화된 자동 실행**을 원하는 니즈가 높다. 또한 기본 프리셋(25/45/60분) 외에 자신에게 맞는 시간(예: 35분, 90분)을 쉽게 설정하고 싶어하는 피드백이 확인되었다.
- **목표**: 
  - (a) 시간 기반 자동 실행으로 일상 루틴에 디톡시 습관을 자연스럽게 통합
  - (b) 위치 기반 자동 실행으로 특정 장소(회사, 학교, 도서관 등)에서 자동으로 집중 모드 활성화
  - (c) 직관적인 커스텀 타이머 UI로 사용자 맞춤 프리셋 생성 경험 개선
- **성과 지표**:
  - 자동 실행 설정 사용자 비율 40% 이상 (전체 DAU 대비)
  - 자동 실행으로 시작된 세션 비율 30% 이상 (전체 세션 대비)
  - 커스텀 타이머 생성율 50% 이상 (타이머 화면 진입자 대비)
  - 자동 실행 설정 후 주간 평균 세션 수 20% 증가
  - 위치 기반 자동 실행 정확도 90% 이상 (설정 위치 도착 시 5분 내 실행)

## 2. 범위
- **포함**: 
  - Android 클라이언트 (자동 실행 설정 UI, 스케줄러 로직, 위치 서비스 연동)
  - Room DB 확장 (v3→v4: 자동 실행 설정 저장)
  - Background 작업 (AlarmManager, Geofencing API)
  - 커스텀 타이머 UI (도넛 그래프 터치 인터랙션)
- **제외 (3차 고도화로 연기)**: 
  - **서버 연동 및 클라우드 동기화** → 3차 고도화에서 구현 (설정 백업, 기기 간 동기화)
  - **웹 서비스 기반 고도화 분석** → 서버 데이터 기반 장기 트렌드, AI 인사이트 제공
  - **소셜 기능** (동료와의 공유, 챌린지, 리더보드) → 커뮤니티 기반 동기부여
  - iOS 앱
  - 복잡한 조건 조합 (시간 AND 위치, 요일별 시간 변경 등)
  - 날씨, 캘린더 연동 자동 실행

## 3. 주요 사용자 시나리오
1. **시간 기반 자동 실행**
   - 직장인 A는 매일 오전 10시, 오후 2시, 오후 4시에 45분 집중 모드가 자동 시작되도록 설정한다.
   - 설정된 시간이 되면 알림과 함께 타이머가 자동으로 시작되고, 차단 설정이 적용된다.
   - A가 회의 중이라면 "지금은 건너뛰기" 버튼으로 해당 회차를 연기할 수 있다.

2. **위치 기반 자동 실행**
   - 학생 B는 학교 도서관 위치를 등록하고 "도착 시 60분 집중 모드 자동 시작"으로 설정한다.
   - B가 도서관 반경 100m 내에 진입하면 앱이 자동으로 타이머를 시작한다.
   - B가 도서관을 떠나면 타이머가 자동으로 종료되거나 연장 여부를 묻는 다이얼로그가 표시된다.

3. **커스텀 타이머 생성**
   - 사용자 C는 타이머 화면에서 도넛 그래프를 터치하여 35분으로 시간을 조정한다.
   - "프리셋으로 저장" 버튼을 눌러 "오후 집중" 이름으로 저장한다.
   - 이후 타이머 화면에서 "오후 집중(35분)" 프리셋을 바로 선택하여 실행할 수 있다.

4. **자동 실행 관리**
   - 사용자 D는 설정 화면에서 등록된 3개의 시간대와 2개의 위치를 확인한다.
   - 주말에는 자동 실행이 불필요하므로 "주말 제외" 옵션을 활성화한다.
   - 특정 위치(회사)의 자동 실행을 일시 중지하거나 삭제할 수 있다.

## 4. 기능 요구사항

### 4.1 시간 기반 자동 실행

#### 4.1.1 자동 실행 시간 설정 화면
- **엔트리 포인트**: 설정 탭 → "자동 실행 설정" → "시간 기반 자동 실행"
- **레이아웃**:
  - 섹션 1: 시간대 리스트 (등록된 시간대 표시, 최대 10개)
  - 섹션 2: "+ 시간대 추가" 버튼
  - 섹션 3: 글로벌 옵션 (주말 제외, 알림 설정)
- **시간대 추가 다이얼로그**:
  - 시간 선택기 (TimePicker, 24시간 형식)
  - 타이머 시간 선택 (프리셋 또는 커스텀)
  - 차단 프리셋 선택 (완전 차단/표준/완화)
  - 요일 선택 (월~일, 다중 선택 가능)
  - 라벨 입력 (선택, 예: "오전 집중", "점심 후 루틴")
- **시간대 카드 UI**:
  - 시간 표시 (예: "10:00 AM")
  - 타이머 시간 + 차단 프리셋 (예: "45분 · 표준 디톡시")
  - 활성화 토글 (ON/OFF)
  - 요일 표시 (예: "월, 화, 수, 목, 금")
  - 편집/삭제 버튼

#### 4.1.2 자동 실행 알림
- **사전 알림**: 설정 시간 5분 전 "곧 집중 모드가 시작됩니다" 알림
- **실행 알림**: 설정 시간에 "집중 모드가 시작되었습니다" 알림
- **알림 액션**:
  - "시작하기" (즉시 타이머 시작)
  - "10분 후" (스누즈)
  - "건너뛰기" (해당 회차 취소)

#### 4.1.3 자동 시작 로직
- AlarmManager를 사용하여 정확한 시간에 실행
  - Android 12+ (API 31+): `setExactAndAllowWhileIdle()` 사용 시 `SCHEDULE_EXACT_ALARM` 권한 필요
  - 권한 없을 경우: WorkManager 또는 `setAndAllowWhileIdle()` (부정확 알람) fallback
- 앱이 백그라운드에 있어도 알림을 통해 사용자에게 안내
- 사용자가 "시작하기" 선택 시 AccessibilityService, DND 등 자동 활성화
- 사용자가 반응하지 않으면 5분 후 자동으로 타이머 시작 (설정 가능)
- 이미 타이머가 실행 중이면 자동 실행 건너뛰기
- **백그라운드 실행 제한 (Android 12+)**:
  - 알림 → 사용자 액션 (Notification Action) → 타이머 시작
  - PendingIntent를 통한 간접 실행으로 백그라운드 제약 우회

#### 4.1.4 정확 알람 권한 관리 (Android 12+)
- **권한 확인**: `AlarmManager.canScheduleExactAlarms()` 체크
- **권한 요청 플로우**:
  1. 시간 기반 자동 실행 최초 설정 시 권한 확인
  2. 권한 없을 경우 설명 다이얼로그 표시
     - "정확한 시간에 집중 모드를 시작하려면 정확한 알람 권한이 필요합니다"
     - "설정에서 '알람 및 리마인더' 권한을 허용해주세요"
  3. "설정으로 이동" 버튼 → `ACTION_REQUEST_SCHEDULE_EXACT_ALARM` Intent
  4. 사용자가 설정에서 권한 허용
- **권한 거부 시 대응**:
  - WorkManager를 사용한 근사 시간 자동 실행 (±15분 오차)
  - 설정 화면에 경고 배너 표시: "정확한 시간 실행을 위해 권한이 필요합니다"
  - 사용자가 언제든 권한 설정 가능하도록 "권한 설정" 버튼 제공
- **권한 상태 모니터링**:
  - 앱 포그라운드 진입 시 권한 재확인
  - 권한 변경 시 자동으로 AlarmManager/WorkManager 전환

#### 4.1.5 글로벌 옵션
- **주말 제외**: 토요일, 일요일 자동 실행 비활성화
- **방해금지 시간 제외**: 스마트폰 DND 모드 활성화 중에는 자동 실행 건너뛰기
- **자동 시작 딜레이**: 알림 후 자동 시작까지 대기 시간 (0분, 5분, 10분)
- **사전 알림 시간**: 몇 분 전 알림 표시 (0분, 5분, 10분, 15분)

### 4.2 위치 기반 자동 실행

#### 4.2.1 위치 등록 화면
- **엔트리 포인트**: 설정 탭 → "자동 실행 설정" → "위치 기반 자동 실행"
- **레이아웃**:
  - 섹션 1: 등록된 위치 리스트 (최대 5개)
  - 섹션 2: "+ 위치 추가" 버튼
  - 섹션 3: 위치 권한 안내 카드
- **위치 추가 플로우**:
  1. 위치 검색 (Google Places API 또는 주소 입력)
  2. 지도에서 위치 확인 및 조정
  3. 반경 설정 (50m, 100m, 200m, 500m)
  4. 라벨 입력 (예: "회사", "학교 도서관")
  5. 타이머 설정 (시간, 차단 프리셋)
  6. 트리거 타입 선택:
     - "도착 시 시작" (geofence enter)
     - "체류 중 주기적 시작" (예: 1시간마다)
- **위치 카드 UI**:
  - 위치 이름 + 주소
  - 반경 표시 (예: "반경 100m")
  - 타이머 시간 + 차단 프리셋
  - 트리거 타입 표시
  - 활성화 토글
  - 편집/삭제 버튼

#### 4.2.2 Geofencing 구현
- Android Geofencing API 사용
- 등록된 위치 중심으로 원형 지오펜스 생성
- ENTER 이벤트 감지 시 자동 실행 트리거
- EXIT 이벤트 감지 시 선택적으로 타이머 종료 안내
- 배터리 최적화: 위치 업데이트 빈도 조절 (Balanced Power Accuracy)

#### 4.2.3 위치 권한 관리
- **필수 권한**:
  - `ACCESS_FINE_LOCATION`: 정확한 위치 권한
  - `ACCESS_BACKGROUND_LOCATION`: 백그라운드 위치 권한 (Android 10+)
- **권한 요청 플로우**:
  1. 위치 추가 시 정확한 위치 권한 요청
  2. 백그라운드 위치 권한 필요성 설명 다이얼로그
     - "회사나 학교에 도착했을 때 자동으로 집중 모드를 시작하려면 위치 권한이 필요합니다"
     - "위치 정보는 기기에만 저장되며 서버로 전송되지 않습니다"
  3. 설정 화면으로 이동하여 "항상 허용" 선택 안내
  4. 단계별 가이드 이미지 제공 (시스템 설정 화면 캡처)
- **권한 미부여 시**:
  - 위치 기반 자동 실행 기능 비활성화
  - 설정 화면에 경고 배너 표시
  - "권한 설정하기" 버튼 제공
  - 시간 기반 자동 실행 대안 제시
- **권한 변경 감지**:
  - 앱 포그라운드 진입 시 권한 재확인
  - "항상 허용" → "앱 사용 중에만" 변경 시:
    - 사용자에게 알림: "위치 기반 자동 실행이 제대로 작동하지 않을 수 있습니다"
    - 재설정 유도 다이얼로그
  - 권한 완전 거부 시:
    - 등록된 모든 위치 기반 자동 실행 일시 중지
    - Geofence 해제하여 배터리 절약

#### 4.2.4 위치 자동 실행 알림
- **진입 알림**: "회사에 도착했습니다. 집중 모드를 시작할까요?"
- **알림 액션**:
  - "시작하기"
  - "오늘은 건너뛰기"
  - "이 위치 비활성화"
- **자동 시작**: 알림 후 사용자 반응 없으면 2분 후 자동 시작 (설정 가능)
- **백그라운드 실행 제한 대응**: 알림 액션을 통한 간접 실행 (Android 12+)

#### 4.2.5 Google Play Store 정책 준수
- **Location Permission Declaration (필수)**:
  - Google Play Console에서 "데이터 보안" 섹션 작성
  - 백그라운드 위치 사용 목적 명시: "위치 기반 자동 실행으로 특정 장소 도착 시 집중 모드 자동 시작"
  - 위치 데이터 처리 방식 선언:
    - 수집: 예 (사용자가 등록한 위치만)
    - 공유: 아니오 (서버 미전송, 로컬 저장만)
    - 암호화: 예 (기기 내 암호화 저장)
    - 삭제 요청: 앱 내에서 즉시 삭제 가능
- **개인정보 처리방침 업데이트**:
  - 위치 정보 수집·이용 목적 명시
  - 수집 방법: Android Geofencing API
  - 보관 기간: 사용자 삭제 시까지
  - 제3자 제공: 없음
  - 사용자 권리: 언제든 삭제 및 비활성화 가능
- **Play Console 심사 대응**:
  - 백그라운드 위치 사용 정당성 설명 준비
  - 기능 시연 비디오 제작 (위치 기반 자동 실행 동작)
  - 대체 기능 제공 확인 (시간 기반 자동 실행)
- **지원 기기 범위**:
  - Google Play Services 탑재 기기만 지원
  - Play Services 미탑재 시 위치 기반 기능 비활성화 (중국 시장 등)
  - 기기 호환성 체크 로직 구현

#### 4.2.6 지오펜싱 예외 처리
- **Google Play Services 확인**:
  - 앱 시작 시 Play Services 가용성 체크
  - 미설치/구버전일 경우 사용자에게 업데이트 안내
  - Play Services 없을 경우 위치 기반 기능 완전 비활성화
- **위치 서비스 OFF 상태 대응**:
  - 설정 화면에 경고 표시: "위치 서비스가 꺼져 있습니다"
  - "위치 서비스 켜기" 버튼 → 시스템 설정 이동
  - 위치 서비스 OFF 시 Geofence 등록 실패 처리
- **실내/GPS 약점 대응**:
  - Network Provider (Wi-Fi, 셀룰러) 활용
  - 반경 최소 100m 권장 (50m는 고급 옵션)
  - 위치 신뢰도 낮을 때 사용자 확인 알림

### 4.4 자동 실행 통합 관리

#### 4.4.1 자동 실행 대시보드
- **엔트리 포인트**: 
  - 설정 탭 → "자동 실행 설정" (메인)
  - 홈 화면 → "자동 실행 상태" 위젯 (빠른 접근)
- **레이아웃**:
  - **섹션 1: 자동 실행 제어 카드** 🆕
    - 전체 활성화/비활성화 토글 (마스터 스위치)
    - 일시중지 옵션:
      - "오늘 하루 중지"
      - "N시간 동안 중지" (1h/3h/6h)
      - "다음 자동 실행까지 중지"
    - 현재 상태 표시 (활성화/일시중지/비활성화)
  - **섹션 2: 다음 예정 자동 실행** 🆕
    - 가장 가까운 자동 실행 표시 (시간 기반/위치 기반)
    - 예정 시간/위치 (예: "오후 2:00 (1시간 30분 후)")
    - 타이머 시간 + 차단 프리셋
    - 해당 회차 건너뛰기 버튼
  - **섹션 3: 자동 실행 통계 카드**
    - 이번 주 자동 실행 횟수 (시간/위치 분리 표시)
    - 자동 실행 성공률
    - 자동 실행으로 얻은 총 집중 시간 🆕
  - **섹션 4: 빠른 접근 버튼**
    - "시간 기반 설정"
    - "위치 기반 설정"
    - "권한 현황 확인" 🆕
  - **섹션 5: 최근 자동 실행 이력** (최근 10개)
    - 시간, 위치 정보
    - 결과 (시작됨/건너뜀/실패)
    - 실패 사유 또는 건너뜀 이유 표시 🆕

#### 4.4.2 자동 실행 이력
- `AutoRunLog` 테이블에 기록:
  - 트리거 타입 (TIME/LOCATION)
  - 트리거 정보 (시간대 ID 또는 위치 ID)
  - 트리거 시각
  - 결과 (STARTED/SKIPPED/FAILED)
  - 실패 사유 (권한 없음, 이미 실행 중, 사용자 취소 등)
  - 연결된 세션 ID (시작된 경우)
- 이력 화면에서 필터링 및 검색
- 성공률 통계 및 주간 트렌드 표시

#### 4.4.3 충돌 방지 로직
- 시간 기반 자동 실행과 위치 기반 자동 실행이 동시에 트리거되면:
  - 위치 기반 우선 (더 구체적인 상황)
  - 사용자에게 선택 다이얼로그 표시
- 이미 타이머 실행 중이면 자동 실행 건너뛰기
- 동일 시간대에 여러 개 설정되면 첫 번째 것만 실행

#### 4.4.4 예외 상황 처리 🆕
- **캘린더 연동 (선택)** (3차 고도화 고려):
  - 시스템 캘린더에서 "바쁨" 일정 확인
  - 일정 시간 중에는 자동 실행 건너뛰기 옵션
  - 사용자가 선택적으로 활성화 가능
- **특정 시간대 일시중지**:
  - "야간 시간 (22:00~07:00) 자동 실행 중지" 설정
  - 사용자 지정 시간대 설정 (예: 점심시간 12:00~13:00)
  - 일시중지 시간대는 최대 3개까지 설정 가능
- **일괄 스누즈**:
  - 홈 화면에서 "다음 자동 실행까지 중지" 버튼
  - "오늘 하루 모든 자동 실행 중지" 옵션
  - "N시간 동안 중지" (1h/3h/6h)
- **저전력 모드 감지** 🆕:
  - 기기 저전력 모드 활성화 시 감지
  - 자동으로 위치 기반 자동 실행 일시중지 (배터리 절약)
  - 사용자에게 알림: "저전력 모드로 위치 기반 자동 실행이 일시중지되었습니다"
  - 저전력 모드 해제 시 자동으로 재활성화

#### 4.4.5 위치 기반 신뢰도 강화 🆕
- **진입 조건 강화**:
  - 체류 시간 설정 (선택): 위치 도착 후 N분 체류 확인 (1분/3분/5분)
  - "도착 후 확인" 옵션: 알림 → 사용자 확인 → 실행 (자동 시작 OFF)
  - 위치 신뢰도 표시: GPS 정확도가 낮으면 경고 표시
- **투명한 로그**:
  - 자동 실행 이력에 상세 정보 표시:
    - "10:23 회사 도착 감지 (GPS 정확도: 50m)"
    - "10:25 집중 모드 시작 (60분)"
    - "실패: 위치 정확도 낮음 (200m 초과)"
  - 성공/실패 패턴 분석 표시:
    - "이 위치는 실내라 GPS 정확도가 낮습니다 (성공률 60%)"
    - "반경을 200m로 늘리면 정확도가 개선될 수 있습니다"
- **사용자 피드백 수집**:
  - 자동 실행 후 "제 시간에 시작되었나요?" 간단한 피드백 요청
  - 실패 시 "왜 실패했나요?" 사용자 제보 옵션
  - 피드백 데이터를 통한 위치 설정 최적화 제안

#### 4.4.6 권한 현황 페이지 🆕
- **엔트리 포인트**: 설정 → "권한 관리" 또는 자동 실행 대시보드 → "권한 현황 확인"
- **레이아웃**:
  - **정확 알람 권한 (Android 12+)**:
    - 상태: 허용됨/거부됨
    - 영향: "정확한 시간에 자동 실행 가능/불가능"
    - 액션: "권한 설정하기" 버튼
  - **백그라운드 위치 권한**:
    - 상태: 항상 허용/앱 사용 중/거부됨
    - 영향: "위치 기반 자동 실행 가능/제한적/불가능"
    - 액션: "권한 설정하기" 버튼
  - **배터리 최적화 제외**:
    - 상태: 제외됨/최적화 중
    - 영향: "백그라운드 실행 안정성"
    - 액션: "설정하기" 버튼
  - **기타 권한**: DND, 접근성, 오버레이 (기존)
- **권한 비활성화 시 영향 요약**:
  - 각 권한 거부 시 사용 불가능한 기능 명시
  - 대체 기능 제안 (예: 위치 거부 → 시간 기반 자동 실행 사용)

  - "권한은 언제든 설정에서 변경하실 수 있습니다"
  - "권한 거부 시에도 기본 기능은 정상적으로 작동합니다"

- `location_based_auto_run_created`: 위치 기반 자동 실행 생성
  - `label`, `radius_meters`, `trigger_type`
- `location_based_auto_run_edited`: 위치 기반 자동 실행 수정
- `location_based_auto_run_deleted`: 위치 기반 자동 실행 삭제
- `location_based_auto_run_toggled`: 위치 기반 자동 실행 ON/OFF
- `location_permission_requested`: 위치 권한 요청
- `location_permission_granted`: 위치 권한 승인
  - `permission_type` (FINE/BACKGROUND)
- `location_permission_denied`: 위치 권한 거부

#### 커스텀 타이머 이벤트
- `custom_timer_opened`: 커스텀 타이머 화면 진입
- `custom_timer_adjusted`: 도넛 그래프로 시간 조정
  - `duration_minutes`, `adjustment_method` (DRAG/TAP)
- `custom_preset_created`: 커스텀 프리셋 저장
  - `name`, `duration_minutes`
- `custom_preset_used`: 커스텀 프리셋 선택하여 시작
  - `preset_id`, `duration_minutes`
- `custom_preset_deleted`: 커스텀 프리셋 삭제

#### 자동 실행 이벤트
- `auto_run_triggered`: 자동 실행 트리거 발생
  - `trigger_type` (TIME/LOCATION)
  - `trigger_source_id`
- `auto_run_notification_shown`: 자동 실행 알림 표시
  - `trigger_type`, `pre_notify` (true/false)
- `auto_run_notification_action`: 자동 실행 알림 액션 선택
  - `action` (START/SNOOZE/SKIP)
- `auto_run_started`: 자동 실행으로 세션 시작
  - `trigger_type`, `duration_minutes`
- `auto_run_skipped`: 자동 실행 건너뜀
  - `reason` (USER_SKIP/ALREADY_RUNNING/PERMISSION_DENIED)
- `auto_run_failed`: 자동 실행 실패
  - `failure_reason`

### 5.3 분석 지표
- 자동 실행 설정 사용자 비율 (시간 기반 / 위치 기반)
- 평균 설정 개수 (시간대, 위치)
- 자동 실행 트리거 횟수 (일/주/월)
- 자동 실행 성공률 (시작됨 / 전체 트리거)
- 자동 실행 건너뛰기 비율 및 사유 분석
- 커스텀 타이머 사용률
- 평균 커스텀 프리셋 개수
- 도넛 그래프 조작 방식 분포 (드래그 vs 탭)
- 위치 권한 승인율
- 자동 실행 후 세션 완주율 vs 수동 시작 완주율 비교

## 6. 비기능 요구사항

### 6.1 성능
- 위치 업데이트 빈도 최적화: 배터리 소모 최소화
- Geofence 등록 제한: 최대 5개 (Android 제한 고려)
- 도넛 그래프 인터랙션 응답 시간 < 16ms (60fps)
- AlarmManager 정확도: 설정 시간 ±2분 이내

### 6.2 배터리 최적화
- Geofencing은 배터리 효율적인 Balanced Power Accuracy 사용
- 위치 기반 자동 실행 비활성화 시 지오펜스 해제
- 불필요한 백그라운드 위치 업데이트 최소화

### 6.3 사용성
- 자동 실행 설정 플로우: 3단계 이내로 완료
- 커스텀 타이머 조작: 5초 내 원하는 시간 설정 가능
- 위치 검색 결과: 1초 이내 표시
- 명확한 권한 안내: 사용자가 왜 필요한지 이해 가능
- **배터리/데이터 사용 투명성** 🆕:
  - 설정 화면에 예상 배터리 영향 표시
  - 최적화 팁 제공
  - 저전력 모드 감지 및 대응

### 6.3.1 배터리/데이터 사용 안내 🆕
- **배터리 영향 안내 카드**:
  - 위치: 자동 실행 설정 화면 하단
  - 내용:
    - "시간 기반 자동 실행: 배터리 영향 최소 (< 1%/일)"
    - "위치 기반 자동 실행: 배터리 소모 예상 3~5%/일"
    - "현재 설정으로 예상 배터리 소모: 약 4%/일"
  - 최적화 팁:
    - "위치 기반 자동 실행을 2개 이하로 유지하세요"
    - "반경을 너무 작게 설정하지 마세요 (100m 이상 권장)"
    - "사용하지 않는 위치는 비활성화하세요"
- **저전력 모드 감지 및 대응**:
  - 기기 저전력 모드 활성화 감지
  - 자동으로 위치 기반 자동 실행 일시중지
  - 알림 표시: "저전력 모드가 감지되어 위치 기반 자동 실행을 일시중지했습니다. 시간 기반 자동 실행은 계속 작동합니다."
  - 저전력 모드 해제 시 자동 재활성화 (사용자 설정)
- **배터리 사용량 모니터링** (선택):
  - 설정 → "배터리 사용량" 페이지
  - 앱의 배터리 사용 통계 표시
  - "지난 7일간 자동 실행 기능이 배터리의 2.3% 사용"
  - Android 설정의 배터리 사용량 페이지로 바로가기
- **데이터 사용량 안내**:
  - 위치 기반 자동 실행은 GPS만 사용 (데이터 미사용)
  - Network Provider (Wi-Fi, 셀룰러) 사용 시 최소 데이터 (<1MB/월)
  - 투명한 안내: "위치 정보는 기기에만 저장되며 서버로 전송되지 않습니다"

### 6.4 안정성
- 위치 권한 거부 시에도 앱 정상 작동
- Geofence 등록 실패 시 사용자에게 안내 및 재시도 옵션
- AlarmManager 설정 실패 시 대체 로직 (WorkManager)
- 앱 강제 종료 후에도 자동 실행 유지 (Broadcast Receiver)

- **Android 버전 지원**:
  - 최소: Android 8.0 (API 26)

  - 타겟: Android 14 (API 34)

  - 위치 기반 자동 실행: Play Services 필수
  - 미탑재 기기: 기능 자동 비활성화 및 안내
  - 버전: 최소 21.0.0 (Geofencing API)

## 7. 위험 요소 및 대응

### 7.1 위치 권한 거부율 높음
- **위험**: 사용자가 백그라운드 위치 권한을 거부하면 위치 기반 자동 실행 불가
- **대응**: 
  - 권한 필요성을 명확히 설명하는 온보딩
  - 시간 기반 자동 실행을 주력으로 홍보
  - 포그라운드 위치만으로도 일부 기능 제공 (앱 실행 중 위치 기반 안내)

### 7.2 배터리 최적화로 인한 자동 실행 실패
- **위험**: Android 배터리 최적화 정책으로 AlarmManager, Geofence 실행 지연 또는 무시
- **대응**:
  - 배터리 최적화 제외 설정 안내
  - WorkManager를 백업으로 사용
  - 자동 실행 실패 시 사용자에게 알림 및 수동 시작 유도

### 7.3 위치 정확도 문제
- **위험**: GPS 신호 약한 실내에서 위치 기반 자동 실행 오작동
- **대응**:
  - 반경을 충분히 크게 설정하도록 가이드 (최소 100m 권장)
  - Wi-Fi 기반 위치도 활용 (Network Provider)
  - 위치 신뢰도 낮으면 사용자에게 확인 알림 표시

### 7.4 도넛 그래프 UI 학습 곡선
- **위험**: 사용자가 도넛 그래프 조작법을 모르거나 어려워함
- **대응**:
  - 첫 진입 시 간단한 튜토리얼 오버레이 표시
  - 기본 프리셋 버튼을 여전히 제공 (대안)
  - 도넛 그래프 위에 "드래그하여 시간 조정" 힌트 텍스트

### 7.5 자동 실행 스팸 우려
- **위험**: 여러 자동 실행 설정이 겹쳐서 하루 종일 알림 폭탄
- **대응**:
  - 시간대 간 최소 간격 30분 강제 (설정 추가 시 경고)
  - 하루 최대 자동 실행 횟수 제한 (예: 10회)
  - "오늘 하루 자동 실행 건너뛰기" 옵션 제공

### 7.6 데이터 마이그레이션
- **위험**: Room v3→v4 마이그레이션 실패 시 앱 크래시
- **대응**:
  - 철저한 마이그레이션 테스트 (단위 테스트, 통합 테스트)
  - 백업 및 복구 로직 구현
  - 마이그레이션 실패 시 fallback (새로 시작)

### 7.7 정확 알람 권한 거부 (Android 12+)
- **위험**: 사용자가 SCHEDULE_EXACT_ALARM 권한을 거부하면 시간 기반 자동 실행이 정확하지 않음
- **대응**:
  - WorkManager fallback으로 ±15분 오차 허용
  - 설정 화면에 명확한 경고: "정확한 시간 실행을 위해 권한 필요"
  - 권한 설정 가이드 제공 (스크린샷, 단계별 안내)
  - 부정확 알람 사용 시 사용자에게 오차 범위 안내

### 7.8 Play Store 심사 거부 (백그라운드 위치)
- **위험**: 백그라운드 위치 권한 사용으로 인한 Play Store 심사 거부 또는 정책 위반

    - 대체 기능 강조 (시간 기반 자동 실행)
  - **심사 대응**:
    - 백그라운드 위치 사용 필수성 설명 준비
    - 데이터 로컬 저장 증명 (서버 전송 없음)

  - **Plan B**:

### 7.9 OEM 배터리 최적화 (Xiaomi, Huawei 등)
