# 11. 추가 기능 제안 – 할 일(To-Do) 메모 결합 스케줄 관리

## 1. 배경 및 목표
- 현재 스케줄(시간/위치 기반 자동 실행)은 집중 세션을 규정하지만, **왜 집중하는지**를 기록할 수단이 부족함.
- 스케줄 상세에 메모와 할 일(To-Do)을 녹여 사용자가 집중 이유·단계별 목표를 확인하도록 하여 **동기 부여·완료 감시** 기능을 강화한다.
- 집중 세션 종료 시 “할 일 달성률”을 리포트/포인트와 연결해 **성과 가시화**를 제공한다.

## 2. 기능 범위 요약
| 분류 | 내용 |
| --- | --- |
| 입력 확장 | 스케줄 생성/편집 화면에 `타이틀`, `설명`, `메모`, `할 일 목록` 필드 추가 |
| 상세 보기 | 기존 시간·위치 정보 상단에 새 필드 노출, 할 일은 체크리스트 UI 제공 |
| 런타임 연동 | 자동 실행 시작 시 오버레이/알림에 해당 스케줄의 주요 할 일을 요약 표시 |
| 결과 기록 | 세션 종료 시 체크 상태를 저장하고, 리포트에서 “할 일 달성률” 통계 추가 |
| 동기화/공유 (v2) | 추후 클라우드 백업, 외부 캘린더 내보내기시 메모/할 일까지 포함 |

MVP는 입력·저장·상세 표시·체크 상태 저장까지만 범위로 잡고, 런타임 연동과 통계 반영은 뒤 단계로 분할.

## 3. 데이터 스키마 설계
### 3.1 엔티티 확장 및 정규화
- `TimeBasedAutoRun` / `LocationBasedAutoRun` 두 엔티티에 공통 필드를 `@Embedded scheduleInfo: ScheduleInfo`로 추가
  ```kotlin
  data class ScheduleInfo(
      val title: String = "",
      val description: String = "",
      val memo: String? = null
  )
  ```
- 할 일 목록은 JSON 대신 별도 테이블 `schedule_todo_items`로 정규화해 쿼리 편의성과 무결성을 확보
  | 컬럼 | 설명 |
  | --- | --- |
  | `id` | PK (UUID) |
  | `scheduleId` | Time/Location schedule FK |
  | `content` | 할 일 내용 |
  | `isRequired` | 필수 여부 |
  | `orderIndex` | 정렬 순서 |
  | `createdAt`/`updatedAt` | 감사 추적 |
- `ScheduleTodo` 데이터 클래스는 `checked/lastCheckedAt` 없이 정의 (스케줄 정의는 원형만 보유)
  ```kotlin
  data class ScheduleTodo(
      val id: String = UUID.randomUUID().toString(),
      val content: String,
      val isRequired: Boolean = false,
      val orderIndex: Int = 0
  )
  ```
- 세션별 체크 이력은 **전용 엔티티** `FocusSessionTodoResult`에 저장
  | 필드 | 설명 |
  | --- | --- |
  | `sessionId` | FocusSession FK |
  | `todoId` | schedule_todo_items FK |
  | `todoContentSnapshot` | 스케줄 편집 시 참조 깨짐 방지를 위한 문자열 스냅샷 |
  | `isRequiredSnapshot` | 필수 여부 스냅샷 |
  | `completed` | Boolean |
  | `completedAt` | Long? |

### 3.2 체크 상태 임시 저장
- 세션 실행 중 체크 변경은 `FocusSessionTodoProgress` 임시 테이블에 즉시 반영
  | 필드 | 설명 |
  | --- | --- |
  | `sessionId` | 진행 중인 세션 ID |
  | `todoId` | ScheduleTodo ID |
  | `checked` | 현재 상태 |
  | `updatedAt` | 마지막 변경 시간 |
- 세션 종료 시 Progress 내용을 `FocusSessionTodoResult`로 이동하고 Progress는 삭제. 앱 강제 종료 대비 자동 저장이 가능하며, 메모리 캐시에만 의존하지 않는다.

### 3.3 마이그레이션 전략
1. Room `version +1` → `ALTER TABLE time_based_auto_run`/`location_based_auto_run`에 `title/description/memo` 컬럼 추가 (공통 Embedded 네이밍 유지). 기존 데이터는 기본값으로 백필.
2. 새 테이블 `schedule_todo_items`, `focus_session_todo_progress`, `focus_session_todo_result` 생성.
3. Foreign Key 및 인덱스 설정 (`scheduleId`, `sessionId`).
4. Migration Test 작성 (`AutoRunScheduleMigrationTest`)로 무결성 검증.

## 4. 런타임 상태 및 데이터 흐름
- **상태 전이**
  1. 스케줄 편집 시 `schedule_todo_items` 갱신.
  2. 세션 시작 → 관련 Todo 목록을 `FocusSessionTodoProgress`로 복사.
  3. 세션 중 체크/해제 → Progress 테이블 업데이트 (UI는 ViewModel StateFlow로 관찰).
  4. 세션 종료 → Progress 데이터를 Result 테이블로 이동 + 완료율 계산.
  5. 취소/실패 시 Progress 삭제, Result 미생성.
- **에러/복구**
  - 앱 강제 종료 후 재실행 시 Progress 테이블 기반으로 체크 상태 복원.
  - Migration 실패 시 앱은 read-only 모드로 전환하고 사용자에게 업데이트 안내 (추가 시나리오는 QA 섹션에 기록).

## 5. API/도메인 계층 변경
- `domain/model/AutoRunSchedule` (가칭) DTO에 동일 필드 반영.
- UseCase: `CreateTimeBasedAutoRunUseCase`, `UpdateLocationBasedAutoRunUseCase` 등에 파라미터 확장.
- `AutoRunStatistics` 등 기존 통계는 영향 없음. 다만 추후 `FocusStatisticsCalculator`에 `todoCompletionRate` 추가 여지를 남겨둔다.

## 6. UI/UX 설계
### 6.1 생성/편집 화면
1. **기본 정보 섹션**: 타이틀(TextField), 설명(Multiline), 메모(Optional Chips 또는 TextArea).
2. **할 일 섹션**:
   - Todo 리스트(최대 10개) + `+ 할 일 추가` 버튼
   - 각 항목: 드래그 정렬(후순위), `필수` 토글, 삭제 버튼
   - Validation: 내용 1~120자, 중복 문구 허용 but 공백 금지
3. **시간/위치 섹션**: 기존 UI 유지.
4. **Preview Card**: 입력 내용 요약하여 실제 상세 화면 모습을 미리 보여줌.

### 6.2 스케줄 상세 화면
- 레이아웃 예시
  ```
  [Header]
    Title | Routine Type Badge
    Description
  [Meta]
    • 시간 : 09:00 ~ 11:00
    • 위치 : 서울 공유오피스 (반경 100m)
  [Memo Card]
    장문 메모 표시 (Markdown 지원 고려)
  [Todo Checklist]
    □ 자료 조사 정리
    □ 피드백 메일 발송 (필수)
    □ 집중 회고 노트 작성
  [Actions]
    - 편집하기
    - 세션 시작/테스트 실행
  ```
- 체크박스는 세션 실행 중에도 업데이트 가능하도록 Compose `LazyColumn` + `rememberSaveable`.

### 6.3 런타임/알림
- MVP+: 자동 실행 알림 및 Focus Overlay 상단에 “오늘의 할 일 Top3” 노출, 체크박스 탭 시 바로 결과 저장.
- 세션 종료 다이얼로그에 “완료한 할 일 n/m” 표시 후 Report 로깅.

## 7. 통계/리포트 연동 (차기 단계)
- `FocusSessionTodoResult` 기반 지표:
  - 세션별 할 일 완료율 = 완료 항목 / 등록 항목
  - 필수 항목 달성률 vs 전체 달성률
  - 일정별 누적 완료 횟수 (루틴 개선 코치 메시지에 활용)
- Report 화면에 “이번 주 평균 할 일 완료율”, “필수 항목 미달성 Top 스케줄” 카드 추가.

## 10. 리스크 및 대응
- **데이터 동기화**: `orderIndex` 기준 정렬이 깨지지 않도록 Drag & Drop 시 즉시 DB 업데이트 및 Diff 적용.
- **Migration 실패**: 구버전 사용자 다수 → `fallbackToDestructiveMigration` 금지, 자동 테스트(`./gradlew test`)에 Migration Test 추가.
- **UI 복잡도 증가**: 생성 화면이 길어짐 → 각 섹션을 `CollapsibleCard`로 나눠 처음에는 기본 정보만 보이게.
- **국제화**: 타이틀/설명/메모 입력 안내문구 다국어 리소스 준비.
