# Allday Detoxy 1차 고도화 PRD

## 1. 배경 및 목표
- **배경**: MVP(4.3)까지 기본 차단·타이머·리포트·보상 기능을 구현했지만, 사용자 맞춤 제어와 동기부여 요소가 부족하다는 피드백이 확인되었다.
- **목표**: (a) 사용자가 차단 강도를 상황·취향에 맞게 관리할 수 있는 집중모드 설정 화면 제공, (b) 성과 추적과 동기부여를 강화하는 리포트 고도화.
- **성과 지표**:
  - 집중모드 설정 화면 노출 대비 설정 완료율 60% 이상.
  - 일간 리포트 조회 사용자 중 70% 이상이 신규 지표를 확인(스크롤/탭)한 로그.
  - 중도 포기 세션도 총 집중시간 통계에 반영되어 통계 누락률 0%.

## 2. 범위
- **포함**: Android 클라이언트(UI, ViewModel, DB) 및 서비스 연동(DND, Accessibility), 로컬 리포트 데이터 모델 확장, 통계 로직 개선.
- **제외**: 서버 연동, 신규 권한 체계, iOS 앱, 외부 리워드 시스템.

## 3. 주요 사용자 시나리오
1. 사용자는 설정 탭 또는 타이머 화면에서 집중모드 설정을 열어 카테고리별 차단 강도를 조정한다.
2. 프리셋 또는 커스텀 세션을 시작하면 선택된 카테고리에 기반하여 차단 정책이 적용된다.
3. 세션 완료 또는 중도 포기 시, 리포트에 성공/실패뿐 아니라 진행된 시간과 차단 효과, 집중률 추세가 반영된다.
4. 사용자는 일/주 리포트에서 집중 시간 성장세, 실패 사유, 주요 방해요인을 확인하고 다시 집중 세션을 설정한다.

## 4. 기능 요구사항

### 4.1 집중모드 설정 화면
- **엔트리 포인트**: 메인 타이머 화면 상단 설정 아이콘, 혹은 사이드 메뉴 → “집중모드 설정”.
- **레이아웃**:
  - 섹션 1: 차단 강도 프리셋(전체 차단/집중/완화) 선택 후 커스터마이즈 가능.
  - 섹션 2: 카테고리별 토글 및 강도 슬라이더.
  - 섹션 3: DND 권한 상태 및 바로가기 버튼.
- **카테고리** *(최종 명칭 TBD)*:
  - SNS (Instagram, Facebook, Threads 등)
  - Web 서핑 (Chrome, Samsung Internet 등)
  - 영상 & 쇼츠 (YouTube, TikTok 등)
  - 업무/생산성 예외(화이트리스트) *옵션*
  - 기타 앱 일괄 차단.
- **동작 요구사항**:
  - 기본값은 “전체 차단”으로 모든 카테고리가 활성화된 상태.
  - 카테고리별 설정은 Room에 저장하여 이후 세션에 자동 적용.
  - 설정 변경 즉시 프리뷰 문구 업데이트(예: “SNS와 영상 앱만 차단합니다”).
  - AccessibilityService는 선택된 카테고리에 따라 차단 패키지 목록을 동적으로 로드한다.
  - DndManager는 세션 시작/종료 시 현재 정책을 그대로 유지하되, 사용자에게 “알림 전체 차단” 상태를 안내한다(카테고리별 DND 필터는 제공되지 않음).
  - 중도 권한 해제 발생 시, 설정 화면에서 경고 표시 및 재요청 버튼 제공.

### 4.2 리포트 고도화
- **데이터 보강**:
  - `FocusSession` 모델에 `interruptedSeconds`, `primaryDistractionCategory`, `giveUpReason` 필드 추가.
  - 세션 중 차단 이벤트를 `FocusInterruption` 테이블(세션 ID, 발생 시각, 앱 패키지, 카테고리)로 기록, 리포트 집계 시 참조.
  - 중도 포기 시에도 타이머가 진행된 시간(`elapsedSeconds`)을 기록하여 총 집중 시간에 합산.
- **지표 확장**:
  - **집중률 성장세**: 최근 7일/30일 대비 집중 성공률 변화 그래프.
  - **평균 집중 유지 시간**: 성공/실패 분리, 실패 시 중도포기까지의 평균 시간 제공.
  - **방해요인 Top 3**: 차단된 앱 카테고리/앱별 발생 횟수와 포기 연관성.
  - **포인트 성장 추세**: 주간 포인트 획득 변화, 다음 보상까지 남은 포인트.
  - **세션 품질 점수(β)**: 성공률, 방해요인, 포기 지점 등을 가중치로 계산한 0~100 지표(내부 알파 → 택스트로 “향상 필요/안정/우수” 단계 제공).
- **UI 요구사항**:
  - 일간 카드: 요약 KPI + 실패 포함 집중 시간, 누적 포인트, 집중률 변화.
  - 주간 인사이트: 그래프 2개(집중률/총 집중시간) + 방해요인 카드.
  - 도움말/Tooltips로 계산 기준 설명.
- **정확성 요구사항**:
  - 세션 종료 시점에 타이머 잔여 시간을 기반으로 elapsed 계산(중도 종료 처리).
  - Accessibility 차단 이벤트(`FocusInterruption`)를 세션에 귀속해 리포트에 반영하고, DND 권한 상태는 참고 지표로만 표시.

## 5. 데이터 및 트래킹
- **로컬 DB**:
  - `FocusSession` 추가 필드 저장 및 마이그레이션 스크립트 필요(Room Migration v2→v3).
  - `UserSettings` 또는 별도 `ReportSnapshot` 테이블에 집계 캐싱.
- **이벤트 로깅**:
  - `focus_settings_open`, `focus_settings_saved`, `focus_settings_category_toggle`.
  - `report_view_daily`, `report_view_weekly`, `report_insight_expand`.
  - `session_interrupted`(reason/category 포함).
- **분석 지표**: 카테고리 활용률, 집중률 변화, 리포트 조회 빈도, 실패 원인 Top.

## 6. 비기능 요구사항
- 권한 변경 감지 시 UI 피드백 < 500ms.
- 리포트 화면 신규 카드 추가 후 첫 로딩 < 1.5s (캐싱/비동기 처리).
- 오프라인에서도 최신 리포트 데이터를 조회 가능(최근 캐시 사용).

## 7. 위험 요소 및 대응
- **카테고리 분류 정확도**: 패키지 매핑 누락 시 차단 실패 → 초기 버전에선 정적 매핑 + 사용자 커스텀 블랙리스트 제공 고려.
- **데이터 마이그레이션**: Room 마이그레이션 실패 시 앱 크래시 위험 → 스테이징 디바이스에서 필수 검증 및 백업/복구 로직 마련.
- **지표 해석 난이도**: 사용자에게 지표가 과도하게 복잡해 보일 수 있음 → UI 카피 및 툴팁으로 단순화, 핵심 KPI는 상단 카드에 요약.

## 8. 완료 기준(DoD)
- 집중모드 설정 화면에서 카테고리 조정 후 세션을 시작해, 해당 카테고리 앱이 정상 차단되고 예외 앱은 허용되는 것을 QA 체크리스트로 검증.
- 중도 포기한 세션의 진행 시간과 방해요인이 리포트 전체/일간 통계에 반영돼 수치가 일치함을 확인.
- 리포트 고도화 카드(집중률 추세, 방해요인, 포인트 추세)가 실제 데이터로 채워지며 빈 상태에서는 비어있음 안내가 노출.
- 신규 이벤트 로그가 QA 빌드에서 확인되며, 기존 리포트 기능엔 회귀 오류가 없는 상태로 `./gradlew assembleDebug` 및 `./gradlew test` 통과.
