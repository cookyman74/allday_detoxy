## 4. 테스트 시나리오

### 4.1 디톡시 제어 설정 테스트

#### 시나리오 1: 프리셋 선택 (완전 차단)
```
1. 디톡시 제어 설정 화면 진입 (DetoxyControlSettingsScreen)
2. "완전 차단" 프리셋 선택 (고위험 사용자 권장)
3. 프리뷰 문구 확인: "완전 차단: SNS, Web, 영상, 기타 앱 차단 중. 디톡시 회복에 집중하세요."
4. 설정 저장 → Analytics 이벤트 로깅 확인 (detoxy_settings_saved, preset="complete_block")
5. 타이머 시작
6. 각 카테고리 앱 실행 시도
   - SNS: Instagram (차단 확인 ✅, LockOverlayScreen 표시)
   - Web: Chrome (차단 확인 ✅)
   - 영상: YouTube (차단 확인 ✅)
   - 메신저: KakaoTalk (허용 확인 ✅)
   - 기타: 게임 앱 (차단 확인 ✅)
```

#### 시나리오 2: 표준 디톡시 (회복 중기)
```
1. "표준 디톡시" 프리셋 선택
2. SNS, 영상만 차단 확인
3. Web, 메신저, 기타 허용 확인
4. 타이머 시작 후 Chrome (허용 ✅), YouTube (차단 ✅)
```

#### 시나리오 3: 메신저 차단 UX
```
1. "완화" 프리셋 선택
2. 메신저 카테고리 토글 ON 시도
3. 안내 다이얼로그 표시 확인:
   - 제목: "💬 메신저 차단 안내"
   - 내용: "긴급 연락이 필요할 수 있어...", "디지털 중독 회복을 위해...", "⚠️ 긴급 연락이 불가능..."
   - 버튼: "메신저도 차단" / "허용 유지 (권장)"
4. "메신저도 차단" 선택
5. Analytics 로깅 확인 (dialog_shown=true)
6. 타이머 시작 후 KakaoTalk (차단 ✅)
```

#### 시나리오 4: 커스텀 설정
```
1. "완화" 프리셋 선택
2. Web 카테고리 수동 활성화
3. 프리셋이 "커스텀"으로 자동 전환 확인
4. Analytics 로깅: preset="custom"
```

4. 기존 데이터 보존 확인 ✅

### 4.3 리포트 고도화 테스트

#### 시나리오 5: 디톡시 위험 지수 (중독 진단)
```
1. 세션 10개 생성 (성공 7개, 실패 3개)
2. 방해요인 이벤트 5개 생성 (Instagram x3, YouTube x2)
3. 리포트 화면 진입
4. 디톡시 위험 지수 카드 확인 ✅
5. 점수 계산 정확도 검증 (예상: 32점) ✅
6. 위험 단계 표시 확인 ("회복" 단계, 0-30점) ✅
7. 메시지 확인: "디지털 중독 위험도가 낮아요! 회복이 잘 진행되고 있습니다. 💪"
8. Analytics 로깅: report_risk_index_calculated(risk_level="recovery")
```

#### 시나리오 6: 디톡시 회복률 추세 (신규)
```
1. 2주간 세션 데이터 생성
   - 1주차: 성공 5개, 실패 5개 (회복률 50%)
   - 2주차: 성공 8개, 실패 2개 (회복률 80%)
2. 리포트 화면 진입
3. 회복률 추세 카드 확인 ✅
4. 주간 변화량 표시 확인: "50% → 80% (+30%p) ⬆️"
5. Analytics 로깅: report_recovery_rate_calculated(recovery_rate=80, change=30)
6. 그래프 렌더링 확인 (7일 추세)
```

#### 시나리오 7: 방해요인 Top 3
```
1. 다양한 앱 차단 이벤트 생성
   - Instagram: 8회
   - YouTube: 5회
   - Chrome: 3회
2. 리포트 화면 진입
3. 방해요인 Top 3 카드 확인 ✅
4. 순위 및 횟수 정확도 검증 ✅
5. 앱 아이콘 표시 확인 ✅
6. "ℹ️ 자세히" 버튼 클릭 → 전체 목록 확인
```

#### 시나리오 8: 디톡시 코치 추천 (중독/회복 관점)
```
1. 위험 지수에 따른 추천 메시지 확인
   - 0-30점 (회복): "디지털 웰빙 회복이 순조로워요! 지금처럼만 유지하세요. 🎉"
   - 31-60점 (주의): "[앱명] 차단 시도가 증가 중입니다. 디톡시 타이머를 10분 더 늘려 회복 속도를 높여보세요."
   - 61-100점 (고위험): "중독 재발 위험! 이번 주 디톡시 시간이 50% 감소했어요. 긴급히 '완전 차단' 모드로 전환하세요."
2. 코치 추천 카드에서 "적용" 버튼 클릭 ✅
3. 디톡시 제어 설정 화면으로 이동 확인
```

### 4.4 권한 플로우 테스트

#### 시나리오 9: 권한 해제 후 재요청
```
1. 모든 권한 부여 상태에서 시작
2. 타이머 시작 (정상 작동 확인)
3. 설정 → 접근성 서비스 비활성화
4. 앱으로 복귀
5. 타이머 시작 시도
6. 권한 에러 다이얼로그 표시 확인 ✅
7. "설정으로 이동" 클릭 ✅
8. 접근성 서비스 재활성화
9. 앱으로 복귀 후 타이머 시작 (정상 작동) ✅
```

#### 시나리오 10: UsageStats 권한 플로우 (신규)
```
1. 리포트 화면 진입
2. "더 정확한 통계를 위해 UsageStats 권한이 필요합니다" 안내 카드 확인
3. "허용하기" 버튼 클릭
4. Android UsageStats 설정 화면으로 이동 ✅
5. AllDay Detoxy 앱 선택 → 허용
6. Analytics 로깅: usage_stats_opt_in(granted=true)
7. 앱으로 복귀 후 UsageStats 데이터 연동 확인
8. 리포트에 앱 사용 시간 통계 추가 표시 확인 ✅
```

#### 시나리오 11: UsageStats 권한 거부
```
1. 리포트 화면에서 "허용하기" 클릭
2. UsageStats 설정 화면에서 허용하지 않음
3. Analytics 로깅: usage_stats_opt_in(granted=false)
4. 앱으로 복귀
5. 기본 리포트 정상 표시 확인 (FocusSession 기반)
6. "UsageStats 권한 없이도 기본 리포트를 제공합니다" 안내 표시 ✅
```

### 4.5 디톡시 루틴 테스트 (신규)

#### 시나리오 12: 루틴 스케줄 설정
```
1. 설정 화면 → 디톡시 루틴 탭 진입
2. 아침 루틴 활성화 (09:00, 25분, 표준 디톡시)
3. 점심 루틴 활성화 (12:00, 15분, 완전 차단)
4. 저녁 루틴 활성화 (18:00, 30분, 표준 디톡시)
5. 각 루틴 설정 저장 확인
6. 메신저 차단 여부 별도 설정: 점심 루틴에서만 메신저 차단
```

#### 시나리오 13: 루틴 자동 실행
```
1. 아침 루틴 시간 (09:00) 도래
2. 알림 표시 확인: "아침 디톡시 루틴 시간입니다"
3. 루틴 자동 시작 확인 (타이머 25분)
4. Analytics 로깅: detoxy_routine_completed(routine_type="morning", success=true)
5. 타이머 정상 작동 확인
6. 완료 시 "아침 루틴 완료! +25 포인트" 표시
```

#### 시나리오 14: 루틴 건너뛰기
```
1. 점심 루틴 알림 표시
2. "나중에" 버튼 클릭
3. 루틴 건너뛰기 확인
4. Analytics 로깅: detoxy_routine_completed(routine_type="lunch", success=false)
5. 리포트에 루틴 준수율 반영 확인 (루틴 완료 1/2 = 50%)
```

## 5. 성능 테스트

### 5.1 메모리 사용량
```
adb shell dumpsys meminfo com.allday.detoxy
```

**목표**:
- 유휴 상태: < 100MB
- 타이머 실행 중: < 150MB
- 오버레이 표시 중: < 180MB

---

### 5.2 배터리 소모
```
adb shell dumpsys batterystats --reset
# 24시간 사용 후
adb shell dumpsys batterystats > battery_stats.txt
```

**목표**:
- 일일 배터리 사용량: < 5%
- 타이머 1시간당 배터리 소모: < 2%

---

### 5.3 앱 크기
```
adb shell pm path com.allday.detoxy
adb pull /data/app/.../base.apk
ls -lh base.apk
```

**목표**:
- APK 크기: < 10MB
- 설치 후 크기: < 20MB

## 7. 버그 트래킹

### 7.1 버그 리포트 템플릿
```markdown
## 버그 제목
[간단한 설명]

## 재현 단계
1. [단계 1]
2. [단계 2]
3. [단계 3]

## 예상 결과
[정상 동작]

## 실제 결과
[실제 발생한 문제]

## 환경 정보
- 기기: Samsung Galaxy S23
- OS: Android 14 (One UI 6.1)
- 앱 버전: v2.0.0 (빌드 200)

## 로그
```
[logcat 출력 또는 스크린샷]
```

## 우선순위
- [ ] Critical (앱 크래시, 데이터 손실)
- [ ] High (주요 기능 동작 불가)
- [ ] Medium (일부 기능 오작동)
- [ ] Low (UI 이슈, 개선 제안)
```

### 7.2 버그 관리
- **도구**: GitHub Issues
- **라벨**:
  - `bug`: 버그
  - `critical`: 치명적 버그
  - `enhancement`: 개선 사항
  - `device-specific`: 특정 기기 이슈
  - `regression`: 회귀 버그
