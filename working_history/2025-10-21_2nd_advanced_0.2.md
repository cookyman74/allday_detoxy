## 🔍 근본 원인 분석

### 0.1 수정의 문제점

**FocusTimerService.kt (0.1 수정)**:
```kotlin
// 정상 완료
if (_state.value == FocusState.RUNNING && _remainingSeconds.value == 0) {
    Log.d(TAG, "Timer finished successfully")
    _state.value = FocusState.FINISHED
    
    // 타이머 완료 브로드캐스트 (ViewModel이 세션 종료 처리)
    sendTimerFinishedBroadcast(success = true)
    
    // 브로드캐스트가 전달될 시간을 주기 위해 지연 후 Service 종료
    delay(500)  // ← 500ms 지연 추가
    stopSelf()
}
```

**문제점**:
- ✅ 500ms 지연을 추가했지만 **여전히 브로드캐스트 전달이 보장되지 않음**
- ❌ Android 시스템 부하, 백그라운드 제약 등으로 브로드캐스트가 유실될 수 있음
- ❌ 프로세스 간 통신(IPC)의 불확실성
- ❌ 타이밍 이슈로 인한 경쟁 조건(Race Condition)

### 실제 동작 플로우 (실패 케이스)

```
타이머 완료 (remainingSeconds == 0)
  ↓
FocusTimerService: _state = FINISHED
  ↓
sendTimerFinishedBroadcast(success = true)
  ↓
delay(500ms) ⏱️
  ↓
stopSelf() ← Service 종료
  ↓
❌ 브로드캐스트가 아직 전달되지 않음!
  ↓
TimerViewModel.timerFinishedReceiver ← 수신 못함
  ↓
onTimerFinish(success=true) 호출 안됨 ❌
  ↓
FocusAccessibilityService.isTimerRunning = true (여전히!)
  ↓
사용자가 웹브라우저 실행
  ↓
AccessibilityService가 차단 시도
  ↓
LockOverlayService.showOverlay(0, 0) ← remainingSeconds, totalSeconds가 0
  ↓
LockOverlayService 비정상 동작
  ↓
AccessibilityService 크래시 💥
  ↓
접근성 설정: "이 서비스가 제대로 작동하지 않습니다"
```

### 왜 브로드캐스트가 전달되지 않을까?

1. **Android 시스템 제약**
   - Android 8.0+ (Oreo)부터 백그라운드 브로드캐스트 제약 강화
   - 암묵적 브로드캐스트(Implicit Broadcast) 제한
   - 배터리 최적화로 인한 브로드캐스트 지연/유실

2. **Service 생명주기 문제**
   - `stopSelf()` 호출 시 Service가 즉시 종료될 수 있음
   - 브로드캐스트 전송 후 500ms 지연이 충분하지 않을 수 있음
   - 시스템이 Service를 강제 종료할 수 있음

3. **프로세스 우선순위**
   - Foreground Service가 종료되면 프로세스 우선순위가 낮아짐
   - 낮은 우선순위 프로세스의 브로드캐스트는 지연되거나 유실될 수 있음

## ✅ 해결 방법: StateFlow로 전환

### 왜 StateFlow가 더 나은가?

1. **즉각적인 반응** ⚡
   - StateFlow는 값이 변경되면 **즉시** collector에게 emit
   - 브로드캐스트와 달리 시스템 제약 없음
   - 같은 프로세스 내에서 직접 관찰

2. **전달 보장** ✅
   - StateFlow는 항상 최신 상태를 보유
   - Collector가 구독하면 **즉시 현재 상태를 받음**
   - 브로드캐스트처럼 유실될 위험 없음

3. **생명주기 안전** 🛡️
   - ViewModel의 viewModelScope에서 collect
   - ViewModel이 살아있는 동안 안전하게 관찰
   - 자동으로 취소 및 정리

4. **디버깅 용이** 🔍
   - 상태 변화를 로그로 추적하기 쉬움
   - 브로드캐스트보다 명확한 플로우

### 구현 방식

**기존 (0.1) - BroadcastReceiver 사용**:
```
FocusTimerService → sendBroadcast() → SystemServer → TimerViewModel.BroadcastReceiver
                    (불안정)           (유실 가능)
```

**변경 후 (0.2) - StateFlow 사용**:
```
FocusTimerService._state.value = FINISHED
                    ↓ (즉시)
TimerViewModel.timerState.collect { state -> ... }
                    ↓ (보장됨)
onTimerFinish(success=true)
```

## 📝 수정 사항

### TimerViewModel.kt - StateFlow 관찰로 전환

**파일**: `app/src/main/java/com/allday/detoxy/presentation/viewmodel/TimerViewModel.kt`

#### 수정 1: BroadcastReceiver 제거 (라인 75-76)

**기존 코드**:
```kotlin
// 타이머 완료 브로드캐스트 리시버
private val timerFinishedReceiver = object : BroadcastReceiver() {
    override fun onReceive(context: Context?, intent: Intent?) {
        intent?.let {
            if (it.action == FocusTimerService.ACTION_TIMER_FINISHED) {
                val success = it.getBooleanExtra(FocusTimerService.EXTRA_SUCCESS, false)
                Log.d(TAG, "Timer finished broadcast received: success=$success")
                onTimerFinish(success)
            }
        }
    }
}
```

**변경 후**:
```kotlin
// 타이머 완료 추적을 위한 이전 상태
private var previousTimerState: FocusState = FocusState.IDLE
```

#### 수정 2: init 블록 - StateFlow 관찰 추가 (라인 90-135)

**변경 후**:
```kotlin
init {
    // 사용자 설정 초기화 (최초 실행 시)
    viewModelScope.launch {
        val settings = repository.getSettings().first()
        if (settings == null) {
            repository.initializeSettings(
                UserSettings(
                    id = 1,
                    totalPoints = 0,
                    currentStreak = 0,
                    lastSuccessDate = null
                )
            )
        }
    }

    // ✅ 타이머 상태 관찰 (브로드캐스트 대신 StateFlow 사용)
    viewModelScope.launch {
        timerState.collect { currentState ->
            Log.d(TAG, "🔔 Timer state changed: $previousTimerState → $currentState")
            
            // RUNNING → FINISHED: 정상 완료
            if (previousTimerState == FocusState.RUNNING && currentState == FocusState.FINISHED) {
                Log.d(TAG, "✅ Timer finished successfully (detected via StateFlow)")
                onTimerFinish(success = true)
            }
            // RUNNING → FAILED: 포기
            else if (previousTimerState == FocusState.RUNNING && currentState == FocusState.FAILED) {
                Log.d(TAG, "❌ Timer failed (detected via StateFlow)")
                onTimerFinish(success = false)
            }
            
            previousTimerState = currentState
        }
    }

    // 타이머 남은 시간을 AccessibilityService에 실시간 동기화
    viewModelScope.launch {
        remainingSeconds.collect { seconds ->
            FocusAccessibilityService.remainingSeconds = seconds
        }
    }
    
    Log.d(TAG, "✅ TimerViewModel initialized with StateFlow observation")
}
```

**주요 변경 사항**:
1. **`timerState` StateFlow를 관찰**
2. **상태 전이 감지**: `RUNNING → FINISHED` (정상 완료), `RUNNING → FAILED` (포기)
3. **즉시 `onTimerFinish()` 호출** - 브로드캐스트 지연 없음
4. **이전 상태 추적**: `previousTimerState`로 상태 전이 감지

#### 수정 3: onCleared() 간소화 (라인 358-367)

**기존 코드**:
```kotlin
override fun onCleared() {
    super.onCleared()
    
    // BroadcastReceiver 해제
    try {
        application.unregisterReceiver(timerFinishedReceiver)
        Log.d(TAG, "Timer finished receiver unregistered")
    } catch (e: IllegalArgumentException) {
        Log.w(TAG, "Receiver already unregistered: ${e.message}")
    }
    
    // ViewModel 종료 시 타이머도 중지
    if (timerState.value == FocusState.RUNNING) {
        resetTimer()
    }
}
```

**변경 후**:
```kotlin
override fun onCleared() {
    super.onCleared()
    
    // ViewModel 종료 시 타이머도 중지
    if (timerState.value == FocusState.RUNNING) {
        resetTimer()
    }
    
    Log.d(TAG, "✅ TimerViewModel cleared")
}
```

**주요 변경 사항**:
1. **BroadcastReceiver 해제 코드 제거** - 더 이상 사용하지 않음
2. **코드 간소화** - StateFlow는 자동으로 정리됨
