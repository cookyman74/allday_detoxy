### 1.4.1 권한 체크 로직 ✅
- **PermissionCheckScreen 생성** (`presentation/ui/permission/PermissionCheckScreen.kt`)
  - Compose 기반 권한 안내 화면
  - 권한 상태 실시간 추적 (mutableStateOf)
  - Lifecycle 감지를 통한 onResume 시 권한 재확인
  - 모든 필수 권한 부여 시 자동 화면 전환 (LaunchedEffect)

**주요 기능**:
```kotlin
@Composable
fun PermissionCheckScreen(
    onAllPermissionsGranted: () -> Unit
) {
    // 권한 상태 추적
    var accessibilityGranted by remember { 
        mutableStateOf(PermissionUtils.isAccessibilityServiceEnabled(context))
    }
    var overlayGranted by remember {
        mutableStateOf(PermissionUtils.canDrawOverlays(context))
    }
    var dndGranted by remember {
        mutableStateOf(PermissionUtils.hasNotificationPolicyAccess(context))
    }
    
    // onResume 시 권한 재확인
    DisposableEffect(lifecycleOwner) {
        val observer = LifecycleEventObserver { _, event ->
            if (event == Lifecycle.Event.ON_RESUME) {
                accessibilityGranted = PermissionUtils.isAccessibilityServiceEnabled(context)
                overlayGranted = PermissionUtils.canDrawOverlays(context)
                dndGranted = PermissionUtils.hasNotificationPolicyAccess(context)
            }
        }
        lifecycleOwner.lifecycle.addObserver(observer)
        onDispose { lifecycleOwner.lifecycle.removeObserver(observer) }
    }
    
    // 모든 필수 권한 부여 시 자동 전환
    LaunchedEffect(accessibilityGranted, overlayGranted) {
        if (accessibilityGranted && overlayGranted) {
            onAllPermissionsGranted()
        }
    }
}
```

### 1.4.5 초기 실행 플래그 관리 ✅

#### PreferenceManager 생성 (`core/utils/PreferenceManager.kt`)
```kotlin
class PreferenceManager(context: Context) {
    private val prefs = context.getSharedPreferences("app_prefs", Context.MODE_PRIVATE)
    
    companion object {
        private const val PREF_NAME = "app_prefs"
        private const val KEY_FIRST_LAUNCH = "is_first_launch"
    }
    
    fun isFirstLaunch(): Boolean {
        return prefs.getBoolean(KEY_FIRST_LAUNCH, true)
    }
    
    fun setFirstLaunchCompleted() {
        prefs.edit().putBoolean(KEY_FIRST_LAUNCH, false).apply()
    }
    
    fun resetFirstLaunch() {  // 테스트용
        prefs.edit().putBoolean(KEY_FIRST_LAUNCH, true).apply()
    }
}
```

**특징**:
- SharedPreferences 기반 영구 저장
- 앱 삭제 전까지 유지
- 디버깅을 위한 resetFirstLaunch() 제공

#### MainActivity에서 초기 화면 분기
```kotlin
@Composable
fun MainScreen() {
    val context = LocalContext.current
    val preferenceManager = remember { PreferenceManager(context) }
    var showPermissionCheck by remember { 
        mutableStateOf(preferenceManager.isFirstLaunch()) 
    }
    
    if (showPermissionCheck) {
        // 첫 실행 시 권한 안내 화면
        PermissionCheckScreen(
            onAllPermissionsGranted = {
                preferenceManager.setFirstLaunchCompleted()
                showPermissionCheck = false
            }
        )
    } else {
        // 메인 타이머 화면
        Scaffold { TimerScreen() }
    }
}
```

**동작**:
- 최초 실행: PermissionCheckScreen 표시
- 이후 실행: 바로 TimerScreen 표시
- 권한 모두 허용 → setFirstLaunchCompleted() 호출 → 플래그 false

## 구현 패턴 및 Best Practices

### 1. Composition over Inheritance
- `PreferenceManager`를 클래스로 구현하여 재사용성 향상
- `PermissionCard`를 Composable 함수로 분리하여 재사용

### 2. State Hoisting
- 권한 상태를 PermissionCheckScreen에서 관리
- onAllPermissionsGranted 콜백으로 상위 컴포넌트에 알림

### 3. Lifecycle Awareness
- LifecycleEventObserver로 onResume 이벤트 감지
- DisposableEffect로 자동 정리 (메모리 누수 방지)

### 4. Reactive UI
- mutableStateOf로 권한 상태 추적
- LaunchedEffect로 상태 변화 감지 및 자동 액션
- 사용자 인터랙션 최소화 (수동 확인 버튼 불필요)

### 5. User-Friendly UX
- 기술 용어 대신 기능 중심 설명
  - "접근성 서비스" → "앱 차단 기능"
  - "오버레이 권한" → "잠금 화면 표시"
- 필수/선택 권한 명확히 구분
- 단계별 안내 메시지 제공
- 자동 화면 전환으로 부드러운 플로우

### 6. Material Design 3
- Material3 컴포넌트 일관 사용 (Card, Button, Icon)
- MaterialTheme.colorScheme 활용
- 시각적 피드백 (색상 변화, 아이콘)

### 7. Defensive Programming
- 권한 체크를 여러 레이어에서 수행
  - PermissionCheckScreen: 초기 안내
  - TimerViewModel: 타이머 시작 전 재확인
- 로그 출력으로 디버깅 지원
- TODO 주석으로 향후 개선 사항 명시

## 주요 교훈 및 문서화

### 1. Compose in Service vs Activity
- **Service**: WindowManager를 통한 오버레이 (LockOverlayScreen)
- **Activity**: 일반 Compose UI (PermissionCheckScreen)
- Activity 컨텍스트에서는 Lifecycle 설정 자동 처리

### 2. Material Icons 제한
- 모든 아이콘이 Compose에서 지원되지 않음
- Block, NotificationsOff 등 일부 누락
- 대체 아이콘 사용 필요: Info, Close 등

### 3. SharedPreferences vs DataStore
- 간단한 플래그 저장: SharedPreferences 충분
- 복잡한 데이터 구조: DataStore 권장 (향후 마이그레이션 고려)

### 4. 권한 UX 원칙
1. 필수/선택 구분 명확히
2. 사용자 친화적 언어 사용
3. 자동화로 인터랙션 최소화
4. 시각적 피드백으로 현재 상태 명시
5. 안내 메시지로 다음 액션 가이드
