# 작업 기록: DB 마이그레이션 v7→v8

**작업 일시**: 2025-12-10  
**작업 범위**: 스케줄 그룹 통합 제어를 위한 DB 스키마 확장 (v7→v8)

## 작업 목적

스케줄 그룹의 활성/비활성/일시중지 상태를 사용자가 명시적으로 제어할 수 있도록 DB 스키마를 확장합니다.

### 해결하고자 하는 문제
- 위치기반 스케줄에서 사용자가 그룹을 비활성화해도 위치 진입 시 자동 활성화됨
- 사용자의 수동 제어 의도가 무시되는 문제

### 관련 PRD
- [04_버튼역할변경_prd.md](../../docs/04_버튼역할변경_prd.md)

## 변경 사항

### 1. ScheduleGroup 엔티티 필드 추가

**파일**: `app/src/main/java/com/allday/detoxy/data/local/entity/ScheduleGroup.kt`

```kotlin
// ==================== v8 추가: 통합 제어 ====================

/**
 * 사용자 수동 제어 상태 (v8+)
 * 
 * - null: 자동 모드 (기본값, 위치에 따라 자동 활성화/비활성화)
 * - "INACTIVE": 사용자가 명시적으로 비활성화 (Geofence 해제)
 * - "PAUSED": 사용자가 명시적으로 일시중지 (Geofence 유지, 알람만 건너뛰기)
 */
val manualOverrideState: String? = null,

/**
 * 일시중지 해제 시각 (v8+)
 * 
 * - null: 일시중지 아님 또는 무기한
 * - timestamp: 해당 시각에 자동으로 활성 상태로 전환
 */
val pauseUntil: Long? = null
```

### 2. Migration 클래스 생성

**파일**: `app/src/main/java/com/allday/detoxy/data/local/migration/Migration_7_8.kt`

```kotlin
val MIGRATION_7_8 = object : Migration(7, 8) {
    override fun migrate(db: SupportSQLiteDatabase) {
        // 1. manualOverrideState 필드 추가
        db.execSQL("""
            ALTER TABLE schedule_group 
            ADD COLUMN manualOverrideState TEXT DEFAULT NULL
        """.trimIndent())

        // 2. pauseUntil 필드 추가
        db.execSQL("""
            ALTER TABLE schedule_group 
            ADD COLUMN pauseUntil INTEGER DEFAULT NULL
        """.trimIndent())

        // 3. 기존 데이터 마이그레이션
        // isActive=false인 그룹은 manualOverrideState='INACTIVE'로 설정
        db.execSQL("""
            UPDATE schedule_group 
            SET manualOverrideState = 'INACTIVE' 
            WHERE isActive = 0
        """.trimIndent())
    }
}
```

## 다음 단계 주의사항

### 단계 2 (ScheduleControlButton 구현) 시 참고

1. **manualOverrideState 값 사용**
   - `null`: ACTIVE 상태 (자동 모드)
   - `"INACTIVE"`: INACTIVE 상태
   - `"PAUSED"`: PAUSED 상태 (pauseUntil 확인 필요)

2. **pauseUntil 만료 체크**
   - `pauseUntil != null && System.currentTimeMillis() >= pauseUntil` 이면 만료됨
   - 만료 시 ACTIVE로 표시하고, 백그라운드에서 `clearExpiredPauses()` 호출 권장

3. **기존 isActive 필드와의 관계**
   - `isActive`는 위치 진입/이탈 시 자동 변경되는 "현재 상태"
   - `manualOverrideState`는 사용자의 "의도"를 저장
   - 위치 진입 로직에서 `manualOverrideState`를 먼저 확인하여 사용자 의도 존중

## 교훈 및 참고사항

1. **SQLite ALTER TABLE 제약**
   - SQLite는 ADD COLUMN만 지원, 컬럼 타입 변경이나 삭제 불가
   - nullable 필드는 DEFAULT NULL로 추가

2. **마이그레이션 데이터 변환**
   - 기존 `isActive=false` 데이터를 `manualOverrideState='INACTIVE'`로 변환
   - 사용자가 명시적으로 비활성화한 것으로 간주
