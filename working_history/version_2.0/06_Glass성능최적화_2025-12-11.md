## 📝 작업 개요
Glassmorphism 구현의 마지막 단계로, 코드 레벨에서의 성능 최적화와 테마 대응성을 점검했습니다. 특히 다크 모드에서의 시인성 문제와 저사양 기기에서의 Fallback 메커니즘을 중점적으로 개선했습니다.

## 🛠 작업 내용

### 1. 다크 모드 대응 최적화
`app/src/main/java/com/allday/detoxy/presentation/ui/component/GlassModifier.kt`

- **문제점**: 기존 코드에서는 `glassTint`가 기본적으로 `GlassWhite`로 고정되어 있어, 다크 모드에서도 밝은 유리 패널이 표시되어 눈부심을 유발하고 테마와 이질감이 있었습니다.
- **해결**:
  - `liquidGlass` 수정자를 업데이트하여 `glassTint`가 명시되지 않은 경우(`Color.Unspecified`), 시스템 테마(`isSystemInDarkTheme()`)를 감지하여 자동으로 Tint 색상을 결정하도록 변경했습니다.
  - Light Mode: `GlassWhite` (Alpha 0.4f)
  - Dark Mode: `GlassBlack` (Alpha 0.5f)
- **효과**: 다크 모드에서 한층 더 깊이 있고 고급스러운 "Dark Glass" 효과가 연출됩니다.

### 2. Fallback 메커니즘 점검
- **로직 확인**: `liquidGlass` 내부에서 `hazeState`가 `null`일 경우 `Modifier.hazeChild` 대신 단순 `Modifier.background`를 적용하는 로직이 이미 존재함을 확인했습니다.
- **활용**:
  - Preview 모드나 Haze 라이브러리를 초기화할 수 없는 환경, 또는 성능 문제로 `LocalHazeState`를 제공하지 않는 경우 안전하게 반투명 배경으로 Fallback 됩니다.
  - 이는 저사양 기기 대응을 위한 중요한 안전장치입니다.

### 3. 성능 고려 사항 (GPU Overdraw)
- **Blur Radius**: 기본 `20.dp`는 모바일 GPU에서 실시간 렌더링하기에 꽤 무거운 연산입니다. 리스트(LazyColumn) 내의 아이템(`ScheduleGroupCard`)에는 동일한 modifier를 사용하되, `Haze` 라이브러리의 최적화(View 렌더링 캐싱 등)에 의존합니다.
- **Overdraw**: `GlassSurface` 내의 컨텐츠는 불투명도를 가지고 있어 뒤쪽의 Mesh Gradient와 겹쳐 그려지므로(Overdraw), 복잡한 중첩을 피하는 것이 좋습니다. 현재 구조는 `Scaffold(Background) -> Surface(Glass) -> Content` 로 3단계 깊이이므로 허용 가능한 수준입니다.
