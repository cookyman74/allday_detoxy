| Low | 자정 넘김 상세 리스트 테스트 케이스 부족 | 셀 합산만 검증, 상세 리스트 검증 없음 |

### 수정 내용

**1. TimeSlotInfo 저장 로직 변경**
- 기존: 요일별 저장 → `createRow()`에서 시작 시간 기준 필터링
- 변경: 요일+Period별 분리 저장 (`dayPeriodTimeSlots: Map<Pair<DayOfWeek, Period>, List<TimeSlotInfo>>`)

```kotlin
// 기여하는 모든 요일+Period 조합에 저장
val contributedDayPeriods = slots.map { slot ->
    val targetDay = day.plus(slot.dayOffset.toLong())
    val period = if (slot.hour in 0..11) Period.AM else Period.PM
    Pair(targetDay, period)
}.toSet()

contributedDayPeriods.forEach { key ->
    val list = dayPeriodTimeSlots.getOrPut(key) { mutableListOf() }
    // 중복 방지
    if (list.none { it.id == timeSlotInfo.id }) {
        list.add(timeSlotInfo)
    }
}
```

**2. createRow() 단순화**
- 필터링 로직 제거, 이미 분리된 목록 전달

**3. 테스트 케이스 추가** (3개)
- `자정 넘김 스케줄은 당일 PM과 다음날 AM 모두 상세 리스트에 포함`
- `자정 넘김 스케줄이 당일 PM에만 있고 AM에는 없어야 할 때 정확히 분리`
- `자정 넘김 시 동일 스케줄이 중복 저장되지 않음`

### Open Question 결정

> Q: 상세 시트에 "시작 시각"을 표시할지, "해당 행에 기여한 슬롯 기준 시각"을 표시할지?

**결정: 시작 시각 기준 유지**
- 사용자에게 원래 설정한 스케줄 정보를 보여주는 것이 직관적
- 자정 넘김 스케줄의 경우, 다음날 AM에 표시되더라도 "어제 밤 시작된 스케줄"임을 인지할 수 있음
- UI에서 "(전날 시작)" 등의 표시는 Phase 3 UI 컴포넌트 구현 시 고려 가능
