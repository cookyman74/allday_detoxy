## 📌 정책 정의 (최종)

### 1. 제한 기준: **활성화 수 제한**
- 위치 기반 스케줄은 **등록 무제한**
- **활성화(is_enabled=true)** 상태는 최대 5개로 제한
- 5개 활성화 상태에서 추가 활성화 시도 시 에러 표시

### 2. Geofence 실패 시 정책 (모든 메서드 동일 적용)
| 메서드 | Geofence 실패 시 처리 |
|--------|----------------------|
| `addLocation()` | isEnabled=false로 DB 저장 + 에러 표시 |
| `updateLocation()` | isEnabled=false로 DB 저장 + 에러 표시 |
| `toggleLocation()` | isEnabled=false로 DB 저장 + 에러 표시 |

### 3. 방어 계층
- **1차 (UX)**: ViewModel에서 선제 개수 체크 → 사용자에게 빠른 피드백
- **2차 (최종)**: `AutoRunGeofenceManager.addGeofence()`에서 최종 방어

### 4. enabledCount 이중 용도 (리뷰 반영)
| 용도 | 데이터 소스 | 특성 |
|------|------------|------|
| **UX 표시용** | `repository.getEnabled()` Flow 기반 | 비동기, 일시적 지연 가능 |
| **정책 체크용** | `repository.getEnabledCount()` 직접 호출 | 동기적 최신 값 |

> ⚠️ UX 표시용 enabledCount와 정책 체크용 getEnabledCount()는 일시적으로 불일치할 수 있음 (Flow 수신 지연). 이는 의도된 설계이며, 최종 방어는 Manager가 담당.
