## 🐛 문제 1: 위치 정보 수정 후 부모 페이지 갱신 안 됨

### 문제 상황
```

1. 스케줄 그룹 "학교" → 📍 위치 클릭
2. [위치 정보 수정] 다이얼로그
3. 반경: 150m → 200m 변경
4. [저장] 클릭
5. 다이얼로그 닫힘
6. 스케줄 그룹 카드에 여전히 "150m" 표시 ❌
```

### 원인 분석
```kotlin

    viewModelScope.launch {  // 비동기로 실행됨 (즉시 반환)
```

**타이밍 이슈**:
1. `updateLocation()` 호출 → 백그라운드 실행 시작
2. 즉시 `loadLinkedLocations()` 호출
3. DB에 아직 이전 데이터가 있으므로 이전 값 로드
4. 나중에 `updateLocation()` 완료 (하지만 UI는 이미 이전 값 표시)

### 해결 방법

#### 1. LocationBasedAutoRunViewModel.kt 수정

```kotlin
/**
 * 위치 정보 업데이트 (suspend 함수)
 *
 * Geofence 재등록 및 DB 업데이트를 순차적으로 처리합니다.
 * suspend 함수로 구현되어 호출자가 완료를 기다릴 수 있습니다.
 */
suspend fun updateLocation(location: LocationBasedAutoRun) {
    try {
        // 1. 기존 Geofence 제거
        geofenceManager.removeGeofence(location.id)

        // 2. 새 Geofence 등록 (활성화된 경우만)
        if (location.isEnabled) {
            val result = geofenceManager.addGeofence(location)
            if (result.isFailure) {
                _errorState.value = LocationError.GeofenceError(...)
                return  // 실패 시 DB 업데이트 안 함
            }
        }

        // 3. Geofence 성공 후 DB 업데이트
        repository.update(location)

    } catch (e: Exception) {
        // DB 업데이트 실패 → Geofence 롤백
        geofenceManager.removeGeofence(location.id)
        _errorState.value = LocationError.DatabaseError(...)
    }
}
```

**Geocoder Address 필드 분석**:
```
예시: "경기도 고양시 일산동구 장항동 장항대로 761번지 일산라페스"
```

### 해결 방법

#### 1. getLocationName() 로직 개선

```kotlin
/**
 * Address에서 위치 이름 추출 (간략한 이름)
 *
 * 우선순위: locality (시/구) > subLocality (동) > featureName (건물명)
 */
private fun getLocationName(address: Address): String {
    // 1. 시/구 레벨 이름 우선 (예: "고양시")
    address.locality?.let { return it }
    
    // 2. 동 레벨 이름 (예: "장항동")
    address.subLocality?.let { return it }
    
    // 3. 건물명 (20자 이하만)
    address.featureName?.let { 
        if (it.length <= 20) return it
    }
    
    // 4. 도로명 (예: "장항대로")
    address.thoroughfare?.let { return it }
    
    return "알 수 없는 위치"
}
```

**우선순위 변경**:
- **Before**: featureName > thoroughfare > subLocality > locality
- **After**: locality > subLocality > featureName(20자 이하) > thoroughfare ✅

#### 2. getFullAddress() 로직 개선

```kotlin
/**
 * Address에서 전체 주소 추출
 *
 * 한국 주소 형태: "시/도 시/구 동 도로명 번지 건물명"
 */
private fun getFullAddress(address: Address): String {
    val parts = mutableListOf<String>()

    // 1. 시/도 (예: "경기도")
    address.adminArea?.let { parts.add(it) }

    // 2. 시/구 (예: "고양시")
    address.locality?.let { parts.add(it) }

    // 3. 동 (예: "일산동구")
    address.subLocality?.let { parts.add(it) }

    // 4. 도로명 (예: "장항대로")
    address.thoroughfare?.let { parts.add(it) }

    // 5. 번지 (예: "761번지")
    address.subThoroughfare?.let { parts.add(it) }

    // 6. 건물명 (중복 체크)
    address.featureName?.let { 
        if (!parts.any { part -> part.contains(it) }) {
            parts.add(it)
        }
    }

    return parts.joinToString(" ")
}
```

**한국 주소 형태**: 시/도 → 시/구 → 동 → 도로명 → 번지 → 건물명 ✅

```kotlin
            showSnackbar("위치 정보가 수정되었습니다")
        } catch (e: Exception) {
            showSnackbar("수정 실패: ${e.message}")
            Log.e("ScheduleGroupScreen", "❌ Failed", e)
        }
    }
}
```

### 1. suspend 함수의 중요성

```kotlin
// ❌ 비동기 함수 (타이밍 이슈)
fun updateLocation(...) {
    viewModelScope.launch { ... }
}

// ✅ suspend 함수 (순차 보장)
suspend fun updateLocation(...) {
    // 완료까지 대기
}
```

### 2. Compose 상태 관리

```kotlin
// ❌ 지연된 상태 변경
scope.launch {
    doWork()
    finally { showDialog = false }
}

// ✅ 즉시 상태 변경
showDialog = false  // Main 스레드에서 즉시
scope.launch { doWork() }  // 백그라운드
```
