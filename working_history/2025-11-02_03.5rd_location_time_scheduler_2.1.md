### 헬퍼 메서드 ✅

**파일**: `DefaultTemplates.kt`

```kotlin
/**
 * 모든 템플릿 목록
 */
val ALL_TEMPLATES = listOf(
    DAILY, WEEKDAY, WEEKEND, HOME, SCHOOL, OFFICE
)

/**
 * ID로 템플릿 찾기
 */
fun findById(id: String): ScheduleTemplate? {
    return ALL_TEMPLATES.find { it.id == id }
}

/**
 * 시간 기반 템플릿 목록
 */
fun getTimeBasedTemplates(): List<ScheduleTemplate> {
    return ALL_TEMPLATES.filter { !it.hasLocation }
}

/**
 * 위치 기반 템플릿 목록
 */
fun getLocationBasedTemplates(): List<ScheduleTemplate> {
    return ALL_TEMPLATES.filter { it.hasLocation }
}
```

**용도**:
- `ALL_TEMPLATES`: UI에서 전체 목록 표시
- `findById()`: ID로 템플릿 검색
- `getTimeBasedTemplates()`: 시간만 설정하는 템플릿 필터링
- `getLocationBasedTemplates()`: 위치 필요한 템플릿 필터링

**코드 통계**: 297줄 (주석 포함)

## 기술적 의사결정

### 1. ScheduleTemplate을 Domain 레이어에 배치

**결정**: `domain/model`에 배치

**근거**:
- ScheduleTemplate은 비즈니스 로직의 핵심 개념
- UI나 Data 레이어에 종속되지 않음
- TimeSlot과 동일한 레이어에 배치하여 일관성 유지

**이점**:
- Clean Architecture 준수
- 테스트 용이성 향상
- 재사용성 증가

### 2. DefaultTemplates를 Data 레이어에 배치

**결정**: `data/template`에 배치

**근거**:
- 템플릿은 "데이터"로 취급 (사전 정의된 설정값)
- Domain 레이어는 순수 비즈니스 로직만 포함
- 향후 서버에서 템플릿을 가져올 경우 Data 레이어에서 처리

**대안 검토**:
- `domain/template`에 배치: 비즈니스 로직이 아니므로 부적절
- `presentation/data`에 배치: UI에 종속되므로 부적절

### 3. TimeSlot 재사용

**결정**: Phase 1에서 정의한 TimeSlot 그대로 사용

**근거**:
- 시간대 데이터 구조는 동일
- 중복 코드 방지
- 일관성 유지 (커스텀과 템플릿 모두 동일한 TimeSlot 사용)

**이점**:
- 코드 재사용성 향상
- ViewModel에서 동일한 변환 로직 사용 가능
- 유지보수 용이

### 4. hasLocation 플래그로 템플릿 유형 구분

**결정**: Boolean 플래그 사용 (enum 대신)

**근거**:
- 템플릿 유형은 2가지만 존재 (시간/위치)
- 간단하고 명확한 구분
- 추가 enum 정의 불필요

**대안 검토**:
- `TemplateType` enum 사용: 오버엔지니어링
- 별도 클래스 상속: 복잡도 증가

### 5. Material Design 색상 사용

**결정**: Material Design 표준 색상 사용

**근거**:
- Android Material 3와 일관성
- 접근성 고려 (충분한 대비)
- 검증된 색상 조합

**색상 선택 기준**:
- **GREEN (#4CAF50)**: 긍정적, 일상적 (매일)
- **BLUE (#2196F3)**: 전문적, 업무적 (평일)
- **ORANGE (#FF9800)**: 활동적, 여유로운 (주말)
- **PURPLE (#9C27B0)**: 편안한, 개인적 (집)
- **INDIGO (#3F51B5)**: 학습, 집중 (학교)
- **BLUE_GREY (#607D8B)**: 중립적, 전문적 (회사)

### 6. defaultRadius 설정

**결정**: 학교는 150m, 나머지는 100m

**근거**:
- **학교**: 캠퍼스가 넓으므로 반경 증가
- **집/회사**: 일반적인 건물 크기 고려

**실제 테스트 필요**:
- 사용자 피드백에 따라 조정 가능
- GPS 정확도 고려

## 템플릿 설계 원칙

- 대부분의 템플릿에 사용

**중간 차단 (MEDIUM)**:
- 집 템플릿 (가족과의 소통 고려)

**완전 차단 (COMPLETE)**:
- 회사 점심 후 시간대 (중요 업무 시간)

### 3. 요일 설정

**매일 (7일)**:
- 일상 루틴 (매일, 집)

**평일 (5일)**:
