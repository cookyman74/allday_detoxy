## 기술적 의사결정

### 1. Companion Object 참조 방식 변경

**문제**: `ScheduleTemplate.IconType.CALENDAR` 참조 실패

**검토된 방법**:
1. ✅ **직접 문자열 사용** (채택)
   - 장점: 간단하고 명확, 빌드 오류 없음
   - 단점: 타입 안전성 저하, 오타 가능성
   - 근거: iconType과 colorHex는 이미 String 타입으로 정의됨

2. ❌ Companion object 구조 변경
   - 장점: 타입 안전성 유지
   - 단점: 도메인 모델 구조 변경 필요, 영향 범위 큼
   - 근거: 현재 구조에서는 불필요한 복잡성 증가

3. ❌ import alias 사용
   - 시도했으나 nested object 문제 해결 안 됨

**결론**: 
- `iconType`과 `colorHex`는 `String` 타입이므로 직접 문자열 사용이 가장 직관적
- `ScheduleTemplate`의 Companion object는 참조용으로 유지 (문서화 목적)

---

### 2. Material Icons 선택

**문제**: `Icons.Default.*` 패키지에 일부 아이콘 부재

**선택 기준**:
1. **의미적 유사성**: 원래 의도와 가장 유사한 아이콘
2. **시각적 명확성**: 사용자가 이해하기 쉬운 아이콘
3. **보편성**: Material Design에서 널리 사용되는 아이콘

**결정 근거**:

| 원래 의도 | 선택한 아이콘 | 근거 |
|----------|--------------|------|
| Work | Place | 회사/학교는 위치 개념이 강함 |
| School | Star | 학습/중요도 표현 |
| CalendarToday | DateRange | 날짜 범위 선택 개념 유사 |
| Schedule | Settings | 일정 설정 의미 내포 |

**대안 검토**:
- BusinessCenter, MenuBook, AccessTime 등 시도했으나 존재하지 않음
- Home, KeyboardArrowRight, DateRange 등은 실제 존재 확인
