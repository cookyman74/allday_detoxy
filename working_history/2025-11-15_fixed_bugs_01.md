## 수정된 버그 목록

### 1. 일반 시간 스케쥴 비활성화 문제 (버그 9번 수정으로 인한 부작용)

**문제**: 버그 9번 수정으로 모든 스케쥴 그룹을 `isActive = false`로 생성하여, 위치기반이 아닌 일반 시간 스케쥴도 비활성화되어 작동하지 않음

**원인 분석**:
1. 버그 9번 수정에서 위치기반 스케쥴 그룹을 `isActive = false`로 생성하도록 변경
2. 하지만 일반 시간 스케쥴(어디서나 적용)도 같은 함수를 사용하여 모두 비활성화됨
3. 일반 시간 스케쥴은 즉시 활성화되어야 하는데 비활성화 상태로 생성됨

**수정 내용**:
1. `ScheduleGroupViewModel.createScheduleGroupWithTimeSlots()`에 `isLocationBased: Boolean = false` 파라미터 추가
2. `ScheduleGroupViewModel.createFromTemplate()`에도 `isLocationBased: Boolean = false` 파라미터 추가
3. `isActive` 설정 로직 변경:
   - 위치기반 스케쥴 (`isLocationBased = true`): `isActive = false` (위치 진입 시 활성화)
   - 일반 시간 스케쥴 (`isLocationBased = false`): `isActive = true` (즉시 활성화)
4. 모든 호출부 수정:
   - `locationInfo == null` (어디서나 적용): `isLocationBased = false` 전달
   - `locationInfo != null` (특정 위치에서만): `isLocationBased = true` 전달

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/presentation/viewmodel/ScheduleGroupViewModel.kt`
- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/ScheduleGroupScreen.kt`

- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/components/AddLocationAutoRunDialog.kt`

**검증 방법**:
1. **일반 시간 스케쥴 (어디서나 적용)**:
   - 위치 설정 없이 시간표 생성
   - 생성된 스케쥴 그룹이 `isActive = true`인지 확인
   - 즉시 알람이 등록되고 "다음 예약"에 표시되는지 확인
2. **위치기반 스케쥴 (특정 위치에서만)**:
   - 위치를 설정하고 시간표 생성
   - 생성된 스케쥴 그룹이 `isActive = false`인지 확인
   - 위치 진입 전에는 알람이 등록되지 않고 "다음 예약"에 표시되지 않는지 확인
