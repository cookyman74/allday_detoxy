#### 1.1 주요 기능

**정확 알람 권한 체크 (Android 12+)**:
```kotlin
fun canScheduleExactAlarms(): Boolean {
    return if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
        alarmManager.canScheduleExactAlarms()
    } else {
        true // Android 12 미만은 권한 불필요
    }
}
```
- StateFlow로 권한 상태 노출 (`_canScheduleExactAlarms`)
- UI에서 실시간으로 권한 변화 감지 가능

**알람 스케줄링 (Doze 모드 대응)**:
```kotlin
fun scheduleTimeBasedAutoRun(autoRun: TimeBasedAutoRun): Boolean {
    val nextTriggerTime = calculateNextTriggerTime(autoRun)
    
    if (canScheduleExactAlarms()) {
        // 정확 알람 (±2분 정확도)
        alarmManager.setExactAndAllowWhileIdle(
            AlarmManager.RTC_WAKEUP,
            nextTriggerTime,
            pendingIntent
        )
    } else {
        // 일반 알람 (±15분 정확도)
        alarmManager.setAndAllowWhileIdle(
            AlarmManager.RTC_WAKEUP,
            nextTriggerTime,
            pendingIntent
        )
    }
}
```
- `setExactAndAllowWhileIdle()`: 절전 모드에서도 정확히 실행
- Fallback: 권한 없을 시 `setAndAllowWhileIdle()` 사용

**요일별 다음 트리거 시각 계산**:
```kotlin
private fun calculateNextTriggerTime(autoRun: TimeBasedAutoRun): Long? {
    val enabledDays = parseEnabledDays(autoRun.enabledDays)
    
    // 오늘 또는 내일부터 최대 7일 검색
    for (daysToAdd in 0..6) {
        val checkCalendar = targetCalendar.clone() as Calendar
        checkCalendar.add(Calendar.DAY_OF_YEAR, daysToAdd)
        
        // 요일 확인
        val dayOfWeek = getDayOfWeekString(checkCalendar)
        if (enabledDays.contains(dayOfWeek)) {
            return checkCalendar.timeInMillis
        }
    }
    
    return null
}
```
- enabledDays JSON 파싱: `["MON","TUE","WED"]` → `Set<String>`
- 활성화된 요일 중 가장 가까운 시각 반환
- 과거 시각 스킵

**PendingIntent 생성 (Android 12+ 대응)**:
```kotlin
private fun createPendingIntent(autoRun: TimeBasedAutoRun): PendingIntent {
    val intent = Intent(context, AutoRunAlarmReceiver::class.java).apply {
        action = ACTION_AUTO_RUN_ALARM
        putExtra(EXTRA_AUTO_RUN_ID, autoRun.id)
        putExtra(EXTRA_DURATION_MINUTES, autoRun.durationMinutes)
        putExtra(EXTRA_PRESET_TYPE, autoRun.presetType)
        putExtra(EXTRA_LABEL, autoRun.label)
    }

    val requestCode = autoRun.id.hashCode() % 10000 + REQUEST_CODE_BASE
    
    return PendingIntent.getBroadcast(
        context,
        requestCode,
        intent,
        PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
    )
}
```
- FLAG_IMMUTABLE 필수 (Android 12+)
- requestCode: ID 해시로 고유값 생성

## 🔍 기술적 하이라이트

### 1. Doze 모드 대응

**문제**: Android 6.0+ Doze 모드에서 일반 알람이 지연됨  
**해결**: `setExactAndAllowWhileIdle()` 사용

```kotlin
alarmManager.setExactAndAllowWhileIdle(
    AlarmManager.RTC_WAKEUP,  // 기기 깨우기
    nextTriggerTime,
    pendingIntent
)
```

**효과**:
- 절전 모드에서도 ±2분 정확도 보장
- 사용자 경험 향상 (정확한 시간에 알림)

### 2. 권한 Fallback 전략

**정확 알람 권한 없음**:
```kotlin
if (canScheduleExactAlarms()) {
    alarmManager.setExactAndAllowWhileIdle()  // ±2분
} else {
    alarmManager.setAndAllowWhileIdle()       // ±15분
    Log.w(TAG, "Inexact alarm scheduled (no permission)")
}
```

**장점**:
- 권한 거부 시에도 기능 동작 (degraded mode)
- UI에서 경고 배너 표시 가능 (StateFlow 활용)
- 사용자에게 권한 재요청 유도

### 3. 요일별 알람 계산 로직

**enabledDays JSON 파싱**:
```kotlin
val enabledDays = parseEnabledDays("[\"MON\",\"TUE\",\"WED\"]")
// Result: setOf("MON", "TUE", "WED")
```

**다음 트리거 시각 계산**:
- 오늘부터 최대 7일 검색
- 활성화된 요일만 고려
- 과거 시각 스킵

**예시**:
- 오늘: 금요일 오후 3시
- 설정: 월/수/금 오전 9시
- 다음 트리거: 다음 주 월요일 오전 9시

### 4. PendingIntent 고유 RequestCode

```kotlin
val requestCode = autoRun.id.hashCode() % 10000 + REQUEST_CODE_BASE
```

**설계 이유**:
- autoRunId는 UUID (문자열) → hashCode로 Int 변환
- REQUEST_CODE_BASE (10000): 다른 PendingIntent와 충돌 방지
- % 10000: overflow 방지 (0~9999 범위)

```kotlin
private fun parseEnabledDays(enabledDaysJson: String): Set<String> {
    return try {
        val regex = Regex(""""(\w+)"""")
        regex.findAll(enabledDaysJson).map { it.groupValues[1] }.toSet()
    } catch (e: Exception) {
        emptySet()
    }

// 수정 후
private fun parseEnabledDays(enabledDaysJson: String): Set<String> {
    if (enabledDaysJson.isBlank() || enabledDaysJson == "[]") {
        Log.w(TAG, "⚠️ Empty enabledDays JSON")
        return emptySet()
    }
    
    return try {
        val regex = Regex(""""(\w+)"""")
        regex.findAll(enabledDaysJson)
            .map { it.groupValues[1].uppercase() } // 🆕 대소문자 정규화
            .filter { it in VALID_DAY_CODES }      // 🆕 유효성 검증
            .toSet()
    } catch (e: Exception) {
        Log.e(TAG, "❌ Failed to parse enabledDays: $enabledDaysJson", e)
        emptySet()
    }
}
```

**개선 사항**:
- ✅ 빈 문자열/빈 배열 체크

- `doWork()`: AlarmManager와 동일한 Intent를 BroadcastReceiver로 전달

```kotlin
@HiltWorker
class AutoRunWorker @AssistedInject constructor(
    @Assisted appContext: Context,
    @Assisted workerParams: WorkerParameters
) : CoroutineWorker(appContext, workerParams) {
    
    override suspend fun doWork(): Result {
        // Input Data에서 autoRun 정보 추출
        val autoRunId = inputData.getString(KEY_AUTO_RUN_ID)
        val durationMinutes = inputData.getInt(KEY_DURATION_MINUTES, 0)
        
        // BroadcastReceiver와 동일한 처리를 위해 Intent 생성
        val intent = Intent(applicationContext, AutoRunAlarmReceiver::class.java).apply {
            action = AutoRunAlarmManager.ACTION_AUTO_RUN_ALARM
            putExtra(AutoRunAlarmManager.EXTRA_AUTO_RUN_ID, autoRunId)
            putExtra(AutoRunAlarmManager.EXTRA_DURATION_MINUTES, durationMinutes)
            // ...
        }
        
        applicationContext.sendBroadcast(intent)
        return Result.success()
    }
}
```

```kotlin
fun scheduleTimeBasedAutoRun(autoRun: TimeBasedAutoRun): Boolean {
    // 다음 트리거 시각 계산
    val nextTriggerTime = calculateNextTriggerTime(autoRun)
    
    // AlarmManager로 스케줄링 시도
    val alarmSuccess = tryScheduleWithAlarmManager(autoRun, nextTriggerTime)
    
    if (!alarmSuccess) {
        // AlarmManager 실패 시 WorkManager로 Fallback
        Log.w(TAG, "⚠️ AlarmManager failed, falling back to WorkManager")
        return scheduleWithWorkManager(autoRun, nextTriggerTime)
    }
    
    return true
}
```

**2.3. WorkManager 스케줄링 메서드**:
```kotlin
private fun scheduleWithWorkManager(autoRun: TimeBasedAutoRun, nextTriggerTime: Long): Boolean {
    val delayMillis = (nextTriggerTime - System.currentTimeMillis()).coerceAtLeast(0)
    
    val inputData = Data.Builder()
        .putString(AutoRunWorker.KEY_AUTO_RUN_ID, autoRun.id)
        .putInt(AutoRunWorker.KEY_DURATION_MINUTES, autoRun.durationMinutes)
        .putString(AutoRunWorker.KEY_PRESET_TYPE, autoRun.presetType)
        .putString(AutoRunWorker.KEY_LABEL, autoRun.label)
        .build()
    
    val workRequest = OneTimeWorkRequestBuilder<AutoRunWorker>()
        .setInitialDelay(delayMillis, TimeUnit.MILLISECONDS)
        .setInputData(inputData)
        .build()
    
    val workName = "${AutoRunWorker.WORK_NAME_PREFIX}${autoRun.id}"
    workManager.enqueueUniqueWork(
        workName,
        androidx.work.ExistingWorkPolicy.REPLACE,
        workRequest
    )
    
    Log.i(TAG, "✅ WorkManager scheduled (±15분 오차)")
    return true
}
```

**2.4. 취소 메서드 업데이트**:

```kotlin
fun cancelTimeBasedAutoRun(autoRunId: String) {
    // AlarmManager 취소
    val pendingIntent = createPendingIntentById(autoRunId)
```

### 1. WorkManager Fallback 전략

**문제**: Android 12+ 정확 알람 권한이 없으면 알람이 실행되지 않음  
**해결**: 자동으로 WorkManager로 전환

**장점**:
- ✅ 사용자 경험 유지 (권한 없어도 기능 동작)
- ✅ 투명한 전환 (로그로 상태 확인 가능)
- ✅ UI에서 현재 스케줄러 타입 표시 가능

**단점**:
- ⚠️ 정확도 저하 (±2분 → ±15분)
- ⚠️ 사용자에게 권한 요청 유도 필요
