### 1. 위치기반 스케쥴 시간 추가/편집 시 위치 정보 유지 문제

**문제**: 위치기반 스케쥴을 등록후 해당 스케쥴에 시간을 추가 또는 편집하면 위치와 상관없이 시간 스케쥴로 가동되는 문제

**원인**: 
- `AddTimeBasedAutoRunDialog`에서 시간을 추가/편집할 때 `scheduleGroupId`를 변경할 수 있어서, 위치기반 스케쥴의 경우 위치 정보가 유지되지 않음

**수정 내용**:
1. `AddTimeBasedAutoRunDialog`에 `isLocationBased` 파라미터 추가
2. 위치기반 스케쥴인 경우:
   - 시간표 연결 섹션에 안내 메시지 표시
   - 독립 실행 옵션 비활성화
   - 시간표 선택 라디오 버튼 비활성화
   - 저장 시 기존 `scheduleGroupId`와 `isIndependent` 값 유지
3. `TimeBasedAutoRunScreen`에서 `scheduleGroupId`가 `linkedScheduleGroupId`로 연결된 `LocationBasedAutoRun`이 있는지 확인하여 `isLocationBased` 전달

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/components/AddTimeBasedAutoRunDialog.kt`
- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/TimeBasedAutoRunScreen.kt`

### 2. 위치기반 스케쥴 생성 시 시간 방법 선택 기본값 설정

**문제**: 위치기반 스케쥴을 등록하는 과정에서 '시간표 만들기'과정에서 '시간 방법 선택'항목을 템플릿이 default으로 설정되어야 하는데 커스텀으로 설정되어 있음

**원인**:
- `ScheduleGroupScreen`에서 `ScheduleCreationDialog`를 호출할 때 `initialMode = CreationMode.CUSTOM`으로 설정되어 있음
- `ScheduleCreationDialog`에서 위치기반 스케쥴로 진행할 때 템플릿 모드로 자동 전환하지 않음

**수정 내용**:
1. `ScheduleGroupScreen`에서 `initialMode = CreationMode.TEMPLATE`으로 변경
2. `ScheduleCreationDialog`에서 위치 검색 단계를 완료하고 `SCHEDULE_SETUP` 단계로 이동할 때, `mode`가 `CUSTOM`이면 자동으로 `TEMPLATE`으로 변경

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/ScheduleGroupScreen.kt`
- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/components/ScheduleCreationDialog.kt`

### 3. 권한 상태 변경 후 화면 복귀 시 권한 상태 업데이트 문제

**문제**: 권한 상태를 변경하고 다시 해당 앱 화면으로 돌아오면 여전히 권한설정이 변경되지 않은 것으로 보여진다. 하지만 앱을 재실행 (껐다 켜기)하면 정상적으로 보인다.

**원인**:
- `DetoxyControlSettingsScreen`에서 화면 재진입 시 권한 상태를 업데이트하지 않음
- `PermissionCheckScreen`에서는 `ON_RESUME` 이벤트를 처리하고 있지만, 다른 권한 관련 화면에서는 처리하지 않음

**수정 내용**:
1. `DetoxyControlSettingsScreen`에 `DisposableEffect`를 사용하여 `ON_RESUME` 이벤트 처리 추가
2. 화면 재진입 시 `viewModel.updatePermissionStates()` 호출하여 권한 상태 업데이트

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/presentation/ui/settings/focus/DetoxyControlSettingsScreen.kt`

### 4. 접근성 서비스 Hilt 의존성 주입 개선

**문제**: `FocusAccessibilityService`에서 Hilt EntryPoint를 사용한 의존성 주입이 실패하는 경우가 발생

**원인**:
- `onServiceConnected()`에서 Hilt 초기화가 완료되기 전에 EntryPoint에 접근하려고 시도
- 동기적으로 처리하여 Hilt 초기화 대기 시간이 부족함

**수정 내용**:
1. Hilt 의존성 주입을 비동기로 처리하도록 변경 (`serviceScope.launch` 사용)
2. Hilt 초기화가 완료될 때까지 재시도 로직 추가:
   - 최대 30회 재시도 (약 3초)
   - 100ms 간격으로 재시도
   - 성공 시 즉시 종료
3. `super.onServiceConnected()` 호출 순서 변경:
   - 초기화 작업을 시작한 후 즉시 호출하여 시스템에 서비스 연결 성공 알림
   - 비동기 초기화는 백그라운드에서 계속 진행
4. 예외 처리 강화 및 로깅 개선

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/service/accessibility/FocusAccessibilityService.kt`

### 6. 위치기반 스케쥴 시간 추가 시 scheduleGroupId 미설정 문제

**문제**: 위치기반 스케쥴에 시간을 추가하거나 수정하면 시간 스케쥴로 작동되는 것으로 보임 (위치와 상관없이 작동)

**원인 분석**:
1. `AddTimeBasedAutoRunDialog`에서 시간을 추가할 때 (existingAutoRun이 null인 경우) 위치기반 스케쥴인 경우에도 `scheduleGroupId`가 제대로 설정되지 않음
2. 기존 로직: `isLocationBased && existingAutoRun != null` 조건으로 편집 시에만 기존 값 유지
3. 새로 추가할 때는 `selectedScheduleGroupId`를 사용하는데, 위치기반 스케쥴인 경우 `initialScheduleGroupId`를 사용해야 함
4. `isIndependent`도 위치기반 스케쥴인 경우 `false`로 설정해야 함 (그룹에 종속되어야 함)

**수정 내용**:
1. `AddTimeBasedAutoRunDialog`의 저장 로직 수정:
   - 위치기반 스케쥴인 경우 (편집/추가 모두):
     - `scheduleGroupId`: 기존 값이 있으면 유지, 없으면 `initialScheduleGroupId` 사용
     - `isIndependent`: 기존 값이 있으면 유지, 없으면 `false`로 설정 (그룹에 종속)
   - 일반 스케쥴인 경우: 기존 로직 유지

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/components/AddTimeBasedAutoRunDialog.kt`

**검증 방법**:
1. 위치기반 스케쥴 생성 (예: "회사" 위치)
2. 해당 스케쥴 그룹의 시간표 관리 화면으로 이동
3. 시간대 추가 다이얼로그 열기
4. 시간대 정보 입력 후 저장
5. 저장된 시간대가 해당 스케쥴 그룹에 연결되어 있고, `isIndependent = false`로 설정되어 있는지 확인
6. 위치 이탈 시 시간대가 비활성화되는지 확인

### 7. 위치기반 스케쥴 시간 추가 시 알람 등록 문제

**문제**: 위치기반 스케쥴에 시간을 추가하면 위치에 진입하지 않았음에도 '다음 예약'이 설정되고 알람이 등록되어 발동될 것으로 보임

**원인 분석**:
1. `AutoRunAlarmManager.scheduleTimeBasedAutoRun()`에서 알람을 등록할 때 그룹 활성화 상태를 확인하지 않음
2. 위치기반 스케쥴의 경우 `scheduleGroupId`가 있고 `isIndependent = false`인데, 그룹이 비활성화 상태일 때도 알람이 등록됨
3. 알람 트리거 시에는 `AutoRunAlarmReceiver`에서 그룹 활성화 상태를 확인하지만, 알람 등록 시에는 확인하지 않아 "다음 예약"에 표시됨

**수정 내용**:
1. `AutoRunAlarmManager`에 `ScheduleGroupDao` 주입 추가
2. `scheduleTimeBasedAutoRun()` 메서드에서 알람 등록 전에 그룹 활성화 상태 확인:
   - `scheduleGroupId`가 있고 `isIndependent = false`인 경우
   - 해당 그룹이 활성화되어 있는지 확인
   - 비활성화되어 있으면 알람 등록하지 않음 (false 반환)

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/core/manager/AutoRunAlarmManager.kt`

**검증 방법**:
1. 위치기반 스케쥴 생성 (예: "회사" 위치)
2. 해당 스케쥴 그룹의 시간표 관리 화면으로 이동
3. 시간대 추가 (예: 18:00 - 25분)
4. 저장 후 스케쥴 화면 확인
5. "다음 예약"에 표시되지 않고, 위치에 진입하기 전까지 알람이 등록되지 않는지 확인
6. 위치에 진입하면 그룹이 활성화되고 알람이 등록되는지 확인

### 8. 위치기반 스케쥴 시간 추가 시 시간 기반으로 등록되는 문제 (심각)

**문제**: 위치기반 스케쥴에 시간을 추가하거나 수정하면 위치에 진입하지 않았음에도 "다음 예약"이 활성화되고 실제로 트리거되어 실행됨. 위치기반 스케쥴이 시간 기반 스케쥴로 등록되는 것으로 보임.

**원인 분석**:
1. `TimeBasedAutoRunScreen`에서 `isLocationBasedState`를 확인하는 로직이 `LaunchedEffect`로 비동기 실행됨
2. 다이얼로그가 열릴 때 `isLocationBasedState`가 아직 false일 수 있음
3. `isLocationBased` 파라미터가 false로 전달되어 `scheduleGroupId`가 null이거나 `isIndependent`가 true로 설정될 수 있음
4. 결과적으로 위치기반 스케쥴이 시간 기반 스케쥴로 등록되어 위치 진입 전에도 알람이 등록되고 실행됨

**수정 내용**:
1. `AddTimeBasedAutoRunDialog`에 `actualIsLocationBased` 계산 로직 추가:
   - `isLocationBased` 파라미터가 true이거나
   - `initialScheduleGroupId`가 null이 아니거나
   - `existingAutoRun?.scheduleGroupId`가 null이 아니고 `isIndependent`가 false인 경우
   - → 위치기반으로 간주
2. 저장 시 `actualIsLocationBased`를 사용하여 `scheduleGroupId`와 `isIndependent` 설정
3. 디버깅 로그 추가하여 실제 저장되는 값 확인 가능하도록 개선

**수정 파일**:

- `app/src/main/java/com/allday/detoxy/presentation/viewmodel/TimeBasedAutoRunViewModel.kt` (로그 추가)
- `app/src/main/java/com/allday/detoxy/core/manager/AutoRunAlarmManager.kt` (로그 추가)
- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/TimeBasedAutoRunScreen.kt` (로그 추가)

**검증 방법**:
1. 위치기반 스케쥴 생성 (예: "회사" 위치)
2. 해당 스케쥴 그룹의 시간표 관리 화면으로 이동
