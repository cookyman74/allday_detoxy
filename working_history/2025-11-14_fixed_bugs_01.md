### 1. 위치기반 스케쥴 시간 추가/편집 시 위치 정보 유지 문제

**문제**: 위치기반 스케쥴을 등록후 해당 스케쥴에 시간을 추가 또는 편집하면 위치와 상관없이 시간 스케쥴로 가동되는 문제

**원인**: 
- `AddTimeBasedAutoRunDialog`에서 시간을 추가/편집할 때 `scheduleGroupId`를 변경할 수 있어서, 위치기반 스케쥴의 경우 위치 정보가 유지되지 않음

**수정 내용**:
1. `AddTimeBasedAutoRunDialog`에 `isLocationBased` 파라미터 추가
2. 위치기반 스케쥴인 경우:
   - 시간표 연결 섹션에 안내 메시지 표시
   - 독립 실행 옵션 비활성화
   - 시간표 선택 라디오 버튼 비활성화
   - 저장 시 기존 `scheduleGroupId`와 `isIndependent` 값 유지
3. `TimeBasedAutoRunScreen`에서 `scheduleGroupId`가 `linkedScheduleGroupId`로 연결된 `LocationBasedAutoRun`이 있는지 확인하여 `isLocationBased` 전달

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/components/AddTimeBasedAutoRunDialog.kt`
- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/TimeBasedAutoRunScreen.kt`

### 2. 위치기반 스케쥴 생성 시 시간 방법 선택 기본값 설정

**문제**: 위치기반 스케쥴을 등록하는 과정에서 '시간표 만들기'과정에서 '시간 방법 선택'항목을 템플릿이 default으로 설정되어야 하는데 커스텀으로 설정되어 있음

**원인**:
- `ScheduleGroupScreen`에서 `ScheduleCreationDialog`를 호출할 때 `initialMode = CreationMode.CUSTOM`으로 설정되어 있음
- `ScheduleCreationDialog`에서 위치기반 스케쥴로 진행할 때 템플릿 모드로 자동 전환하지 않음

**수정 내용**:
1. `ScheduleGroupScreen`에서 `initialMode = CreationMode.TEMPLATE`으로 변경
2. `ScheduleCreationDialog`에서 위치 검색 단계를 완료하고 `SCHEDULE_SETUP` 단계로 이동할 때, `mode`가 `CUSTOM`이면 자동으로 `TEMPLATE`으로 변경

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/ScheduleGroupScreen.kt`
- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/components/ScheduleCreationDialog.kt`

### 3. 권한 상태 변경 후 화면 복귀 시 권한 상태 업데이트 문제

**문제**: 권한 상태를 변경하고 다시 해당 앱 화면으로 돌아오면 여전히 권한설정이 변경되지 않은 것으로 보여진다. 하지만 앱을 재실행 (껐다 켜기)하면 정상적으로 보인다.

**원인**:
- `DetoxyControlSettingsScreen`에서 화면 재진입 시 권한 상태를 업데이트하지 않음
- `PermissionCheckScreen`에서는 `ON_RESUME` 이벤트를 처리하고 있지만, 다른 권한 관련 화면에서는 처리하지 않음

**수정 내용**:
1. `DetoxyControlSettingsScreen`에 `DisposableEffect`를 사용하여 `ON_RESUME` 이벤트 처리 추가
2. 화면 재진입 시 `viewModel.updatePermissionStates()` 호출하여 권한 상태 업데이트

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/presentation/ui/settings/focus/DetoxyControlSettingsScreen.kt`

### 4. 접근성 서비스 Hilt 의존성 주입 개선

**문제**: `FocusAccessibilityService`에서 Hilt EntryPoint를 사용한 의존성 주입이 실패하는 경우가 발생

**원인**:
- `onServiceConnected()`에서 Hilt 초기화가 완료되기 전에 EntryPoint에 접근하려고 시도
- 동기적으로 처리하여 Hilt 초기화 대기 시간이 부족함

**수정 내용**:
1. Hilt 의존성 주입을 비동기로 처리하도록 변경 (`serviceScope.launch` 사용)
2. Hilt 초기화가 완료될 때까지 재시도 로직 추가:
   - 최대 30회 재시도 (약 3초)
   - 100ms 간격으로 재시도
   - 성공 시 즉시 종료
3. `super.onServiceConnected()` 호출 순서 변경:
   - 초기화 작업을 시작한 후 즉시 호출하여 시스템에 서비스 연결 성공 알림
   - 비동기 초기화는 백그라운드에서 계속 진행
4. 예외 처리 강화 및 로깅 개선

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/service/accessibility/FocusAccessibilityService.kt`

### 5. 빌드 오류: LocalLifecycleOwner import 경로 수정

**문제**: 빌드 시 `DetoxyControlSettingsScreen.kt`에서 `LocalLifecycleOwner`를 찾을 수 없다는 컴파일 오류 발생
```
e: Unresolved reference: LocalLifecycleOwner
```

**원인**:
- 잘못된 import 경로 사용: `androidx.lifecycle.compose.LocalLifecycleOwner`
- 올바른 import 경로: `androidx.compose.ui.platform.LocalLifecycleOwner`

**수정 내용**:
1. `DetoxyControlSettingsScreen.kt`의 import 문 수정
   - 변경 전: `import androidx.lifecycle.compose.LocalLifecycleOwner`
   - 변경 후: `import androidx.compose.ui.platform.LocalLifecycleOwner`

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/presentation/ui/settings/focus/DetoxyControlSettingsScreen.kt`

**검증**:
- `./gradlew compileDebugKotlin` 실행하여 빌드 성공 확인

## 검증 방법

### 버그 1 검증
1. 위치기반 스케쥴을 생성
2. 해당 스케쥴 그룹의 시간표 관리 화면으로 이동
3. 시간대 추가 또는 편집 다이얼로그 열기
4. 시간표 연결 섹션에 안내 메시지가 표시되고, 독립 실행 옵션과 시간표 선택이 비활성화되어 있는지 확인
5. 시간대를 수정하고 저장
6. 위치기반 스케쥴이 정상적으로 유지되는지 확인

### 버그 2 검증
1. 스케줄 그룹 화면에서 새 그룹 만들기 클릭
2. 위치 설정에서 "특정 위치에서만" 선택
3. 위치 검색 및 반경 설정 완료
4. 시간표 만들기 단계로 이동
5. "시간 방법 선택" 항목이 템플릿으로 기본 선택되어 있는지 확인

### 버그 3 검증
1. 디톡시 제어 설정 화면으로 이동
2. 권한 상태 확인
3. 설정 앱으로 이동하여 권한 변경 (예: 접근성 서비스 비활성화)
4. 앱으로 돌아오기
5. 권한 상태가 즉시 업데이트되어 표시되는지 확인
