## 🐛 타이머 버그 수정 (추가 작업)

### 문제 상황
**발견 일시**: 2025-10-20  
**문제점**: 화면 슬립 모드(화면 끄기) 진입 시 타이머가 정상 작동하지 않음
- ViewModel의 코루틴이 화면 잠금 시 중단되어 타이머가 멈추는 현상
- Foreground Service로 실행 중인 LockOverlayService는 정상 작동
- 타이머 카운트다운이 멈춰 정확한 집중 시간 측정 불가

### 해결 방법 선택
**선택한 방법**: Option 1 - Foreground Service에서 타이머 관리

**이유**:
1. ✅ **안정성**: 시스템에 의한 타이머 중단 방지 (START_STICKY)

### 구현 내역

#### 1. FocusTimerService.kt 생성 (신규 파일, 303줄)
**파일**: `app/src/main/java/com/allday/detoxy/service/timer/FocusTimerService.kt`

**주요 기능**:
- Foreground Service로 타이머 실행
- StateFlow를 통한 상태 공유 (state, remainingSeconds, totalSeconds)
- 1초 간격 타이머 업데이트 (Dispatchers.Default)
- 타이머 완료 브로드캐스트 전송
- 알림 바 실시간 업데이트 (10초마다)

**Public API**:
```kotlin
// Static StateFlow (어디서든 접근 가능)
val state: StateFlow<FocusState>
val remainingSeconds: StateFlow<Int>
val totalSeconds: StateFlow<Int>

// Service 제어
fun startTimer(context: Context, durationMinutes: Int, sessionId: String)
fun stopTimer(context: Context)
fun giveUpTimer(context: Context)
```

**브로드캐스트 액션**:
- `ACTION_TIMER_FINISHED`: 타이머 완료 시 전송
- `EXTRA_SUCCESS`: 성공(true) / 포기(false)
- `EXTRA_SESSION_ID`: 세션 ID

#### 2. TimerViewModel.kt 리팩토링 (수정, 345줄)
**파일**: `app/src/main/java/com/allday/detoxy/presentation/viewmodel/TimerViewModel.kt`

**변경 사항**:
- `FocusTimer` 제거 → `FocusTimerService` 사용
- StateFlow를 Service에서 가져옴 (직접 관리 제거)
- BroadcastReceiver 등록 (타이머 완료 이벤트 수신)
- `startTimer()`: Service 시작 호출
- `giveUpTimer()`: Service 포기 호출
- `resetTimer()`: Service 중지 호출
- `onCleared()`: BroadcastReceiver 해제

**주요 코드**:
```kotlin
// Service StateFlow 사용
val timerState: StateFlow<FocusState> = FocusTimerService.state
val remainingSeconds: StateFlow<Int> = FocusTimerService.remainingSeconds
val totalSeconds: StateFlow<Int> = FocusTimerService.totalSeconds

// BroadcastReceiver 등록 (init)
val filter = IntentFilter(FocusTimerService.ACTION_TIMER_FINISHED)
application.registerReceiver(timerFinishedReceiver, filter)

// Service 시작

```
