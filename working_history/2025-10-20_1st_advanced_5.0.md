## 🐛 타이머 버그 수정 (추가 작업)

### 문제 상황
**발견 일시**: 2025-10-20  
**문제점**: 화면 슬립 모드(화면 끄기) 진입 시 타이머가 정상 작동하지 않음
- ViewModel의 코루틴이 화면 잠금 시 중단되어 타이머가 멈추는 현상
- Foreground Service로 실행 중인 LockOverlayService는 정상 작동
- 타이머 카운트다운이 멈춰 정확한 집중 시간 측정 불가

### 해결 방법 선택
**선택한 방법**: Option 1 - Foreground Service에서 타이머 관리

## 🐛 리포트 '총 집중 시간' 0 표시 버그 수정 (추가 작업 3)

### 문제 상황
**발견 일시**: 2025-10-20  
**문제점**: 리포트 페이지의 '총 집중 시간'이 계속 0으로 표시됨
- 집중 세션을 완료해도 '총 집중 시간'이 0분으로 표시
- 다른 통계(성공 세션, 스트릭 등)는 정상적으로 표시됨

### 원인 분석

**ReportUiState.getTotalFocusMinutes() 분석**:
```kotlin
fun getTotalFocusMinutes(): Int = todaySessions
    .filter { it.success }
    .sumOf { it.durationMinutes }  // ← 문제!
```

**문제점**:
- `durationMinutes`는 세션 시작 시 설정한 **목표 시간** (예: 25분, 45분)
- 실제로 집중한 시간이 아님
- 타이머 완료 시 `durationMinutes`가 업데이트되지 않음
- **실제 집중 시간 = `endTime - startTime`**으로 계산해야 함

**예시**:
```
세션 시작: startTime = 1697800000000, durationMinutes = 25
세션 완료: endTime = 1697801500000, success = true
실제 집중 시간 = (1697801500000 - 1697800000000) / 1000 / 60 = 25분

하지만 기존 로직은 durationMinutes (목표 시간)만 보고 있었음
```

### 해결 방법

**실제 집중 시간을 계산하도록 수정**:
```kotlin
fun getTotalFocusMinutes(): Int = todaySessions
    .filter { it.endTime != null }  // 종료된 세션만
    .sumOf { 
        // 실제 집중 시간 = (종료 시간 - 시작 시간) / 1000ms / 60s
        val actualMinutes = ((it.endTime!! - it.startTime) / 1000 / 60).toInt()
        actualMinutes
    }
```

**변경 사항**:
1. `it.success` 필터 대신 `it.endTime != null` 사용
   - 성공/실패 여부와 무관하게 실제로 집중한 시간 모두 계산
   - 포기한 세션도 실제 집중 시간은 포함
2. `durationMinutes` (목표) 대신 `endTime - startTime` (실제) 사용
   - 정확한 집중 시간 계산
