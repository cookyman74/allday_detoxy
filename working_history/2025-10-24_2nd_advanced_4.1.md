## 🏗️ 아키텍처

### 1. 화면 분기 로직 (3단계)

```kotlin
if (!playServicesAvailable) {
    // 1단계: Play Services 미지원 → 경고만
    PlayServicesWarningCard()
} else if (!hasFullLocationPermission) {
    // 2단계: 권한 없음 → 권한 안내만
    LocationPermissionCard()
} else {
    // 3단계: 모든 조건 충족 → 위치 리스트
    if (locations.isEmpty()) {
        EmptyLocationState()
    } else {
        LocationBasedAutoRunCard() // 리스트
        LocationBatteryImpactCard() // 배터리 안내
    }
}
```

### 2. 에러 처리 시스템

```kotlin
sealed class LocationError {
    data class GeofenceError(val message: String)
    data class PermissionError(val message: String)
    data class DatabaseError(val message: String)
    data class UnknownError(val message: String)
}

// ViewModel에서 에러 상태 관리
private val _errorState = MutableStateFlow<LocationError?>(null)
val errorState: StateFlow<LocationError?> = _errorState.asStateFlow()

// UI에서 Snackbar로 에러 표시
LaunchedEffect(errorState) {
    errorState?.let { error ->
        snackbarHostState.showSnackbar("에러: ${error.message}")
        viewModel.clearError()
    }
}
```

### 3. 트랜잭션 로직 (데이터 일관성 보장)

```kotlin
// addLocation: Geofence 먼저 → DB 저장
fun addLocation(location: LocationBasedAutoRun) {
    // 1. Geofence 등록 먼저 시도
    if (location.isEnabled) {
        val result = geofenceManager.addGeofence(location)
        if (result.isFailure) {
            _errorState.value = LocationError.GeofenceError(...)
            return@launch  // 실패 시 DB 저장 안 함
        }
    }
    
    // 2. Geofence 성공 후 DB 저장
    repository.insert(location)
    
    // 3. DB 저장 실패 시 Geofence 롤백
    catch (e: Exception) {
        if (location.isEnabled) {
            geofenceManager.removeGeofence(location.id)
        }
        _errorState.value = LocationError.DatabaseError(...)
    }
}
```

## 🔧 주요 기능

### 1. 권한 관리

- **Play Services 체크**: `GoogleApiAvailability.isGooglePlayServicesAvailable()`
- **위치 권한**: `ACCESS_FINE_LOCATION`, `ACCESS_BACKGROUND_LOCATION`
- **자동 재확인**: `DisposableEffect` + `LifecycleObserver`로 onResume 시 권한 재확인
- **단계별 요청**: 정확한 위치 → 백그라운드 위치 순서

### 2. 위치 추가/편집

- **2단계 플로우**: 위치 검색 → 상세 설정
- **주소 검색**: `GeocoderUtils`로 주소 → 좌표 변환
- **설정 옵션**: 라벨, 반경(50/100/200/500m), 타이머, 프리셋, 체류 시간, 도착 후 확인
- **편집 모드**: 기존 위치 수정 시 설정 단계부터 시작

### 3. 배터리 영향 투명성

- **예상 소모량**: 활성화된 위치 개수에 따라 2~7%/일
- **최적화 팁**: 2개 이하 유지, 반경 100m 이상, 체류 시간 1분 이상
- **실시간 표시**: 활성화된 개수에 따른 동적 안내

### 4. 개수 제한 관리

- **최대 5개**: `AutoRunGeofenceManager.MAX_GEOFENCES`
- **활성화 기준**: 비활성화된 위치는 개수 제한에 포함 안 됨
- **FAB 표시**: 활성화된 개수가 5개 미만일 때만 표시

## 🐛 해결된 이슈

### 1. 컴파일 오류
- **문제**: `return@LazyColumn` 사용 (LazyColumn DSL에서 불가)
- **해결**: else-if 구조로 3단계 분기 명확화

### 2. 에러 처리 부재
- **문제**: Geofence 등록 실패 시 사용자 피드백 없음
- **해결**: `LocationError` sealed class + `errorState` StateFlow + Snackbar

### 3. 데이터 불일치 위험
- **문제**: DB 저장 → Geofence 등록 순서로 불일치 발생 가능
- **해결**: Geofence 먼저 → DB 저장 순서로 변경, 실패 시 자동 롤백

### 4. 권한 재확인 누락
- **문제**: 설정 화면에서 돌아올 때 권한 상태 갱신 안 됨
- **해결**: `DisposableEffect` + `LifecycleObserver`로 onResume 시 자동 재확인

### 5. 개수 제한 로직 불일치
- **문제**: Screen(전체 개수) vs GeofenceManager(활성화 개수) 로직 불일치
- **해결**: 활성화된 개수 기준으로 통일
