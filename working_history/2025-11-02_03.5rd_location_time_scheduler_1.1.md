### 1.4 ScheduleGroupViewModel 확장 (Day 4) ✅

**파일**: `app/src/main/java/com/allday/detoxy/presentation/viewmodel/ScheduleGroupViewModel.kt`

#### 1. 의존성 추가
```kotlin
@HiltViewModel
class ScheduleGroupViewModel @Inject constructor(
    private val repository: ScheduleGroupRepository,
    private val scheduleManager: ScheduleGroupManager,
    private val timeBasedRepository: TimeBasedAutoRunRepository  // 🆕 추가
) : ViewModel()
```

#### 2. createScheduleGroupWithTimeSlots() 메서드 추가

**동작 방식**:
1. ScheduleGroup 생성
2. 각 TimeSlot에 대해 TimeBasedAutoRun 생성
3. TimeBasedAutoRun을 ScheduleGroup에 연결 (scheduleGroupId 설정)

**핵심 로직**:
```kotlin
timeSlots.forEach { slot ->
    val autoRun = TimeBasedAutoRun(
        hour = slot.startHour,
        minute = slot.startMinute,
        durationMinutes = slot.durationMinutes,
        presetType = slot.presetType,
        enabledDays = formatEnabledDays(slot.enabledDays),  // List<DayOfWeek> → JSON
        scheduleGroupId = scheduleGroup.id,
        isIndependent = false,  // 그룹에 종속
        isEnabled = true
    )
    timeBasedRepository.insert(autoRun)
}
```

#### 3. formatEnabledDays() 유틸리티 메서드

**기능**: List<DayOfWeek> → JSON 문자열 변환

**예시**:
```kotlin
listOf(DayOfWeek.MONDAY, DayOfWeek.TUESDAY, ..., DayOfWeek.FRIDAY)
→ "[\"MON\",\"TUE\",\"WED\",\"THU\",\"FRI\"]"
```

**코드 통계**: +70줄

### 1.5 AddLocationAutoRunDialog 통합 (Day 5) ✅

**파일**: `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/components/AddLocationAutoRunDialog.kt`

**변경 사항**:
```kotlin
// Before (v0.8)
QuickCreateScheduleDialog(
    onConfirm = { scheduleName ->
        val newGroupId = scheduleViewModel.createScheduleGroup(scheduleName, null)
    }
)

// After (v0.9)
QuickCreateScheduleDialog(
    onConfirm = { scheduleName, mode, data ->
        val newGroupId = when (mode) {
            CreationMode.TEMPLATE -> {
                scheduleViewModel.createScheduleGroup(scheduleName, null)  // Placeholder
            }
            CreationMode.CUSTOM -> {
                @Suppress("UNCHECKED_CAST")
                val timeSlots = data as List<TimeSlot>
                scheduleViewModel.createScheduleGroupWithTimeSlots(
                    name = scheduleName,
                    description = null,
                    timeSlots = timeSlots
                )
            }
        }
    }
)
```

**설명**:
- CreationMode에 따라 분기 처리
- 커스텀 모드: 시간대 포함 생성
- 템플릿 모드: Phase 2에서 구현 예정 (현재는 Placeholder)

## 기술적 의사결정

### 1. TimeSlot을 Domain 모델로 분리

**결정**: UI와 Entity 사이의 중간 데이터 모델로 TimeSlot 도입

**근거**:
- **UI 레이어**: 사용자 입력을 TimeSlot으로 수집
- **Domain 레이어**: TimeSlot을 TimeBasedAutoRun으로 변환
- **장점**: UI와 Data 레이어 분리, 재사용성 향상

### 2. enabledDays JSON 문자열 변환

**결정**: ViewModel에서 List<DayOfWeek> → JSON 문자열 변환

**근거**:
- TimeBasedAutoRun은 enabledDays를 JSON 문자열로 저장
- 변환 로직을 ViewModel에 두어 UI는 Domain 모델(TimeSlot)만 사용
- 유지보수성: 변환 로직 중앙화

### 3. CreationMode 열거형 도입

**결정**: 템플릿과 커스텀 모드를 열거형으로 구분

**근거**:
- 타입 안전성: Any 타입 대신 sealed class 고려했으나 단순성 우선
- 확장성: Phase 2에서 TEMPLATE 모드 추가 용이
- 가독성: when 표현식으로 명확한 분기

### 4. Phase 2 준비: TEMPLATE 모드 비활성화

**결정**: TEMPLATE 모드를 UI에 표시하되 비활성화

**근거**:
- 사용자에게 향후 기능 안내
- UI 구조를 미리 완성하여 Phase 2 작업 최소화
- RadioButton의 enabled 파라미터로 쉽게 제어
