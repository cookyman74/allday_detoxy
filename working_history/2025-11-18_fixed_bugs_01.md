## 수정된 버그 목록

### 1. 위치기반 스케줄 등록 시 자동 활성화 설정 비활성화 문제

**문제**: 위치기반 스케줄을 등록하면 "자동 활성화 설정" 부분의 "진입 시 시간표 활성화"와 "이탈 시 시간표 비활성화" 스위치가 항상 비활성화 상태로 되어 있어 설정을 변경할 수 없음. 또한 수정 기능을 통해서도 활성화 후 저장해도 해당 정보가 저장되지 않음.

**증상**:
- 위치기반 스케줄 등록 시 자동 활성화 설정 스위치가 비활성화됨
- 설정을 변경해도 저장되지 않음
- 위치기반 스케줄이 정상 작동하지 않음

**원인 분석**:
1. `LocationEditDialog.kt`에서 "진입 시 시간표 활성화"와 "이탈 시 시간표 비활성화" 스위치의 `enabled` 속성이 `isEnabled`에 의존
2. Geofence 등록 실패 시 `LocationBasedAutoRunViewModel`에서 `isEnabled = false`로 설정
3. `isEnabled = false`이면 스위치가 비활성화되어 사용자가 변경할 수 없음
4. Geofence 실패 시 `activateScheduleOnEnter`와 `deactivateScheduleOnExit`를 강제로 `false`로 설정하여 사용자 설정이 무시됨

**수정 내용**:
1. **`LocationEditDialog.kt` 수정**:
   - "진입 시 시간표 활성화" 스위치의 `enabled` 조건을 `isEnabled`에서 `location.linkedScheduleGroupId != null`로 변경
   - "이탈 시 시간표 비활성화" 스위치의 `enabled` 조건을 `isEnabled`에서 `location.linkedScheduleGroupId != null`로 변경
   - 이제 `linkedScheduleGroupId`가 있으면 `isEnabled`와 관계없이 스위치를 변경할 수 있음

2. **`LocationBasedAutoRunViewModel.kt` 수정**:
   - `addLocation()` 메서드: Geofence 실패 시 `activateScheduleOnEnter`와 `deactivateScheduleOnExit`를 `false`로 강제 설정하지 않도록 수정
   - `updateLocation()` 메서드: Geofence 실패 시 `activateScheduleOnEnter`와 `deactivateScheduleOnExit`를 `false`로 강제 설정하지 않도록 수정
   - 사용자가 설정한 값을 유지하여, 나중에 Geofence가 등록되면 작동할 수 있도록 함

**수정 파일**:
- `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/components/LocationEditDialog.kt`
- `app/src/main/java/com/allday/detoxy/presentation/viewmodel/LocationBasedAutoRunViewModel.kt`

**검증 방법**:
1. **위치기반 스케줄 등록**:
   - 위치를 설정하고 시간표 생성
   - 위치 정보 수정 다이얼로그 열기
   - "위치 기반 자동 실행" 토글을 켜기
   - "진입 시 시간표 활성화"와 "이탈 시 시간표 비활성화" 스위치가 활성화되어 변경 가능한지 확인
   - 스위치를 켜고 저장
   - 다시 다이얼로그를 열어 설정이 유지되는지 확인

2. **Geofence 등록 실패 시나리오**:
   - 위치 권한이 없는 상태에서 위치기반 스케줄 생성
   - 위치 정보 수정 다이얼로그 열기
   - "진입 시 시간표 활성화"와 "이탈 시 시간표 비활성화" 스위치를 켜고 저장
   - 다시 다이얼로그를 열어 설정이 유지되는지 확인 (Geofence 실패해도 설정값은 보존)

3. **위치기반 스케줄 정상 작동 확인**:
   - 위치 권한을 허용하고 Geofence 등록 성공
   - 위치 진입 시 연결된 시간표가 활성화되는지 확인
   - 위치 이탈 시 연결된 시간표가 비활성화되는지 확인
