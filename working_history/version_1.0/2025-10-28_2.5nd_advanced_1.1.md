## 1. NextAutoRunCalculator 클래스 설계 및 구현

### 1.1 작업 개요
- **목표**: 다음 예정 자동 실행을 계산하는 도메인 로직 구현
- **참조 문서**: 
  - `docs/02.5_autosetting_todolist.md` §1.1.1
  - `app/src/main/java/com/allday/detoxy/core/manager/AutoRunAlarmManager.kt` (기존 계산 로직)

### 1.2 설계 결정사항

#### 1.2.1 위치 기반 자동 실행 처리 방안
**문제점**: Geofence 진입 시간은 예측 불가능

**선택한 해결책**: 위치 기반은 "다음 예정"에서 제외
- **이유**: 
  - 최근 7일간 진입 시간 평균 추정은 신뢰도가 낮음
  - 사용자가 매일 같은 시간에 특정 위치를 방문한다는 보장이 없음
  - 예측 실패 시 사용자 경험을 해칠 수 있음
- **대안**: 위치 기반 자동 실행은 별도 섹션에서 "활성화된 위치" 목록으로 표시

#### 1.2.2 클래스 구조
- **위치**: `domain/manager/NextAutoRunCalculator.kt`
- **의존성**: 
  - `AutoRunSettingsRepository` (글로벌 설정)
  - `UserSettingsRepository` (마스터 스위치, 일시중지)
- **싱글톤**: `@Singleton` 어노테이션으로 앱 전역에서 하나의 인스턴스만 사용

### 1.3 구현 내용

#### 1.3.1 주요 기능

##### calculateNextAutoRun()
```kotlin
suspend fun calculateNextAutoRun(enabledAutoRuns: List<TimeBasedAutoRun>): NextAutoRunInfo?
```

**구현 로직**:
1. 마스터 스위치 체크 - 꺼져있으면 `null` 반환
2. 글로벌 일시중지 상태 체크 - 일시중지 중이면 `null` 반환
3. 활성화된 자동 실행 리스트가 비어있으면 `null` 반환
4. 글로벌 옵션 (주말 제외) 확인
5. 각 자동 실행의 다음 트리거 시각 계산
6. 가장 가까운 시각 반환

**글로벌 옵션 지원**:
- ✅ **주말 제외**: `excludeWeekends` 설정이 true이면 토요일/일요일 건너뛰기
- ✅ **일시중지**: `autoRunPauseUntil` 설정이 현재 시각보다 미래이면 null 반환

##### calculateNextTriggerTime()
```kotlin
private fun calculateNextTriggerTime(autoRun: TimeBasedAutoRun, excludeWeekends: Boolean): Long?
```

**구현 로직**:
1. `enabledDays` JSON 파싱하여 활성화된 요일 추출
2. 오늘부터 최대 13일(2주) 검색
3. 현재 시각 이후만 허용
4. 주말 제외 옵션 적용
5. 활성화된 요일 중 가장 가까운 시각 반환

**참조**: `AutoRunAlarmManager.calculateNextTriggerTime()` 로직을 기반으로 구현

##### formatTimeUntil()
```kotlin
private fun formatTimeUntil(targetTimeMillis: Long): String
```

**구현 로직**:
- 60분 미만: "N분 후"
- 24시간 이내: "N시간 N분 후"
- 48시간 이내: "내일 오전/오후 HH:mm"
- 48시간 이후: "N요일 오전/오후 HH:mm"

**예시**:
- "5분 후"
- "1시간 30분 후"
- "내일 오전 9:00"
- "수요일 오후 2:30"

#### 1.3.2 NextAutoRunInfo 데이터 클래스

```kotlin
data class NextAutoRunInfo(
    val triggerType: String, // TIME, LOCATION
    val triggerTime: Long,
    val timeUntilTrigger: String, // "1시간 30분 후"
    val label: String, // "오후 업무", "회사"
    val durationMinutes: Int,
    val presetType: String,
    val sourceId: String,
    val confidence: Float? = null // 위치 기반일 때 신뢰도 (0.0~1.0)
)
```

**필드 설명**:
- `triggerType`: 현재 버전에서는 "TIME"만 지원
- `triggerTime`: 트리거 시각 (epoch millis)
- `timeUntilTrigger`: 사용자 친화적인 남은 시간 표시
- `label`: 자동 실행 라벨 또는 시간 (예: "오후 업무" 또는 "14:30")
- `durationMinutes`: 타이머 시간 (분)
- `presetType`: 차단 프리셋 (FULL_BLOCK, STANDARD, RELAXED)
- `sourceId`: 자동 실행 ID (UI에서 상세 화면 이동 시 사용)
- `confidence`: 시간 기반은 null (위치 기반용 예약 필드)

- **Fake 구현의 한계**: Concrete 클래스는 Mocking 없이 테스트 어려움
- **의존성 주입 테스트**: Interface 기반 설계가 테스트에 유리
- **테스트 범위 조정**: 의존성이 많은 경우 단위/통합 분리 필요

### 9.2 Gradle 테스트 실행
- `./gradlew test`: 모든 단위 테스트 실행
- `./gradlew compileDebugUnitTestKotlin`: 테스트 코드 컴파일만
- 린트 오류와 컴파일 오류의 구분

### 9.3 Repository 패턴의 테스트 전략
- **단위 테스트**: 비즈니스 로직만 분리
- **통합 테스트**: Repository와 함께 실제 동작 검증
- **E2E 테스트**: UI부터 DB까지 전체 플로우
