## 2. ScheduleGroupViewModel 확장

### 2.1 개요

2.5차 고도화에서 생성된 ScheduleGroupViewModel을 3차 고도화 요구사항에 맞춰 확장했습니다.

**파일**: `app/src/main/java/com/allday/detoxy/presentation/viewmodel/ScheduleGroupViewModel.kt`

### 2.2 주요 변경사항

#### 2.2.1 ScheduleGroupManager 주입

2.5차에서는 repository만 주입되었지만, 3차 고도화에서는 ScheduleGroupManager를 추가로 주입하여 시간표 활성화/비활성화 로직을 관리합니다.

```kotlin
@HiltViewModel
class ScheduleGroupViewModel @Inject constructor(
    private val repository: ScheduleGroupRepository,
    private val scheduleManager: ScheduleGroupManager  // 🆕 3차 고도화
) : ViewModel() {
    // ...
}
```

#### 2.2.2 activeGroup StateFlow 추가

현재 활성화된 시간표 그룹을 UI에 표시하기 위한 StateFlow를 추가했습니다.

```kotlin
/**
 * 활성화된 ScheduleGroup (Flow)
 *
 * 3차 고도화: 한 번에 하나의 시간표만 활성화 가능 (단일 활성화 원칙)
 */
val activeGroup: StateFlow<ScheduleGroup?> = repository.getActive()
    .map { it.firstOrNull() }
    .stateIn(
        scope = viewModelScope,
        started = SharingStarted.WhileSubscribed(5000),
        initialValue = null
    )
```

#### 2.2.3 activateGroup/deactivateGroup 메서드 추가

ScheduleGroupManager를 통한 시간표 활성화/비활성화 메서드를 추가했습니다.

```kotlin
/**
 * ScheduleGroup 활성화
 *
 * 3차 고도화: ScheduleGroupManager를 통한 시간표 활성화
 * - 다른 모든 그룹 자동 비활성화 (단일 활성화 원칙)
 * - 그룹 내 활성화된 시간대의 알람 자동 등록
 */
fun activateGroup(scheduleGroupId: String) {
    viewModelScope.launch {
        try {
            _isLoading.value = true
            val result = scheduleManager.activateGroup(scheduleGroupId)
            if (result.isFailure) {
                _errorState.value = "시간표 활성화 실패: ${result.exceptionOrNull()?.message}"
            }
        } catch (e: Exception) {
            _errorState.value = "시간표 활성화 실패: ${e.message}"
        } finally {
            _isLoading.value = false
        }
    }
}

/**
 * ScheduleGroup 비활성화
 *
 * 3차 고도화: ScheduleGroupManager를 통한 시간표 비활성화
 * - 그룹 내 모든 시간대의 알람 자동 취소
 */
fun deactivateGroup(scheduleGroupId: String) {
    viewModelScope.launch {
        try {
            _isLoading.value = true
            val result = scheduleManager.deactivateGroup(scheduleGroupId)
            if (result.isFailure) {
                _errorState.value = "시간표 비활성화 실패: ${result.exceptionOrNull()?.message}"
            }
        } catch (e: Exception) {
            _errorState.value = "시간표 비활성화 실패: ${e.message}"
        } finally {
            _isLoading.value = false
        }
    }
}
```

#### 2.2.4 getTimeBasedAutoRuns 메서드 추가

ScheduleGroupCard에서 시간대 목록을 표시하기 위한 메서드를 추가했습니다.

```kotlin
/**
 * 특정 ScheduleGroup의 연결된 TimeBasedAutoRun 조회
 *
 * 3차 고도화: ScheduleGroupCard에서 시간대 목록 표시 시 사용
 */
fun getTimeBasedAutoRuns(scheduleGroupId: String): Flow<List<TimeBasedAutoRun>> {
    return flow {
        repository.getLinkedTimeBasedAutoRuns(scheduleGroupId).let { emit(it) }
    }
}
```

#### 4.2.6 유틸 함수 추가

**formatTime**: 시간을 "오전 9:00" 형식으로 포맷합니다.

```kotlin
private fun formatTime(hour: Int, minute: Int): String {
    val period = if (hour < 12) "오전" else "오후"
    val displayHour = when {
        hour == 0 -> 12
        hour > 12 -> hour - 12
        else -> hour
    }
    return String.format("%s %d:%02d", period, displayHour, minute)
}
```

**getIconForType**: 아이콘 타입에 따라 아이콘을 반환합니다.

```kotlin
private fun getIconForType(iconType: String): ImageVector {
    return when (iconType) {
        "WORK" -> Icons.Default.Star
        "STUDY" -> Icons.Default.Star
        "GYM" -> Icons.Default.Star
        "HOME" -> Icons.Default.Home
        else -> Icons.Default.Star
    }
}
```

## 9. 리뷰 반영 (2025-10-31 저녁)

### 9.1 리뷰 의견

#### 9.1.1 위치 개수 미표시 문제
- **지적 사항**: 문서에는 "연결된 위치 및 시간표 개수 표시"가 체크되어 있지만, 실제 UI에는 시간표 목록만 표시되고 위치 개수가 표시되지 않음
- **원인**: `linkedLocationCounts`를 로딩하지만 Card에서 사용하지 않음

#### 9.1.2 Card의 ViewModel 직접 호출 패턴
- **지적 사항**: `ScheduleGroupCard` 내부에서 `viewModel.getTimeBasedAutoRuns(group.id)`를 호출하여 매 recomposition마다 새로운 Flow가 생성될 수 있음
- **문제점**: 
  - 성능 이슈 (불필요한 repository 호출 반복)
  - 유지보수성 저하 (Card가 ViewModel에 강하게 결합)

#### 9.2.3 ScheduleGroupViewModel 개선

**Before**:
```kotlin
fun getTimeBasedAutoRuns(scheduleGroupId: String): Flow<List<TimeBasedAutoRun>> {
    return flow {
        repository.getLinkedTimeBasedAutoRuns(scheduleGroupId).let { emit(it) }
    }
}
```

**After**:
```kotlin
// ✅ Map 기반 캐싱으로 변경
private val _linkedTimeBasedAutoRuns = MutableStateFlow<Map<String, List<TimeBasedAutoRun>>>(emptyMap())
val linkedTimeBasedAutoRuns: StateFlow<Map<String, List<TimeBasedAutoRun>>> = _linkedTimeBasedAutoRuns.asStateFlow()

fun loadAllLinkedCounts() {
    viewModelScope.launch {
        try {
            val groups = scheduleGroups.value
            val timeCounts = mutableMapOf<String, Int>()
            val locationCounts = mutableMapOf<String, Int>()
            val timeBasedAutoRuns = mutableMapOf<String, List<TimeBasedAutoRun>>()
            
            groups.forEach { group ->
                // 시간대 목록 로드
                val linkedAutoRuns = repository.getLinkedTimeBasedAutoRuns(group.id)
                timeBasedAutoRuns[group.id] = linkedAutoRuns  // ✅ 목록 저장
                timeCounts[group.id] = linkedAutoRuns.size
                
                // 위치 개수 로드
                locationCounts[group.id] = repository.getLinkedLocationCount(group.id)
            }
            
            _linkedTimeBasedAutoRuns.value = timeBasedAutoRuns  // ✅ 한 번에 로드
            _linkedTimeBasedAutoRunCounts.value = timeCounts
            _linkedLocationCounts.value = locationCounts
        } catch (e: Exception) {
            _errorState.value = "연결된 설정 조회 실패: ${e.message}"
        }
    }
}
```

**개선 효과**:
- ✅ 화면 초기화 시 모든 데이터를 한 번에 로드 (효율적)
- ✅ Card에서 ViewModel을 호출하지 않아도 됨
- ✅ 캐싱을 통한 성능 개선
