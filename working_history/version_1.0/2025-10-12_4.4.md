## ✅ 완료 작업

### 1. Gradle 의존성 설정

#### 1.1 libs.versions.toml 업데이트
```toml
[versions]
firebaseBom = "32.7.0"
googleServices = "4.4.0"
firebaseCrashlytics = "2.9.9"

[libraries]
firebase-bom = { group = "com.google.firebase", name = "firebase-bom", version.ref = "firebaseBom" }
firebase-crashlytics-ktx = { group = "com.google.firebase", name = "firebase-crashlytics-ktx" }
firebase-analytics-ktx = { group = "com.google.firebase", name = "firebase-analytics-ktx" }

[plugins]
google-services = { id = "com.google.gms.google-services", version.ref = "googleServices" }
firebase-crashlytics = { id = "com.google.firebase.crashlytics", version.ref = "firebaseCrashlytics" }
```

**추가된 라이브러리**:
- Firebase BOM 32.7.0 (Bill of Materials - 버전 통합 관리)
- Firebase Crashlytics KTX (Kotlin Extensions)
- Firebase Analytics KTX (Crashlytics 필수 의존성)

**추가된 플러그인**:
- Google Services Plugin 4.4.0 (google-services.json 처리)
- Firebase Crashlytics Plugin 2.9.9 (매핑 파일 업로드)

#### 1.2 프로젝트 레벨 build.gradle.kts
```kotlin
plugins {
    // 기존 플러그인...
    alias(libs.plugins.google.services) apply false
    alias(libs.plugins.firebase.crashlytics) apply false
}
```

#### 1.3 앱 레벨 app/build.gradle.kts
```kotlin
plugins {
    // 기존 플러그인...
    alias(libs.plugins.google.services)
    alias(libs.plugins.firebase.crashlytics)
}

dependencies {
    // 기존 의존성...
    
    // Firebase
    implementation(platform(libs.firebase.bom))
    implementation(libs.firebase.crashlytics.ktx)
    implementation(libs.firebase.analytics.ktx)
}
```

**BOM 사용 이유**:
- Firebase 라이브러리 간 버전 호환성 자동 관리
- 개별 라이브러리 버전 명시 불필요
- 버전 충돌 방지

### 2. Application 클래스 업데이트

#### 2.1 DetoxyApplication.kt 주석 추가
```kotlin
/**
 * Hilt 의존성 주입을 위한 Application 클래스

 * @HiltAndroidApp 어노테이션으로 Hilt의 코드 생성 트리거

 */
@HiltAndroidApp
class DetoxyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        
        // Firebase Crashlytics는 자동 초기화됨 (google-services.json 필요)
        // 필요 시 커스텀 키/로그 설정:
        // FirebaseCrashlytics.getInstance().setCustomKey("key", "value")
        // FirebaseCrashlytics.getInstance().log("App started")
        
        // TODO: Timber 로그 초기화 (추후 추가)
    }
}
```

**주요 변경사항**:
- Crashlytics 자동 초기화 명시

- 명시적 초기화 코드 불필요 (Google Services 플러그인이 처리)

## 💡 주요 결정 사항

### 1. Firebase BOM 사용
- **장점**: 버전 호환성 자동 관리, 의존성 간 충돌 방지
- **단점**: 최신 버전 직접 제어 불가 (BOM 버전에 종속)
- **결정**: BOM 사용 (안정성 우선)

### 2. 자동 초기화 vs 수동 초기화
- **자동 초기화 선택**: Google Services 플러그인이 처리
- **수동 초기화 불필요**: 커스텀 키/로그만 필요 시 추가

### 3. Analytics 포함
- Crashlytics는 Analytics를 필수 의존성으로 요구
- 사용자 행동 분석에도 활용 가능 (추후 고려)
