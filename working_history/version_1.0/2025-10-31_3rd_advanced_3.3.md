## 2. TimeBasedAutoRunViewModel 확장

### 2.1 개요

3차 고도화에서 TimeBasedAutoRun에 연결된 ScheduleGroup 정보를 표시하기 위해 ViewModel을 확장했습니다.

**파일**: `app/src/main/java/com/allday/detoxy/presentation/viewmodel/TimeBasedAutoRunViewModel.kt`

### 2.2 주요 변경사항

#### 2.2.1 ScheduleGroupRepository 주입

```kotlin
@HiltViewModel
class TimeBasedAutoRunViewModel @Inject constructor(
    private val repository: TimeBasedAutoRunRepository,
    private val alarmManager: AutoRunAlarmManager,
    private val settingsRepository: AutoRunSettingsRepository,
    private val userSettingsRepository: UserSettingsRepository,
    private val scheduleGroupRepository: ScheduleGroupRepository  // 🆕 3차 고도화
) : ViewModel() {
    // ...
}
```

**목적**: TimeBasedAutoRun에 연결된 ScheduleGroup 정보를 가져오기 위해 ScheduleGroupRepository 주입

#### 2.2.2 scheduleGroupMap StateFlow 추가

```kotlin
// 🆕 3차 고도화: 스케줄 그룹 맵 (ID -> ScheduleGroup)
private val _scheduleGroupMap = MutableStateFlow<Map<String, ScheduleGroup>>(emptyMap())
val scheduleGroupMap: StateFlow<Map<String, ScheduleGroup>> = _scheduleGroupMap.asStateFlow()
```

**구조**: Map<String, ScheduleGroup> 형태로 그룹 ID를 키로 하는 맵
**목적**: O(1) 시간 복잡도로 빠르게 그룹 조회

#### 2.2.3 loadScheduleGroups() 메서드 추가

```kotlin
/**
 * 시간표 그룹 로드
 *
 * 3차 고도화: TimeBasedAutoRun에 연결된 ScheduleGroup 정보를 가져옵니다.
 */
private fun loadScheduleGroups() {
    viewModelScope.launch {
        scheduleGroupRepository.getAll().collect { groups ->
            _scheduleGroupMap.value = groups.associateBy { it.id }
        }
    }
}
```

**설명**:
- `scheduleGroupRepository.getAll()`: 모든 ScheduleGroup을 Flow로 가져옴
- `associateBy { it.id }`: List를 Map으로 변환 (ID를 키로 사용)
- Flow collect를 통해 실시간으로 그룹 변경 사항 반영

#### 2.2.4 init 블록 업데이트

```kotlin
init {
    loadAutoRuns()
    loadAutoRunControlState()
    loadScheduleGroups()  // 🆕 3차 고도화: 시간표 그룹 로드
}
```

**설명**: ViewModel 초기화 시 scheduleGroups를 자동으로 로드

  ├── AutoRunSettingsRepository (기존)

## 4. TimeBasedAutoRunScreen 연동

### 4.1 개요

TimeBasedAutoRunScreen에서 ScheduleGroup 정보를 가져와 TimeBasedAutoRunCard에 전달합니다.

**파일**: `app/src/main/java/com/allday/detoxy/presentation/ui/autorun/TimeBasedAutoRunScreen.kt`

### 4.2 주요 변경사항

#### 4.2.1 scheduleGroupMap collect 추가

```kotlin
val autoRuns by viewModel.autoRuns.collectAsStateWithLifecycle()
val canScheduleExactAlarms by viewModel.canScheduleExactAlarms.collectAsStateWithLifecycle()
val errorState by viewModel.errorState.collectAsStateWithLifecycle()

// 🆕 3차 고도화: 시간표 그룹 맵
val scheduleGroupMap by viewModel.scheduleGroupMap.collectAsStateWithLifecycle()

// 글로벌 옵션 상태

// ...
```

**설명**: ViewModel의 scheduleGroupMap을 UI 상태로 collect

#### 4.2.2 TimeBasedAutoRunCard에 scheduleGroup 전달

**Before**:
```kotlin
autoRuns.forEach { autoRun ->
    TimeBasedAutoRunCard(
        autoRun = autoRun,
        onToggle = { id, enabled ->
            viewModel.toggleAutoRun(id, enabled)
        },
        onEdit = { editingAutoRun = it },
        onDelete = { id ->
            deletingAutoRunId = id
        }
    )
}
```

**After**:
```kotlin
autoRuns.forEach { autoRun ->
    // 🆕 3차 고도화: 연결된 시간표 그룹 조회
    val scheduleGroup = autoRun.scheduleGroupId?.let { scheduleGroupMap[it] }
    
    TimeBasedAutoRunCard(
        autoRun = autoRun,
        scheduleGroup = scheduleGroup,  // 🆕 3차 고도화
        onToggle = { id, enabled ->
            viewModel.toggleAutoRun(id, enabled)
        },
        onEdit = { editingAutoRun = it },
        onDelete = { id ->
            deletingAutoRunId = id
        }
    )
}
```

**로직**:
1. `autoRun.scheduleGroupId`가 있으면 scheduleGroupMap에서 조회
2. 조회 결과를 `scheduleGroup` 변수에 저장
3. TimeBasedAutoRunCard에 전달

### 4.3 데이터 플로우

```
ScheduleGroupRepository
  ↓ (Flow<List<ScheduleGroup>>)
TimeBasedAutoRunViewModel.scheduleGroupMap
  ↓ (StateFlow<Map<String, ScheduleGroup>>)
TimeBasedAutoRunScreen (collect)
  ↓ (scheduleGroup: ScheduleGroup?)
TimeBasedAutoRunCard (display)
```

## 8. 기술적 고려사항

### 8.1 아이콘 선택

**시도한 아이콘들**:
1. `Icons.Default.Folder` - ❌ 존재하지 않음
2. `Icons.Default.Schedule` - ❌ 존재하지 않음
3. `📋` 이모지 - ✅ 최종 선택

**이유**: Material Icons filled에 적절한 시간표 아이콘이 없어서 이모지 사용

### 8.2 성능 최적화

**Map 사용**:
```kotlin
val scheduleGroupMap: StateFlow<Map<String, ScheduleGroup>>
```

**장점**:
- O(1) 시간 복잡도로 빠른 조회
- autoRuns가 많아도 성능 저하 없음

**대안 (사용 안 함)**:
```kotlin
// List를 매번 순회하는 방식 (O(n))
scheduleGroups.find { it.id == autoRun.scheduleGroupId }
```

### 8.3 Flow collect 전략

```kotlin
scheduleGroupRepository.getAll().collect { groups ->
    _scheduleGroupMap.value = groups.associateBy { it.id }
}
```

**특징**:
- ScheduleGroup이 추가/수정/삭제되면 자동으로 UI 업데이트
- 실시간 반영

```kotlin
autoRuns.forEach { autoRun ->
    TimeBasedAutoRunCard(/* ... */)
}
```

**특징**:
- 모든 항목이 즉시 Composition
- 현재 최대 10개 제한으로 성능 문제 없음
- 기존 2.5차 버전과 동일한 패턴

**LazyColumn 전환 시 장점** (향후 필요 시):
```kotlin
LazyColumn {
    items(autoRuns) { autoRun ->
        TimeBasedAutoRunCard(/* ... */)
    }
}
```
- 많은 항목도 효율적 렌더링
- 스크롤 성능 향상
- 메모리 사용량 감소

**결론**: 현재는 10개 제한으로 문제 없으므로 유지. 향후 제한 해제 시 고려.
