## 작업 상세

### 1. onConfirm 시그니처 변경 ✅

**목적**: 생성 모드(템플릿/커스텀)와 데이터를 함께 전달

**변경 내용**:
```kotlin
// Before (v0.8)
fun QuickCreateScheduleDialog(
    onDismiss: () -> Unit,
    onConfirm: (name: String) -> Unit,  // ❌ 단순 이름만 전달
    locationLabel: String = ""
)

// After (v0.9)
fun QuickCreateScheduleDialog(
    onDismiss: () -> Unit,
    onConfirm: (name: String, mode: CreationMode, data: Any) -> Unit,  // ✅ 모드와 데이터 전달
    locationLabel: String = ""
)
```

**이유**:
- `CreationMode.TEMPLATE`: `data`는 `ScheduleTemplate` 객체
- `CreationMode.CUSTOM`: `data`는 `List<TimeSlot>` 객체
- 호출부에서 모드에 따라 적절한 처리 가능

### 2. 상태 관리 확장 ✅

**추가된 상태 변수**:
```kotlin
// 생성 모드
var mode by remember { mutableStateOf(CreationMode.CUSTOM) }  // 기본값: CUSTOM

// 커스텀 모드 상태
var timeSlots by remember { mutableStateOf(listOf<TimeSlot>()) }  // 시간대 목록
var showTimeSlotInput by remember { mutableStateOf(false) }      // 입력 다이얼로그 표시 여부
var editingSlot by remember { mutableStateOf<TimeSlot?>(null) }  // 수정 중인 시간대

// 템플릿 모드 상태 (Phase 2에서 구현)
// var selectedTemplate by remember { mutableStateOf<ScheduleTemplate?>(null) }
// var showTemplateSelector by remember { mutableStateOf(false) }
```

**설계 결정**:
- `mode`의 기본값을 `CUSTOM`으로 설정 (프로세스 우선순위: 커스텀 > 템플릿)
- `timeSlots`는 불변 리스트로 관리하여 Compose 재구성 최적화
- `editingSlot`이 null이면 추가, null이 아니면 수정

### 5. TimeSlotInputDialog 통합 ✅

**구현 로직**:
```kotlin
if (showTimeSlotInput) {
    TimeSlotInputDialog(
        existingSlot = editingSlot,  // null이면 추가, 아니면 수정
        onDismiss = { 
            showTimeSlotInput = false
            editingSlot = null
        },
        onConfirm = { slot ->
            if (editingSlot != null) {
                // 수정
                timeSlots = timeSlots.map { 
                    if (it == editingSlot) slot else it 
                }
            } else {
                // 추가
                timeSlots = timeSlots + slot
            }
            showTimeSlotInput = false
            editingSlot = null
        }
    )
}
```

**특징**:
- `existingSlot`이 null이면 추가 모드
- `existingSlot`이 있으면 수정 모드
- 수정 시 `map`으로 불변 리스트 생성
- 추가 시 `+` 연산자로 새 리스트 생성

## 기술적 의사결정

### 1. when 표현식 활용

**결정**: 생성 모드에 따라 when 표현식으로 UI/로직 분기

**근거**:
- `CreationMode` 열거형의 모든 케이스를 명시적으로 처리
- 컴파일러가 누락된 케이스를 검출
- Phase 2에서 템플릿 모드 추가 시 코드 변경 최소화

### 2. 불변 리스트 패턴

**결정**: `timeSlots`를 불변 리스트로 관리

**근거**:
- Compose의 상태 관리 best practice
- `map`, `+`, `-` 연산자로 새 리스트 생성
- 재구성 최적화 (참조 비교로 변경 감지)

### 3. enabled 파라미터 추가

**결정**: `RadioButtonRow`에 `enabled` 파라미터 추가

**근거**:
- Phase 2 준비를 위해 템플릿 모드 비활성화 지원
- UI에 표시하되 선택 불가능하게 처리
- 투명도 조정으로 시각적 피드백 제공

### 4. locationLabel 기본값 제안

**결정**: locationLabel이 있으면 기본 이름으로 제안

**근거**:
- 위치 기반 자동 실행에서 호출 시 편의성 향상
- 사용자가 수정 가능하므로 강제하지 않음
- 빈 문자열("")도 지원하여 일반 시간표 생성도 가능
