# 02. Location UI 기능 구현 및 리팩토링

**작성일**: 2025-12-14  
**작성자**: Antigravity

---

## 1. 작업 개요
위치 기반 스케줄 등록/수정 화면에서 사용자가 현재 위치를 원클릭으로 등록할 수 있는 기능을 구현하고, 중복된 코드를 공통 컴포넌트로 리팩토링했습니다.

## 2. 변경 내역

### 2.1 공통 컴포넌트: `LocationSearchContent.kt` (신규)
- `AddLocationAutoRunDialog`와 `LocationEditDialog`에서 사용하던 검색 UI 로직을 공통 컴포넌트로 분리했습니다.
- **주요 기능**:
    - 주소 검색 입력창 (Trailing Icon: 검색어가 없으면 '현재 위치', 있으면 '로딩')
    - "📍 현재 위치로 설정" 명시적 버튼 추가
    - 검색 결과 리스트 표시 (정확도 Chip 추가)
    - 로딩/에러/결과 없음 상태 처리

### 2.2 `AddLocationAutoRunDialog.kt` 리팩토링
- 기존 `LocationSearchStep`의 내부 구현을 `LocationSearchContent` 사용으로 변경했습니다.
- **기능 추가**:
    - `rememberLauncherForActivityResult`를 사용하여 위치 권한(`ACCESS_FINE_LOCATION`) 요청 로직 구현
    - `LocationUtils.getCurrentLocation` 호출 연결
    - 권한 획득 시 -> 위치 조회 -> 역지오코딩 -> 결과 리스트에 표시 흐름 완성
    - Toast 메시지를 통한 사용자 피드백 (권한 거부, 위치 못 찾음 등)

### 2.3 `LocationEditDialog.kt` 리팩토링
- 내부 `LocationSearchDialog`를 리팩토링하여 `LocationSearchContent`를 사용하도록 변경했습니다.
- `AddLocationAutoRunDialog`와 동일한 "현재 위치" 로직을 적용했습니다.

## 3. 검증 결과
- **UI 구조**: 검색창, 버튼, 결과 리스트가 의도한 대로 배치됨.
- **권한 처리**: 권한이 없을 때 시스템 다이얼로그 호출 확인 (코드 레벨 검증).
- **컴포넌트 재사용**: 두 다이얼로그가 동일한 `LocationSearchContent`를 사용하여 일관성 확보.

## 4. 특이사항
- 위치 권한이 없는 경우 Toast 메시지로 안내하도록 처리했습니다.
- 역지오코딩(좌표->주소) 실패 시에도 좌표 기반으로 "알 수 없는 위치" 등으로 등록할 수 있도록 예외 처리를 추가했습니다.
