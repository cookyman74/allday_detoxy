### 3.2 Room Migration (02_advanced_room_migration_strategy.md)

#### ✅ 수정된 스키마

**1. LocationBasedAutoRun.address Nullable 처리** (§2.2)
```kotlin
val address: String? = null,  // 주소 (검색 실패 시 null 허용) 🆕
```
**이유**: Google Places API 검색 실패 시에도 좌표만으로 Geofence 등록 가능

**2. AutoRunLog FK 추가** (§2.4)
```kotlin
@Entity(
    tableName = "auto_run_log",
    foreignKeys = [
        ForeignKey(
            entity = FocusSession::class,
            parentColumns = ["id"],
            childColumns = ["sessionId"],
            onDelete = ForeignKey.SET_NULL
        )
    ]
)
```

**3. AutoRunLog 참조 무결성 정책** (§2.4)
- `sessionId`: FocusSession FK (ON DELETE SET NULL)
- `triggerSourceId`: Soft reference (FK 없음)
  - 원본 삭제 시에도 통계 분석을 위해 로그 유지
  - UI에서 "삭제된 설정" 표시

**4. 인덱스 추가** (§7.1)
- `idx_auto_run_log_type_time (triggerType, triggerTime DESC)`: 타입별 이력 조회
- `idx_auto_run_log_session (sessionId)`: FK 인덱스 (자동 생성)

**5. UserSettings 필드 PRD 연계 명시** (§3.1)
- `autoRunPauseUntil`, `autoRunMasterEnabled` 필드 사용처 명확화

### 3.3 Analytics (02_advanced_analytics_schema.md)

#### ✅ 개인정보 보호 강화

**1. 해시 알고리즘 변경** (§1.2, §2.5)
- 변경 전: SHA-256
- 변경 후: **HMAC-SHA256 + 앱 고유 솔트**

```kotlin
private fun hashLocationLabel(label: String): String {
    val salt = BuildConfig.ANALYTICS_SALT
    val mac = Mac.getInstance("HmacSHA256")
    val secretKey = SecretKeySpec(salt.toByteArray(), "HmacSHA256")
    mac.init(secretKey)
    val hash = mac.doFinal(label.toByteArray())
    return hash.joinToString("") { "%02x".format(it) }
}
```

**솔트 생성**:
```gradle
buildConfigField("String", "ANALYTICS_SALT", "\"${generateRandomSalt()}\"")
```

**2. 프리셋 이름 수집 금지** (§4.2)
- 변경 전: `name: string` (프리셋 이름 그대로 전송)
- 변경 후: `name_length: number` (이름 길이만 전송)
- **이유**: 사용자가 개인정보 포함 가능 (예: "김철수 업무용")

**3. 정확 알람 권한 이벤트 확장** (§5.1)
- 신규 파라미터: `went_to_settings` (boolean)
- **목적**: 설정 이동 후 권한 거부 vs 다이얼로그 거부 구분
- **분석**: `went_to_settings=true & is_granted=false` → 권한 유도 실패

**4. 파라미터 관리 전략** (§11 신규 섹션)
- Firebase 이벤트당 최대 25개 파라미터 제한 준수
- 현재 최대 사용량: 8개 (location_based_auto_run_created)
- 우선순위 기반 파라미터 축소 정책
- 분기별 사용량 리뷰 절차
