## 2. ScheduleGroupManager 구현

### 2.1 개요

시간표 그룹의 활성화/비활성화 및 연결된 시간대 알람 관리를 담당하는 중앙 관리 클래스입니다.

**파일**: `app/src/main/java/com/allday/detoxy/core/manager/ScheduleGroupManager.kt`

### 2.2 주요 기능

#### 2.2.1 activateGroup(groupId: String)

**처리 흐름**:
1. 다른 모든 그룹 비활성화 (단일 활성화 원칙)
2. 해당 그룹 활성화 (lastActivatedAt 업데이트)
3. 그룹 내 활성화된 시간대의 알람 재등록

**단일 활성화 원칙**:
- 한 번에 하나의 시간표만 활성화 가능
- 새로운 시간표 활성화 시 기존 활성화된 시간표는 자동 비활성화
- 사용자 혼란 방지 및 위치별 명확한 시간표 매핑

**구현 방식**:
- `repository.getActive().first()`로 현재 활성화된 모든 그룹 조회
- 개별 순회하며 `deactivateGroup()` 호출 (자기 자신 제외)
- `repository.deactivateAll()` 같은 일괄 비활성화 메서드는 사용하지 않음

**주요 코드**:
```kotlin
suspend fun activateGroup(groupId: String): Result<Unit> = runCatching {
    Log.i(TAG, "🔄 Activating schedule group: $groupId")

    // 1. 다른 모든 그룹 비활성화 (개별 순회 방식)
    val activeGroups = repository.getActive().first()
    activeGroups.forEach { group ->
        if (group.id != groupId && group.isActive) {
            deactivateGroup(group.id).getOrThrow()
        }
    }

    // 2. 해당 그룹 활성화 (lastActivatedAt 업데이트)
    val timestamp = System.currentTimeMillis()
    repository.toggleActiveWithTimestamp(groupId, true, timestamp)

    // 3. 그룹 내 활성화된 시간대 알람 등록
    val timeBasedAutoRuns = repository.getLinkedTimeBasedAutoRuns(groupId)
    val enabledAutoRuns = timeBasedAutoRuns.filter { it.isEnabled }

    var successCount = 0
    var failCount = 0

    enabledAutoRuns.forEach { autoRun ->
        val success = alarmManager.scheduleTimeBasedAutoRun(autoRun)
        if (success) successCount++ else failCount++
    }

    Log.i(TAG, "✅ Schedule group activated: $groupId (Success: $successCount, Failed: $failCount)")
}
```

#### 2.2.2 deactivateGroup(groupId: String)

**처리 흐름**:
1. 해당 그룹 비활성화 (lastActivatedAt은 유지)
2. 그룹 내 모든 시간대의 알람 취소

**구현 방식**:
- `repository.toggleActive(groupId, false)` 사용
- `lastActivatedAt` 필드는 유지 (통계 목적)
- 활성화 여부(`isActive`)만 변경

**주요 코드**:
```kotlin
suspend fun deactivateGroup(groupId: String): Result<Unit> = runCatching {
    Log.i(TAG, "🔄 Deactivating schedule group: $groupId")

    // 1. 그룹 비활성화 (lastActivatedAt은 유지)
    repository.toggleActive(groupId, false)

    // 2. 그룹 내 모든 시간대 알람 취소
    val timeBasedAutoRuns = repository.getLinkedTimeBasedAutoRuns(groupId)
    
    timeBasedAutoRuns.forEach { autoRun ->
        alarmManager.cancelTimeBasedAutoRun(autoRun.id)
    }
    
    Log.i(TAG, "✅ Schedule group deactivated: $groupId (${timeBasedAutoRuns.size} alarms cancelled)")
}
```

### 2.3 의존성

- **ScheduleGroupRepository**: 그룹 CRUD 및 참조 무결성 관리
- **AutoRunAlarmManager**: 시간대 알람 등록/취소
- **Context**: Application Context (필요 시 사용)

### 2.4 Hilt 주입

**구현 방식**:
- `@Singleton` 어노테이션으로 싱글톤 보장
- `@Inject constructor`를 통한 자동 주입
- 추가 모듈 불필요 (Hilt가 자동 제공)

**실제 코드**:
```kotlin
@Singleton
class ScheduleGroupManager @Inject constructor(
    @ApplicationContext private val context: Context,
    private val repository: ScheduleGroupRepository,
    private val alarmManager: AutoRunAlarmManager
) { /* ... */ }
```

**Note**: 
- ScheduleGroupRepository와 AutoRunAlarmManager도 이미 Hilt로 관리되므로 자동 주입됩니다.
- 별도 `@Module`이나 `@Provides` 메서드를 작성할 필요가 없습니다.
- 계획 문서에 제시된 `ScheduleModule.kt`는 실제 구현에서 불필요한 것으로 확인되었습니다.

## 3. GeofenceTransitionsReceiver 확장

### 3.1 개요

Geofence ENTER/EXIT 이벤트 수신 시 시간표 그룹 활성화/비활성화를 자동으로 처리합니다.

**파일**: `app/src/main/java/com/allday/detoxy/receiver/GeofenceTransitionsReceiver.kt`

### 3.2 추가된 기능

#### 3.2.1 Hilt EntryPoint 추가

BroadcastReceiver는 `@AndroidEntryPoint`를 사용할 수 없으므로 `EntryPointAccessors`를 통해 수동으로 의존성을 가져옵니다.

```kotlin
@EntryPoint
@InstallIn(SingletonComponent::class)
interface GeofenceReceiverEntryPoint {
    fun locationBasedAutoRunDao(): LocationBasedAutoRunDao
    fun scheduleGroupManager(): ScheduleGroupManager
}
```

#### 3.2.2 ENTER 트리거 확장 (시간표 활성화)

**처리 흐름**:
1. locationId로 LocationBasedAutoRun 조회
2. activateScheduleOnEnter 옵션 및 linkedScheduleGroupId 확인
3. ScheduleGroupManager를 통해 시간표 활성화

**주요 코드**:
```kotlin
// EntryPoint를 통해 필요한 의존성 가져오기
val entryPoint = EntryPointAccessors.fromApplication(
    context.applicationContext,
    GeofenceReceiverEntryPoint::class.java
)

val locationDao = entryPoint.locationBasedAutoRunDao()
val scheduleManager = entryPoint.scheduleGroupManager()

// 비동기 작업 (goAsync)
val pendingResult = goAsync()

scope.launch {
    try {
        val location = locationDao.getByIdOnce(locationId)
        
        if (location != null && location.activateScheduleOnEnter && location.linkedScheduleGroupId != null) {
            val scheduleGroupId = location.linkedScheduleGroupId
            
            // ScheduleGroup 활성화 (알람 자동 등록)
            val result = scheduleManager.activateGroup(scheduleGroupId)
            
            if (result.isSuccess) {
                Log.i(TAG, "✅ ScheduleGroup activated on ENTER: $scheduleGroupId")
            }
        }
    } finally {
        pendingResult.finish()
    }
}
```

#### 3.2.3 EXIT 트리거 구현 (시간표 비활성화)

**처리 흐름**:
1. locationId로 LocationBasedAutoRun 조회
2. deactivateScheduleOnExit 옵션 및 linkedScheduleGroupId 확인
3. ScheduleGroupManager를 통해 시간표 비활성화

**주요 코드**:
```kotlin
scope.launch {
    try {
        val location = locationDao.getByIdOnce(locationId)
        
        if (location != null && location.deactivateScheduleOnExit && location.linkedScheduleGroupId != null) {
            val scheduleGroupId = location.linkedScheduleGroupId
            
            // ScheduleGroup 비활성화 (알람 자동 취소)
            val result = scheduleManager.deactivateGroup(scheduleGroupId)
            
            if (result.isSuccess) {
                Log.i(TAG, "✅ ScheduleGroup deactivated on EXIT: $scheduleGroupId")
            }
        }
    } finally {
        pendingResult.finish()
    }
}
```

### 3.3 CoroutineScope 추가

BroadcastReceiver에서 비동기 작업을 안전하게 수행하기 위해 CoroutineScope를 추가했습니다.

```kotlin
private val scope = CoroutineScope(SupervisorJob() + Dispatchers.IO)
```

## 4. AutoRunAlarmReceiver 확장

### 4.1 개요

시간 기반 자동 실행 알람 트리거 시 scheduleGroupId를 체크하여 그룹이 비활성화 상태일 때 실행을 건너뜁니다.

**파일**: `app/src/main/java/com/allday/detoxy/receiver/AutoRunAlarmReceiver.kt`

### 4.2 추가된 기능

#### 4.2.1 EntryPoint 확장

ScheduleGroupDao를 주입받기 위해 EntryPoint에 추가했습니다.

```kotlin
@EntryPoint
@InstallIn(SingletonComponent::class)
interface AutoRunAlarmReceiverEntryPoint {
    // ... 기존 메서드들
    fun scheduleGroupDao(): com.allday.detoxy.data.local.dao.ScheduleGroupDao
}
```

#### 4.2.2 scheduleGroupId 체크 로직

**처리 흐름**:
1. TimeBasedAutoRun 조회
2. isIndependent = false이고 scheduleGroupId가 있는지 확인
3. ScheduleGroup 조회 및 isActive 확인
4. 그룹이 비활성화 상태면 실행 건너뛰기 (SKIPPED 로그 기록)
5. 다음 알람 재스케줄링 (그룹이 활성화되면 다시 실행될 수 있도록)

**주요 코드**:
```kotlin
// 2. 🆕 3차 고도화: scheduleGroupId 체크
// 시간대가 그룹에 소속되어 있고, 그룹이 비활성화 상태면 실행 건너뛰기
val autoRun = entryPoint.timeBasedAutoRunDao().getById(autoRunId).firstOrNull()

if (autoRun != null && !autoRun.isIndependent && autoRun.scheduleGroupId != null) {
    val scheduleGroup = entryPoint.scheduleGroupDao().getByIdOnce(autoRun.scheduleGroupId)
    
    if (scheduleGroup == null || !scheduleGroup.isActive) {
        Log.w(TAG, "⏭️ Skipping auto-run: ScheduleGroup not active (groupId: ${autoRun.scheduleGroupId})")
        logAutoRunSkipped(autoRunId, "SCHEDULE_GROUP_NOT_ACTIVE", entryPoint)
        
        // Analytics 로깅
        AnalyticsHelper.logAutoRunSkipped(
            triggerType = "TIME",
            reason = "SCHEDULE_GROUP_NOT_ACTIVE"
        )
        
        // 다음 알람 재스케줄링 (그룹이 활성화되면 다시 실행될 수 있도록)
        rescheduleNextAlarm(autoRunId, entryPoint)
        return@launch
    }
}
```

### 4.3 처리 흐름 변경

기존 처리 흐름에 scheduleGroupId 체크를 추가하여 다음과 같이 변경되었습니다:

1. 자동 실행 가능 여부 확인 (마스터 스위치 + 일시중지)
2. **🆕 scheduleGroupId 체크 (그룹 비활성화 시 건너뛰기)**
3. 이미 타이머 실행 중인지 확인
4. Analytics - 자동 실행 트리거
5. 실행 알림 표시
6. AutoRunLog 기록
7. 자동 시작 딜레이 적용
8. 다음 알람 자동 스케줄링

## 5. AutoRunGeofenceManager 확장

### 5.1 개요

위치 이탈 시 시간표 비활성화를 지원하기 위해 EXIT 트리거를 추가했습니다.

**파일**: `app/src/main/java/com/allday/detoxy/core/manager/AutoRunGeofenceManager.kt`

### 5.2 변경 사항

#### 5.2.1 createGeofence 메서드 확장

**트랜지션 타입 설정 로직**:

1. **deactivateScheduleOnExit = true + dwellTimeMinutes > 0**
   → ENTER | DWELL | EXIT (시간표 자동 활성화/비활성화 + 체류 시간)

2. **deactivateScheduleOnExit = true + dwellTimeMinutes = 0**
   → ENTER | EXIT (시간표 자동 활성화/비활성화 + 즉시 트리거)

3. **deactivateScheduleOnExit = false + dwellTimeMinutes > 0**
   → ENTER | DWELL (체류 시간만)

4. **deactivateScheduleOnExit = false + dwellTimeMinutes = 0**
   → ENTER (즉시 트리거만)

**주요 코드**:
```kotlin
// 트랜지션 타입 결정 (ENTER, DWELL, EXIT)
var transitionTypes = Geofence.GEOFENCE_TRANSITION_ENTER

// 체류 시간이 있으면 DWELL 추가
if (autoRun.dwellTimeMinutes > 0) {
    transitionTypes = transitionTypes or Geofence.GEOFENCE_TRANSITION_DWELL
    builder.setLoiteringDelay(autoRun.dwellTimeMinutes * 60 * 1000)
}

// 🆕 3차 고도화: 위치 이탈 시 시간표 비활성화 옵션
if (autoRun.deactivateScheduleOnExit) {
    transitionTypes = transitionTypes or Geofence.GEOFENCE_TRANSITION_EXIT
    Log.d(TAG, "Geofence: EXIT enabled (시간표 자동 비활성화)")
}

builder.setTransitionTypes(transitionTypes)
```

## 6. LocationBasedAutoRunDao 확장

### 6.1 개요

```kotlin
/**
 * ID로 위치 기반 자동 실행 조회 (suspend, 일회성)
 *
 * GeofenceTransitionsReceiver에서 위치 진입/이탈 시 사용합니다.
```

- **getById(id: String): Flow<LocationBasedAutoRun?>**

  - 일회성 조회 (suspend 함수)
